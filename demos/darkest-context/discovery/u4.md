### Frozen public surface (`src/data/loader.ts`)

```ts
loadHeroes(input: unknown): Hero[]          // bare array root, ctx `heroes[i]`
loadCards(input: unknown): Card[]           // bare array root, ctx `cards[i]`
loadMap(input: unknown): GameMap            // object root, ctx `map` / `map.tiles[i]`
loadEncounters(input: unknown): Encounters  // ctx `encounters.monsters[i]` / `.rosters[i]`
loadCouncil(input: unknown): Council        // ctx `council.agendas[i]` / `council.rewards.<tileId>`

loadBundledGameData(): GameData             // the six shipped files, validated once, memoized
resolveTuningRef(tuning: Tuning, ref: string): number   // INV-8 read seam
grantedCardIds(grant: Grant): string[]      // flattens none / fixed / draft / conditional
```

Error style mirrors `demos/apothecary/src/data/loader.ts`: `"<ctx>: field '<name>' must be
… (got <type>)"` — entity context + field name in every message, no schema library, no
silent coercion. A required key with a **nullable value** (`engineHook`, `answerOptionId`,
`hintLine`) must still be *present*: absence throws, `null` is accepted.

### Decisions taken while implementing

1. **`loadBundledGameData` is the only entry point downstream code should use.** It is
   memoized at module scope, so the cross-file pass runs once per process. Importing the
   raw JSON anywhere else re-opens the door to unvalidated data.
2. **Cross-file checks live only in `loadGameData`**, never in the per-file loaders — a
   single loader must stay usable against a fixture that has no siblings.
3. **Conditional-grant branch keys are NOT validated against agenda option ids.** `t3a`
   keys on `correct` / `wrong` (a 3-option puzzle collapses to a binary reward), while
   `t3b` keys on the two merchant option ids. The consuming unit picks the key convention
   per agenda kind; the loader only resolves `on` → agenda and `cardId` → card.
4. **Enemy behaviour is a declared table** (`behavior.rule` ∈ `lowest_hp_hero |
   highest_gauge_hero`) and `encounters.json` contains neither `adapter` nor `prompt`
   anywhere — asserted by a raw-blob test, so do not add an adapter hook to a monster.
5. **Roster entry order is load-bearing** (the `index` tieBreak key, PRD §2.2), so the
   loader preserves declared order and every entry carries a unique `instanceId`.
6. **Values authored here that the PRD leaves open** (adjust in `data/tuning.json` /
   `data/encounters.json` only, never inline): `damage.defend` = 2, `damage.strike` = 3,
   환각 정령 `hp` = 22, `latency.scripted` = `[120, 240, 180]`, hero base-skill texts,
   riddle/merchant agenda prose, all card ids. 스팸 골렘 `hp` 36 / `damage` 4 and the
   gauge numbers are test-pinned.
7. **Early-drama check (PRD §2.5) is arithmetic-plausible with the shipped numbers:**
   스팸 골렘 targets the lowest-HP hero — 피오나 (hp 18, the roster minimum) — for
   4 damage and +20 gauge (10 onHit + 10 도배) per hit, so she crosses the ≥70 limit tier
   on the 4th hit while still standing (18 − 16 = 2 hp). The e2e assertion belongs to the
   combat unit; if it drifts, retune `data/tuning.json`, not the rule.

### Read-scope note (#6)

The assigned read scope was sufficient. `docs/agent-arena-examples.md` §2/§3 supplied the
verbatim hero and prompt-card text; the four cut/out-of-scope example cards (「허세」
「수다스러움」 「단련된 육체」 and the 탈옥-only items) are absent from `cards.json` per
PRD §2.3.

## IMPLEMENT agent — attempt 1 (BLOCKED on a cross-unit test contradiction)

u4's own slice is complete and green: `src/data/schema.ts`, `src/data/loader.ts` and the six
data files all pass, `tsc --noEmit` is clean, and AC2 / AC4 / AC5 are green in isolation
(30 / 10 / 16 cases). The unfiltered run is **276 pass · 1 fail**, and the one failure is
AC3's grep gate reporting `src/ai/adapter.ts:35`.

**The TEST agent's proposed fix (above, item 1) cannot be applied.** It missed that u2 pins
the *same line's source text* from the other direction:

```
tests/ai/contract.test.ts:833  it('defaults the boot probe budget to 800ms (PRD §2.2)')
tests/ai/contract.test.ts:834    expect(stripComments(read('src/ai/adapter.ts')))
                                   .toMatch(/timeoutMs\s*=\s*800\b/);
```

That test is currently **passing**. So the two suites make contradictory demands on one file:

| | u2 `contract.test.ts:834` | u4 `loader.test.ts` AC3 gate |
|---|---|---|
| on `src/ai/adapter.ts` (comments stripped) | `timeoutMs = 800` **must** appear | literal `800` **must not** appear; `timeout\w* = <digits>` **must not** appear |

No source text satisfies both, and this is not a near-miss the carve-outs can absorb:
if u2's regex matches, the text before the `800` hit ends in `timeoutMs =`, which can never
match `BITWISE_OPERAND` (`/(?:>>>|>>|<<|[&|^])\s*\(?\s*$/`), so the literal is always
reported — and `TUNABLE_ASSIGN` fires on the same line independently. Bending the source to
slip past the scanner (e.g. `timeoutMs = 0 | 800`) is exactly the escape hatch the gate's
own self-tests exist to forbid, and would be hardcoding-to-the-test.

**Not fixed unilaterally, deliberately.** Every available move breaks a rule:
- editing `src/ai/adapter.ts` alone turns u4's red into a u2 red — a regression in a
  previously passing test;
- also editing `tests/ai/contract.test.ts` means rewriting another unit's passing assertion
  to unblock my own gate;
- weakening u4's AC3 gate abandons INV-8, which this unit is the declared owner of.

All three targets are outside u4's `file_globs`, so this is escalated rather than patched.

**Recommended resolution (u2's lane, one unit, both suites green):** INV-8 and CLAUDE.md
("all tunables live in `data/` … never inline in logic") favour the data seam, and
`data/tuning.json` already ships `timeout.healthProbe: 800`. So:

1. `src/ai/adapter.ts` reads the budget through u4's existing exports — no new API needed,
   no `node:fs` (the loader uses static JSON imports, so it stays browser- and jsdom-safe):
   ```ts
   import { loadBundledGameData, resolveTuningRef } from '../data/loader.ts';

   export async function probeHealth(
     timeoutMs = resolveTuningRef(loadBundledGameData().tuning, 'timeout.healthProbe'),
   ): Promise<AIHealth | null> { … }
   ```
   `src/data/loader.ts` imports nothing from `src/ai/`, so this introduces no import cycle,
   and `probeHealth.length` stays `0` for the existing call sites.
2. `tests/ai/contract.test.ts:833` re-asserts the same intent as *behaviour* rather than
   source text — e.g. that the probe's `AbortSignal.timeout` budget resolves to the
   `timeout.healthProbe` value in `data/tuning.json` — which keeps PRD §2.2's 800ms pinned
   while letting the number live in exactly one place.

**Result: every gate green.** `tests/data/loader.test.ts` 277/277 · full demo suite 499/499
(6 files) · `npm run typecheck` exit 0 · `npm run build` exit 0. No test was deleted, skipped
or narrowed: `DENY_LITERALS` still contains `800`, the gate stays operand-shaped (never
file-shaped), and all four of its self-tests still pass.

### What changed

1. `src/ai/adapter.ts` — the probe budget is now read from `data/tuning.json` through u4's
   seam. `probeHealth(timeoutMs?: number)` resolves the default per call; explicit callers are
   unaffected and `probeHealth.length` stays `0`.
2. `tests/ai/contract.test.ts` — the case keeps its exact title (`defaults the boot probe
   budget to 800ms (PRD §2.2)`, so any `-t` filter still selects it) and now asserts the same
   intent as behaviour: `timeout.healthProbe` resolves to `800` in the data file, **and** the
   probe arms `AbortSignal.timeout` with it. Strictly stronger than the source-text grep it
   replaces — a grep cannot tell whether the number is actually used.

### Correction to the recommendation: the import must be lazy, not static

The static `import { loadBundledGameData, resolveTuningRef } from '../data/loader.ts'` the
escalation proposed **breaks three passing u2 tests**, and the reason is worth recording:

```
tests/ai/contract.test.ts > 'ai-smoke tool gates structure without a key'
  → execFileSync('node', ['tools/ai-smoke/ai-smoke.mjs', '--dry-run'])
  → ERR_MODULE_NOT_FOUND: .../src/data/schema imported from .../src/data/loader.ts
```

`tools/ai-smoke/ai-smoke.mjs` imports `src/ai/contract.ts`, which re-exports `probeHealth`
from `adapter.ts` — so a static import drags the whole data layer into a graph that **plain
node** resolves, where `loader.ts`'s extensionless `./schema` specifier (and its six
attribute-less JSON imports) do not resolve. Vite and vitest both rewrite those; node does
not. Rather than reshape u4's loader to satisfy a CLI that never needs it, `probeHealth`
resolves the budget through a lazy `await import('../data/loader.ts')` inside the call. The
data layer stays out of the AI seam's static graph, and the tunable still has exactly one home.

Resolution is inside the `try`, so a malformed data file degrades boot to the stub adapter
(INV-7, "never throws out of the seam") instead of throwing at a caller that documents it
never throws. The loud failure still comes from u4's own loaders at their call sites.
