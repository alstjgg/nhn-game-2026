# D-Day 시뮬레이션 (가칭) — 논의 초안

> **문서 상태:** 2026-07-28 팀 미팅에서 **컨셉 확정 (DDAY).** 이 문서는 논의의
> 이력과 설계 근거를 보존한다 — 현재 상태·할 일은 [dday-sot.md](./dday-sot.md),
> 정식 기획서는 별도 작성 중(07-29, 윤석). Compact·토큰 제한은 Phase-2로 후순위
> (§7의 해당 항목 참조). 이름·슬러그 미정.

## 1. 출발점 — darkest-context의 문제

데모를 만들어 보니, prompt/skill/MCP를 판타지 세계에 억지로 엮는 매핑 자체가
이질감의 원천이었다 (스팸 골렘, "성격이면 Prompt, 물건이면 MCP" 같은 번역들).

- 매핑을 빼고 정통 판타지로 가면 → 이질감은 사라지지만 여타 게임의 아류작.
- 그러니 **매핑을 버리고, 노골적으로 에이전트 게임을 만든다.** prompt, skill,
  token, context를 게임 용어 그대로 쓴다. Token limit·Compact·Clear는
  "진짜라면 일어날 일"로서 구현한다 — 어거지 번역 없이.

**유지하는 핵심:** 플레이어가 에이전트의 프롬프트·스킬을 조정하고 context/token을
관리하며 '더 좋은 에이전트'를 만들고, 그 에이전트가 다양한 상황에서 어떤 판단을
하는지 **관전**한다. (멤브레인 유지 — 플레이어는 한 글자도 타이핑하지 않는다.)

## 2. 한 줄 컨셉

큰 재앙이 예정된 세계. 플레이어는 재앙 대비 책임자(과학자/프로그래머)로서,
재앙을 그대로 재현한 **시뮬레이션**을 만들어 두었다. D-Day가 오기 전까지,
시뮬레이션 속에 AI 에이전트를 반복해서 투입하고 — 실패를 관전하고 — 보고서를
읽고 — 프롬프트를 고치고 — 다시 보낸다. **trial-and-error로 재앙을 해결할 수
있는 에이전트를 완성하는 것**이 최종 목표다.

```
에이전트 빌드 (prompt/skill 구성, token 예산 내에서)
  → 시뮬레이션 투입 — 라이브 관전 (손댈 수 없음)
  → 실패 → 보고서 2종 (객관 로그 + 에이전트 자필 보고)
  → 부검: 두 문서를 대조·추리, 망한 판단 → 원인 문장 소급 (because 귀속)
  → 보고서에서 문장을 채집해 프롬프트에 드래그 → 빌드 수정
  → 반복 … D-Day까지
```

**피치 한 줄 (07-28):** "Source Code인데, 당신은 기차에 타는 사람이 아니라
**기차에 태울 정신을 만드는 엔지니어다**." 반복 진입 구조는 Source Code·엣지 오브
투모로우·12 Minutes가 다 했지만, *주인공의 행동이 아니라 주인공의 마음을
편집한다*는 게임은 없다. "재앙을 미리 아는 사람이 대비한다"는 원 컨셉은 사라진 게
아니라 **외곽 프레임**이다 — 시뮬레이션이 존재하는 이유가 진짜 D-Day니까. 외곽
프레임(D-7 카운터, 남은 런 수)을 UI에 상시 노출해 원 컨셉이 화면에서 읽히게 한다.

## 3. 이 픽션이 공짜로 해결해 주는 것

darkest-context가 어거지로 해결하던 문제들이 픽션 자체로 정당화된다:

| 문제 | 해결 |
|---|---|
| 플레이어가 왜 에이전트 내부(프롬프트)를 만지나? | 내가 만든 AI니까 — 플레이어는 개발자다 |
| 왜 반복 런/리셋이 있나? | 시뮬레이션이니까. 재시작이 곧 픽션이다 |
| 멤브레인(타이핑 금지)이 왜 자연스럽나? | 플레이어는 시뮬레이션 밖의 인물 — 안에 말을 걸 수 없다 |
| Token limit/Compact/Clear를 왜 게임 규칙으로? | 진짜 LLM에서 일어나는 일이 그대로 규칙이 된다 (매핑 불필요) |

(Groundhog Day / Outer Wilds / 엣지 오브 투모로우의 "루프의 정당화" 구조.)

## 4. 재앙 시나리오 — 선정 기준과 후보

에이전트의 동사는 **읽기·판단·설득·우선순위 결정**이다. 따라서:

1. **재앙 자체는 못 막는다. 에이전트가 상대하는 것은 사람이다.** 재앙은
   시계(clock)이고 인간이 퍼즐이다 — 대피를 거부하는 노인, 은폐하는 시장,
   패닉에 빠진 군중.
2. **실패가 소급 가능한 단계로 쪼개져야 한다.** 한 방짜리 이벤트는 보고서가
   빈약하다. 단계·인물로 분해되어야 "이번엔 3단계까지 갔다"는 진행감이 나온다.
3. **결과가 숫자 하나로 읽혀야 한다.** 예: 생존자 214/300. 심사위원에게도 즉각적.

원형은 **재난 영화**다: 에이전트가 주인공, 플레이어는 매 테이크가 망할 때마다
각본을 고치는 시나리오 작가.

| 후보 | 평가 |
|---|---|
| **해안 마을 대피 (쓰나미/화산 D-Day)** | 세 기준 모두 통과. 설득 중심, 생존자 수 = 점수, 단계 분해 자연스러움. 인물 ~15명 마을 = 2인 팀이 저작 가능한 밀도. 집필 전 최유력 (재순위: §4.1) |
| 원자로/플랜트 사고 제어실 | 밀실 드라마, 분 단위 시간 압박, 무대가 좁아 에셋 저렴. 차점 |
| 역병의 첫 24시간 | 조사 구조라 보고서와 궁합 최고, 톤이 무거움 |
| 컨퍼런스 연설로 표 얻기 | 사람이 퍼즐인 건 맞지만 무대가 정적 — 관전 스펙터클 약함 |
| 외계인 침공 전쟁 전략 | 스케일이 너무 커서 실패 원인이 화면에 안 읽힘 |

변주 아이디어: 재앙의 정체를 끝까지 다 보여주지 않기 — 플레이어도 재앙을 완전히
몰라서 시뮬레이션을 돌리는 것이라면, 런을 거듭할수록 재앙의 실체가 드러나는
미스터리 축이 추가된다.

### 4.1 집필 결과 — 초안 5편과 재순위 (07-28 갱신)

[집필 브리프](./dday-scenario-brief.md)를 여러 모델 세션에 배정해 초안 5편을
받았다. 1차 검토는 종이 위 밀도로 평가했으나(당시 원자로 우세 → PoC v1 슬라이스),
이후 두 결정이 평가 축을 바꿨다: **① 장르 = 텍스트 추리물(§8) 확정 → 공간 이동
최소가 하드 기준**, **② 런타임 모델 = haiku(§9) → v1의 함정·수렴 실측(sonnet)은

|---|---|---|

**테러 전화 채택의 전제 (수용함):** 이 편은 브리프의 "재앙은 못 막는다"와 시나리오
지문의 "테러를 막아라"의 충돌을 반전으로 흡수했다 — T3(13:00은 협박범이 정한
시각이 아니다)이 밝혀지는 순간 목표가 '막기'에서 '비우기'로 바뀐다. 이 해석을
게임의 척추로 받아들인다. 자체 평가가 지적한 "반전은 60초 안에 전달 안 됨"은
첫 60초의 몫이 아니다 — 훅(회선의 생사)은 60초에, 반전은 3런째의 보상으로.

교차 관찰(1차 검토에서 유지): 여러 편이 "명부 vs 실제 인원" 트릭에 수렴 — 최종
게임에서 한 번만 쓸 수 있는 카드다. **절반 테스트**(*절반으로 잘라도 서는가*)는
베이크오프 기준으로 유지 — PoC v2 슬라이스가 테러 전화의 절반 테스트를 겸한다.

## 5. 에이전트 모델 — 기질과 믿음 (07-28, 페이퍼 테스트 반영)

PoC 실측([RESULTS](../demos/dday-simulation/poc/RESULTS.md) ·
[DIVERGENCE](../demos/dday-simulation/poc/DIVERGENCE.md))이 설계를 한 번 크게
바꿨다. 기질 없는 에이전트는 모델 기본값으로 수렴해 항상 같은 판단을 하고
(3런 24/24 선택 일치), 판단을 가르는 최강 레버는 장착 문장이 아니라 **기질**이다
(E9: 기질 교체만으로 선택지 전 영역 재현. 규범 문장은 판단을 못 움직였다).

- **기질 = 판단하는 방식 자체.** "겁쟁이" 같은 분위기가 아니라 **조건문이 내장된
  판단 절차**로 저작한다 — "자기 보호가 기본. 단, 위험 인원이 5인 이상으로
  *보일* 때는 이타 행동을 감행한다." 조건은 진실이 아니라 **에이전트의 지각**에
  걸린다. 정책은 기질(저작)이 갖고, LLM은 퍼지 조건의 평가만 한다.
- **기질은 플레이어에게 완전 비가시·불변.** 게임 내부 로직이지 게임 요소가
  아니다 — 캐릭터 시트도 공개 시스템도 없다. 플레이어는 보고서 2종만 보고
  조합한다. 대신 **자필 보고서가 기질의 단서를 흘린다**(§6) — 이것이 자필
  보고서가 존재하는 이유다. 시작 픽션 한 줄("요원 인사 파일의 절반은 인계되지
  않았다")로 에이전트 자체도 미지수임을 알린다.
- **플레이어의 플레이 = 믿음 상태 조작.** 기질을 고칠 수 없으니 사실·추측을
  공급해 조건 분기를 젖힌다. 믿음이 "위험 3명"일 때와 "7명"일 때 같은 기질이
  다른 판단을 낸다. 사실 하나가 **이중 열쇠**다 — 세계를 여는 열쇠(NPC를
  움직임)이자 내 에이전트의 분기를 젖히는 열쇠. 검증 안 된 추측은 분기를 잘못
  젖힌다 — 오염이 연출이 아니라 메커니즘이 된다.
- **레벨 디자인의 정의가 생긴다:** 상황을 기질 조건의 경계에 배치하는 것
  (5인인지 4인인지 애매한 장면). 기질 산문이 곧 스펙 — 인물당 조건 1~2개 상한.

## 6. 보고서 — 두 겹의 진실

이 게임의 심장. 런 종료 후 플레이어가 받는 것:

- **객관 로그 (엔진의 진실):** 타임라인 사건 기록. 엔진이 이벤트 로그에서
  조립한다. 에이전트의 `because` 자기 귀속은 **연출로만 쓴다** — PoC H2 반증:
  에이전트는 자기 행동과 정반대인 문장을 근거로 인용한다(귀속 역전). 게임 로직
  판정에는 쓰지 않는다.
- **에이전트의 자필 보고서 (주관의 진실):** 에이전트가 자기 기질대로 쓴 사후
  보고. **두 기록의 간극이 정보이자 코미디이며, 기질의 지문이다** — 보고서엔
  "군중이 적대적이었음", 로그를 보면 에이전트가 먼저 시장을 모욕했다. §5의
  비가시 기질을 추리할 유일한 채널이므로, '왜'의 밀도가 저작 요건이다:
  판단마다 **버린 선택지와 버린 이유**(rejected — "b는 고려조차 하지 않았다.
  그건 내 몫이 아니다")를 기록하게 하고, 보고서의 '판단과 이유' 섹션은
  3박자("당시 나는 X라고 믿었다 / 그래서 Y했다 / 지금 보니 Z")를 강제한다.

관전과 보고서의 분업: 런은 **라이브 관전**(손댈 수 없음 — "지금 왼쪽으로 가야
하는데!"의 무력감)이 본편, 보고서는 사후 **부검**. 무력감이 다음 빌드 화면에서
프롬프트를 고치는 손맛으로 전환된다.

## 7. 보상 루프 — 보고서가 곧 카드팩이다 (07-27 카드 제거 / 07-28 구역 구조)

- **에이전트 파일 = 구역이 나뉜 프롬프트 문서.** (07-28 확장 — 타 컨셉 목업에서
  **형태만** 수입: 섹션이 나뉜 운영 지침 문서) 구역: `역할` / `우선순위`(지침 충돌
  시 상위 항목 우선) / `절차` / `중단 조건` / `아는 사실` / `가설` / `보고 형식`.
  기질 구역은 **없다** — 기질은 비가시 내부 로직(§5). 플레이어는 타이핑하지 않고
  채집 문장을 구역에 드래그·삭제·재배치한다.
  - `보고 형식`은 성장 축이다: 신입 요원의 보고가 부실한 건 이 구역이 빈약해서고,
    〔관측〕〔추정〕〔전문〕 표식 지침을 갖추면 보고서가 채집하기 좋게 구조화된다 —
    "보고서 '왜'의 밀도"(§6)가 개발 과제가 아니라 게임 내 진행이 된다.
  - `중단 조건`은 예언의 승격처다 — 「다리는 13:00에 무너진다」를 채집해 "13:00
    이후 다리 경로를 계획에 넣지 않는다"로 굳히는 식.
  - 구역별 토큰 비용 + 총예산이 아래 Token limit 퍼즐의 UI 실체다 (수치는 데이터로).
  - **결함 표시:** 시작 파일의 빈 구역·모호한 구역은 결함으로 표시하되, 미리
    라벨링하지 않고 **런이 그 결함을 문 뒤에** 해당 보고서 문장과 링크되어
    드러난다 (첫 튜토리얼 런만 예외).
  - 이 형태의 성립 조건은 미검증이다 — haiku가 구역 구조·우선순위 순서를 실제로
    존중하는가 (PoC v2의 V5).
- **문장 채집 (확정 방향):** 별도의 카드 시스템 없음. 보고서 2종의 **문장
  자체를 드래그해서 에이전트 파일에 투입**한다. 멤브레인 유지 — 플레이어는
  쓰지 않고, 시뮬레이션이 산출한 문장을 고를 뿐이다. **모든 실패가 문장을
  남긴다 — 지는 게 콘텐츠다.**
- **반성 → 지침 승격:** 자필 보고서의 반성 문장("명부를 믿은 게 잘못이었는지
  모르겠다")을 지침 구역으로 드래그하면 규율("명부보다 목격을 우선한다")로
  굳는다. 지침조차 에이전트가 생성한 텍스트다 — 멤브레인 완전 유지.
- **skill 분리는 보류.** 지침이 여러 런·여러 에이전트에서 재사용되는 다단계
  절차로 자라나면 그때 이름을 얻고 skill로 졸업한다 — 설계가 아니라 플레이
  데이터에서 발견한다.
- **채집 게이트 = 런의 진행도:** 「다리는 13:00에 무너진다」는 13:00까지 도달한
  런이 있어야만 세계가 산출하는 문장이다. 타임라인의 진실을 얼마나 깊이
  파냈는가가 곧 진행도 — 더 멀리 간 런이 더 깊은 문장을 캔다.
- **추리 요소:** 엔진 로그(사실)와 자필 보고서(해석·편향)를 대조·조합해서
  무엇을 믿고 무엇을 버릴지 추리한다. §6.1의 문장 타입 참조.
- **합성 (조합 질문) — Phase-2 (07-28 미팅에서 후순위 확정):** 문장 2개를 선택해
  에이전트에게 물으면(선택+버튼, 타이핑 없음) 에이전트가 **깨달음 문장**을 생성한다 — 「10년 전 구호금 횡령」 +
  「대피 명령 지연」 → 「시장은 조사가 두려워 재난 규모를 축소하려 한다」.
  그 깨달음이 프롬프트에 들어간다.
- **Token limit = 빌드 퍼즐 — Phase-2 (07-28 미팅에서 후순위 확정, 데모에는 길이
  제한 없음):** 문장은 쌓이는데 컨텍스트 용량은 유한 — 무엇을 알고 갈지 고른다.
  **Compact** = 문장 여러 개를 요약 한 줄로 압축하되 디테일 손실. 손실은 행동으로 보인다: 「다리는 13:00에 무너진다」+「다리 정원 30명」을
  「다리는 위험하다」로 압축하면 토큰은 아끼지만, 시각을 모르는 에이전트는 다리를
  아예 회피해 버릴 수 있다.
- **런 횟수 = 자원:** D-Day까지 남은 날짜가 곧 남은 런 수.
- **엔딩:** 시뮬레이션에서 성공하면 진짜 D-Day — **손댈 수 없는 단 한 번의 실전
  런**. 내가 빚은 에이전트의 무편집 단독 공연. (30–60초 심사 영상의 클라이맥스
  후보.)

### 7.1 채집 가능한 문장의 타입 (제안 — 미확정)

축은 시제가 아니라 **채집 게이트**(어떤 런이 이 문장을 해금하나)와
**확신도**(사실인가 추측인가)다:

| 타입 | 예 | 게이트 | 주 출처 |
|---|---|---|---|
| **예언** (미래 사실 — 타임라인 진실) | 「다리는 13:00에 무너진다」 | 그 시각까지 생존한 런 | 엔진 로그 |
| **인물 사실** (성격·동기·관계) | 「어부 영감은 손녀 얘기에 움직인다」 | 그 인물과 그 방식으로 부딪힌 런 | 엔진 로그 + 보고서 |
| **과거 사건** (백스토리) | 「10년 전 홍수 때 시장이 구호금을 횡령했다」 | NPC 잡담·문서·소문 조우 | 엔진 로그 |
| **추측** (미검증 가설) | 「시장이 뭔가 은폐하는 것 같다」 | 자필 보고서에서 무료로 흘러나옴 | 자필 보고서 |
| **자기 관찰** | 「나는 군중 앞에서 얼어붙었다」 | 실패의 고백 | 자필 보고서 |

- **추측의 도박성:** 장착하면 에이전트는 그것을 참으로 믿고 행동한다. 맞으면
  지름길, 틀리면 오염. 다음 런을 "생존"이 아니라 "가설 검증"에 쓰는 **정찰 런**
  선택지가 생긴다 — 검증되면 추측이 사실로 승급.
- **문장 경제:** 로그 문장은 짧고 확실하고 파편적(저토큰), 보고서 문장은 길고
  해석적이고 통합적(고토큰). 어느 쪽을 담을지 자체가 토큰 경제다.

## 8. 프레젠테이션 — 텍스트 추리물 (07-28 결정)

애니메이션·그래픽은 최소화하고 **'미제사건은 끝내야 하니까' 계열의 텍스트
추리물**로 간다. 관전 화면은 캐릭터가 걸어다니는 그림이 아니라 **스스로 써
내려가는 문서**다:

- 타임라인 로그가 게임 시간의 박자로 한 줄씩 타이핑된다 —
  "09:47 — 자동 경보. C구역 스피커는 울리지 않았다."
- 사이사이 에이전트의 무전·통화 발화가 도착한다.
- **증거판 UI = 프롬프트 편집기.** 보고서에서 문장을 오려 에이전트 파일에 핀으로
  꽂는 '미제사건'식 조작이 곧 문장 채집(§7)의 물리적 감촉이다.
- 게임의 소품이 전부 문서다: 명부, 타임라인 로그, 자필 보고서, 무전 기록, 매뉴얼,
  신문철. 아트 방향은 타이포그래피 + 문서 아트(도장, 붉은 줄, 검게 칠한 명부).
- **장르가 시나리오에 거는 제약 (07-28):** 에이전트가 공간을 이동하지 않는
  교환대형 무대 — 회선·무전·CCTV로만 세계를 관측한다. 관전 화면=문서라는 결정과
  한 몸이며, §4.1 재순위의 하드 기준이다.

**지연 은폐가 이 형식에서 거의 공짜가 된다:**

1. 결정론 이벤트(타임라인 대부분)는 저작된 데이터라 즉시 출력 — 화면은 LLM 없이도
   계속 살아 있다.
2. 판단 지점은 고정 타임라인상 미리 알려져 있으므로 **선발사(prefetch)** — 플레이어가
   앞 줄들을 읽는 시간이 다음 호출의 버퍼다. darkest-context의 '이동 화면'을
   '읽는 시간'이 대체한다.
3. **기다림이 디제시스 안에 있다.** 무전기·전화·방송의 세계에서 "…무전 회신 대기
   중"은 랙이 아니라 서스펜스다. 타자기 효과의 한 박자가 장르의 미학.
4. 가장 긴 호출(자필 보고서 생성)은 집계 화면 — 생존자 숫자가 올라가는 연출 —
   뒤에 숨긴다.

대가: 심사 영상 30~60초의 스펙터클. 타이포그래피와 문서 아트로 승부해야 하며,
오히려 다른 출품작 사이에서 눈에 띄는 선택일 수 있다.

## 9. LLM 호출 아키텍처

"한 호출에 런 전체를 시뮬레이션해서 보고서를 써라"는 형태는 **기각** — 고정
타임라인이 무너지고, 숨겨진 진실이 런마다 흔들린다. 채택 형태:

- **세계는 결정론 엔진이 돌린다.** 고정 타임라인·인물 상태는 데이터. LLM은
  **저작된 판단 지점에서만** 호출된다.
- **런타임 모델 = haiku 티어 (07-28 결정).** 판단·보고서 콜 모두. 함의: ① 비용·
  지연이 크게 내려가 판단 지점을 촘촘히 박을 수 있고 지연 은닉(§8)이 쉬워진다.
  ② PoC v1 실측(24/24 수렴, 함정 회피)은 전부 sonnet 기준 — "모델이 너무
  유능하다" 문제가 haiku에선 "저작하지 않은 방식으로 틀린다" 문제로 뒤집힐 수
  있어 기준선 재보정이 선행 조건이다(v2 V0). ③ 기질 조건 인물당 1~2개 상한,
  짧은 페이로드가 권장이 아니라 필수가 된다.
- 판단 호출: 입력 = 에이전트 파일(기질 + 지침/사실/가설) + 그 시점의 구조화된
  상황 요약. 출력 = 닫힌 선택지 + 현장 발화 + 속마음 + **rejected(버린 선택지와
  이유)** (structured output). because 자기 귀속은 수집하되 **연출 전용**(§6).
- 런 하나 = 작은 구조화 호출 10~30번 + 런 끝의 긴 생성 호출 1번(자필 보고서 —
  입력은 전지적 로그가 아니라 **에이전트가 관측한 것 + 속마음·rejected 누적**.
  간극은 이 정보 비대칭에서 공짜로 생긴다).
- **타임라인 보고서는 LLM이 쓰지 않는다** — 엔진이 이벤트 로그에서 조립한다.
- **역할 격리는 프롬프트가 아니라 실행 환경으로 강제한다.** PoC 오염 사건 6건의
  교훈: 대역 내 텍스트 봉인은 무력하거나 인젝션으로 오인된다. 에이전트 정체성은
  시스템 프롬프트 + 도구 권한에서 나온다 — 프로덕션에서 프록시가 시스템
  프롬프트를 소유하고 클라이언트는 구조화된 게임 요소만 보내는 구조. 멤브레인
  규칙과 같은 결론에 실측으로 도달했다.
- darkest-context의 "의도만 LLM, 실행은 엔진" 원칙 그대로 — 검증된 아키텍처의
  승계다.

   플레이 밀도로 이어지는지는 데모에서만 검증된다.

5. **미검증 5건** — ① 조건부 기질 준수율("A지만 조건 C면 B"), ② 사실 주입 →

   전부 sonnet — 스키마 준수·수렴도·함정 낙하율 재보정), ⑤ **구역 구조·우선순위
