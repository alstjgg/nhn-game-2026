# DDAY 로드맵

> 2026-07-29 기준. 대상 기간: 2026-07-29 ~ 08-10 (대회 제출 마감).
> 팀 공유용 — 기획 문서의 일정 파트로 편입 가능한 수준을 목표로 유지한다.
> 날짜는 전부 잠정 타깃이며, 마일스톤 통과 시점에 갱신한다.

## 1. 목표

프롬프트로 에이전트의 '판단'을 조작하는 상황실 추리 게임(DDAY)을 제출 가능한
데모 수준까지 완성한다. 에이전트 프롬프트가 게임 엔진이므로, **메커니즘 검증이
크리티컬 패스**이고 시나리오·UI는 그 산출물(메커니즘 스펙) 위에서 생성한다.

## 4. 의존 관계

```
M1–M2 확정 ──┐
             ├─→ M3 테스트 스위트 → M4 스크리닝 → M5 딥테스트 → M6 스펙 v1
L1 콜 셰이프 ─┘                                                  │
                                            ┌────────────────────┤
                                            ↓                    ↓
G 기획 문서 ←──(시스템 파트 근거)──── S1 체크리스트 → S2 생성 → S3 선정
L 프록시 구현 (L1 이후 병렬 진행)           │                    │
                                            ↓                    ↓
                                       U UI/UX 기획         P 페이퍼 테스트
```

- **M과 L은 병렬**, 단 L1(콜 셰이프)은 M3의 전제 — 테스트가 프로덕션 콜 셰이프를
  미러링해야 딥테스트 결과가 그대로 이관된다. L 담당 미정 시 M 오너가 잠정
  tool-use 스키마를 확정하고 프록시가 추후 준수하거나 이의를 제기한다(블록 방지
  기본값).
- **D(기본 프롬프트)는 M 딥테스트의 상류다**: 프로브는 기본 프롬프트 위에서
  돌므로, 딥테스트가 끝난 뒤 프롬프트가 바뀌면 소견의 발판이 흔들린다. 순서:
  v0.4로 step 4까지 진행 → L1 확정 창에서 A/B 소량 콜([내력] 유무;
  [무게]·필드 순서는 기결) → **step 5(딥테스트) 진입 전 v1 동결 + K 파일
  lint + 동결 템플릿 N≥10 재베이스라인·필드별 토큰 회계**(기존 경계 법칙은
  전부 구 베이스에서 도출됐고, 베이스라인이 비퇴화하면 N·정지 규칙을
  재산정해야 한다). 동결 후 변경은 스펙 §9식 명시적 재바인딩으로만. 연출
  절("인간적인 것이 우선한다", "결함을 껴안는다")은 판정 콜에서 제외 —
  내레이션·리포터 프롬프트 소속 (스펙 §6).
- **A(아키텍처 스펙)는 중심 기술의 단일 기준**: M은 A에 파라미터(생존 메커니즘,
  가이드라인, 발화율)를 공급할 뿐 A의 불변식을 바꾸지 못한다. L·S·U는 A를
  기준으로 구현·생성하고, G는 A를 시스템 파트의 근거로 인용한다.
- **U의 종이 목업 1종은 예외적으로 MS4 앞으로 당겨진다** (의존 역전): 발견
  가능성 프로브(테스트 Tier B)가 플레이어가 보는 표면을 재료로 요구하기
  때문. 인덱스카드 수준이면 충분하며, U 본작업(S1 이후)과는 분리된 조기
  마이크로 산출물이다. 블라인드 코딩은 프로브 저작자가 코더를 겸할 수 없어
  (무결성 원칙과 동일한 사람-분리) 윤석 몫이 기본값 — 메커니즘당 ~20분.
- G(기획 문서)는 독립 진행하되, M6 스펙이 시스템 파트의 근거 자료로 들어간다.
- S는 M6 부분 산출물로 조기 시작 가능 (검증 완료된 메커니즘부터).
