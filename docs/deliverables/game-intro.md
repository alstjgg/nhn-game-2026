## 조금 더 긴 소개

대설주의보가 내린 밤, 한내시립스포츠돔에서 천장이 처진다는 신고가 한 통 들어온다. 공기로
부풀려 세운 지붕이라 안에 있는 사람들은 두 명씩만 도는 회전문으로 빠져나와야 한다. 그런데
야간 당직자는 안에 아무도 없다고 말한다. 지붕은 어차피 내려앉는다. 남은 문제는 그때 몇 명이
아직 회전문 앞에 서 있느냐다.

당신은 이 사건을 재구성한 모의 단말 앞에 앉은 신규 운영자다. 현장에 나가는 사람은 당신이
아니라 **당신이 파견한 AI 요원**이고, 요원이 무엇을 판단할지는 지시할 수 없다. 당신이 할 수
있는 일은 하나뿐이다. 지난 시행이 남긴 **현장 기록과 요원 보고에서 문장을 채굴해, 다음
요원의 인수인계 사항에 배치하는 것.** 요원의 판단은 명령이 아니라 요원이 아는 사실에서
나오기 때문에, 아는 것이 달라지면 판단도 달라진다.

# 2. 게임 방법

## 2.1 목표

**하나의 사고 상황을 반복 시뮬레이션하며, 사망자 수를 최소화한다.**

플레이어는 현장에 직접 개입하지 않는다. 매 시행마다 AI 요원을 한 명 파견하고, 그 요원이
내리는 판단이 결과를 가른다. 요원에게 명령할 수는 없다. 플레이어가 정하는 것은 **요원이
무엇을 알고 현장에 들어가는가** 하나뿐이다.

> 운영자는 흩어진 기록을 모아 현장 요원에게 전달하고, 이것이 생환자 수를 결정합니다.
> — 게임 내 강평 화면

전달할 재료는 지난 시행이 남긴다. 시뮬레이션이 도는 동안 쌓인 **현장 기록**, 그리고 시행이
끝난 뒤 요원이 직접 쓴 **보고**다. 여기서 문장을 채굴해 다음 요원의 인수인계 사항에 배치하면
요원이 아는 사실이 바뀌고, 그만큼 판단도 달라진다.

**실패한 시행도 자원이 된다.** 사망자를 줄이지 못한 회차라도 다음에 배치할 문장을 남기고,
상황이 더 진행된 회차일수록 남기는 문장이 많다. 그래서 이 게임에서 쌓이는 것은 캐릭터의
능력치가 아니라 **요원에게 건넬 수 있는 정보의 정확도**다.

> 최대한 많은 생환자를 확보하십시오.
> — 게임 내 브리핑 화면

결과는 합격과 불합격으로 갈리지 않는다. **누가 살아 나왔는지**로 갈리기 때문에, 사망자 수가
같아도 그 안에서 벌어진 일은 다르다.

## 2.2 진행 순서

로그인하면 브리핑 두 장이 지나가고 데스크가 열린다. 그다음부터는 아래 네 단계가 반복된다.

```
① 작성   AGENT FILE — 채굴한 문장을 인수인계 사항의 네 칸에 배치한다
   ↓        (첫 시행에는 배치할 문장이 없다. 그대로 파견한다)
② 파견   DEPLOY — 요원이 현장으로 떠나고, 이후로는 개입할 수 없다
   ↓
③ 관전   LIVE FEED — 18시 38분부터 사건이 한 줄씩 올라온다. 요원의 무전과 판단도 여기 찍힌다
   ↓
④ 분석   REPORTS — 문서 두 개가 남는다. 실패 원인을 짚고 문장을 채굴한다
   ↓
   ①로 — 시행 한 번을 소모한다
```

**시행은 모두 네 번이다.** 1회차는 개입 없이 그날을 그대로 지켜보는 회차이고, 이후 세 번을
다시 시행할 수 있다.

## 2.3 조작

**마우스 클릭이 전부다. 게임 어디에도 키보드로 글자를 넣는 곳은 없다.**

| 조작 | 하는 일 |
|---|---|
| **문장 클릭** (REPORTS 안) | 그 문장을 채굴해 인수인계 사항의 빈 칸에 **한 번에** 배치한다. 배치할 수 없는 문장이면 거절 사유가 잠깐 뜬다 |
| **해제** (AGENT FILE 안) | 배치한 문장을 칸에서 뺀다 |
| **페이지 넘김 `‹` `›`** | AGENT FILE은 요원 한 명당 한 페이지다. 지난 요원에게 무엇을 건넸는지 넘겨 볼 수 있다 |
| **DEPLOY** | 인수인계를 확정하고 요원을 파견한다. 되돌릴 수 없어서 확인 창이 한 번 뜬다(`파견` / `취소`) |
| **창 드래그** | 데스크의 창 위치를 옮긴다 |
| **♪** | 음소거 |
| **건너뛰기** | 브리핑과 표지 연출을 건너뛴다 |

**인수인계 사항은 최대 네 칸이다.** 네 칸이 다 차면 더이상 배치할 수 없고, 기존 문장을
해제해야 넣을 수 있다. 무엇을 빼고 무엇을 넣을지가 이 게임의 핵심이다.

> **AI에게 직접 말을 거는 입력창은 없다.** 플레이어가 AI에 닿는 길은 시뮬레이션이 스스로
> 만들어낸 문장을 골라 인수인계 사항에 배치하는 것, 그 하나뿐이다. 요원의 **성향**(어떤
> 상황에서 어떻게 판단하는지)은 화면에 드러나지도 않고 고칠 수도 없다. 플레이어가 다루는
> 것은 **사실**이다. 그래서 이 게임의 추리는 "AI를 어떻게 설득할까"가 아니라 **"이 요원은
> 무엇을 잘못 알고 있었고, 그걸 바로잡을 문장은 어느 기록에 있나"** 를 묻는다.

## 2.4 화면

데스크에는 창이 셋 있다.

- **REPORTS** — 시행이 끝나면 문서 두 개가 쌓인다. **현장 기록**(시뮬레이션이 남긴 객관적
  사실)과 **요원 보고**(요원이 직접 쓴 서술)다. 두 문서는 합쳐지지 않고, **둘 사이의 차이가
  곧 단서다.** 요원이 무엇을 잘못 알고 있었는지는 요원이 쓴 문장에만 드러난다. 문장을
  채굴하는 곳도 여기다.
- **LIVE FEED** — 관전 화면. 사건이 게임 안 시각에 맞춰 한 줄씩 올라오고, 요원이 회선에
  내보낸 무전도 함께 찍힌다. 이 동안에는 개입할 수 없다.
- **AGENT FILE** — 요원의 파일. 인수인계 사항 네 칸과 호출부호(ECHO-1, ECHO-2 …)가 있다.
  요원마다 한 페이지씩 쌓인다.

현장에 나가 있는 것은 요원이고, 등장인물은 전부 회선 너머에 있다. 플레이어도 요원도 사고
현장을 직접 보지 못한다. 화면에 올라오는 모든 것은 누군가가 회선으로 전한 말이거나 기록으로
남긴 문장이다.

## 2.5 종료 조건

**엔딩은 두 가지이고, 어느 쪽이든 강평 화면 세 장으로 끝난다.**

| 엔딩 | 조건 | 화면 |
|---|---|---|
| **성공** | 한 시행이 **사망자 0명**으로 끝났을 때. 몇 회차든 상관없다 | 시뮬레이션 종료 → 훈련 강평 → **모의 과정 완료 · 임용 확정** |
| **실패** | 네 번을 다 쓰고도 거기 닿지 못했을 때 | 시뮬레이션 종료 → 훈련 강평 → **모의 과정 완료 · 평가 보류** |

4회차에 성공해도 성공이다. 남은 시행이 0이 되는 것과 실패는 다르다.

전원을 내보내는 길은 하나가 아니다. 서로 다른 두 갈래로 도달할 수 있다.

# 3. 실행 방법

**설치할 것이 없다. 웹 페이지에 접속하면 바로 플레이된다.**

1. §4의 링크를 연다.
2. 로그인 화면에서 안내대로 진행하면 브리핑 두 장이 지나가고 데스크가 열린다.
3. 첫 시행에는 인수인계에 배치할 문장이 없다. **그대로 DEPLOY를 누르면 된다.** 개입하지
   않았을 때 무슨 일이 벌어지는지 먼저 보는 것이 1회차의 목적이다.

**권장 환경**

- **데스크톱 브라우저** (Chrome · Edge · Safari · Firefox 최신 버전). 모바일과 태블릿은
  지원하지 않는다.
- 설치, 다운로드, 계정 생성, 결제, 유료 라이선스 — 어느 것도 필요 없다.
- 새로고침하면 새 회차가 시작된다.
- 소리가 있지만 없어도 플레이에는 지장이 없다. 음소거는 ♪ 버튼으로 한다.
