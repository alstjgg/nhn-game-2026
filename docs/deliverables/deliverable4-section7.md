# 7. Utilizing AI — 모델에서 더 나은 출력을 끌어내기 위해 한 일

이 게임의 판단은 LLM이 내린다. 한 라운드에 세 번 불려서 행동을 정하고, 그 결정을 장면으로 쓰고,
하루가 끝나면 보고서를 낸다. 세 번 모두 **인물의 성격을 적어둔 문서**를 함께 받는다. 모델의
판단을 바꾸려면 이 문서를 건드리는 수밖에 없고, 플레이어에게 허용된 것도 게임에 이미 나온 문장을
골라 여기에 끼워 넣는 일뿐이다.

그래서 이 절의 질문은 하나다 — **같은 모델에서 더 정확하고 더 재현 가능한 출력을 어떻게
끌어내는가.** 아래 수치는 모두 실측값이다. 원자료와 검증 코드는 각주에 적은 경로에서 확인할 수
있다. 저장소는 `github.com/alstjgg/nhn-game-2026`이고, 경로는 모두 저장소 최상위 기준이다.

## 7.1 어느 모델이 이 작업을 감당하는가

두 모델에 같은 프롬프트를 넣고 응답 시간을 쟀다.

| 측정 항목 | 후보 (Nova 2 Lite) | 채택 (Claude haiku) |
|---|---|---|
| 응답 시간 평균 | 4.19초 | 7.79초 |
| 글자당 생성 시간 | 6.60 ms | 7.23 ms |
| 요구 분량(20–30문장) 준수 | 12–16문장, 미달 | 준수 |

응답 시간만 보면 후보가 두 배 가까이 빠르다. 그런데 **글자당 생성 시간으로 나누면 차이가 9%로
줄어든다.** 후보가 아낀 3.6초는 글을 빨리 써서 번 것이 아니다. 요구한 20–30문장을 12–16문장으로
줄여 쓰면서 생긴 시간이다.

**채택 모델은 글자당 9% 느린 대신, 요구한 분량과 형식을 그대로 지켰다.** 후보를 빠르게 만든
원인이 곧 탈락 사유였던 셈이다. 응답 시간 총량만 놓고 모델을 고르면 요구사항 미준수를 성능으로
오인하게 된다. 응답을 줄이고 싶으면 분량을 줄이라고 지시하면 되고, 그 때문에 모델을 바꿀 일은
아니다.

## 7.2 모델이 무너지는 지점을 찾고, 입력으로 끌어올렸다

같은 상황을 재료만 바꿔 반복 호출해, 되풀이해 재현되는 오동작 일곱 가지를 확정했다.

| 오동작 | 관측된 내용 |
|---|---|
| 화자 오배정 | 전화선 너머 인물의 대사가 같은 공간 인물의 입에서 나온다. 10회 중 8회 |
| 어휘 축 불일치 | 판단 조건이 지켜보는 축의 어휘로 쓰지 않은 사실은 조건을 켜지 못하고, 때로는 끄기까지 한다 |
| 귀속 반전 | 판단 근거를 물으면 자기 행동과 반대되는 문장을 인용한다 |
| 모순 흡수 | 입력에 들어 있던 모순을 지적하지 않고 매끄럽게 이어 붙인다. 보고서 5편 중 3편 |
| 탈출구 수렴 | 두 해석이 모두 고를 수 있는 선택지가 하나라도 있으면 전부 그리로 몰린다 |
| 과잉 신중 | 상황에 시간 여유가 있으면 모든 판단이 "일단 확인부터"로 우회한다 |
| 한쪽만 지키는 순응 | 요구가 여럿이면 그중 하나만 지키고, 어겼다는 사실은 알리지 않는다. 제한 시간을 통과한 보고서가 요구 분량 20–30문장을 16문장으로 어긴 사례 |

**일곱 항목 중 프롬프트 문구를 고쳐서 나아진 것은 하나도 없다.** 출력이 좋아진 것은 모델에
넘기는 자료의 구조와 낱말을 바꿨을 때였다. 두 건이 대표적이다.

**같은 문장, 다른 자리.** 화자 오배정의 원인은 모델에 넘기는 자료의 구조에 있었다. 전화선 너머
인물이 '장면 등장인물' 목록에 없으니 모델은 목록 안에서 쓸 수 있는 이름을 골랐고, 형식상 유효한
값이라 데이터 형식 검사로는 걸리지 않는다. 지시문을 고쳐도 위반율은 내려가지 않았다.

그래서 「전화선 너머 인물은 방 안 인물과 대화하지 않는다」는 제약을 **문장은 한 글자도 바꾸지
않고** 세 위치에 넣어 5회씩 쟀다.

1. 등장인물 목록과 떨어진 '주의사항' 구획에 문장으로 적는다 — 위반 **2회**
2. 등장인물을 '방 안' / '전화선 너머'로 나눠서 넘긴다 — 위반 **1회**
3. 인물 이름표마다 소속을 붙이고, 제약을 그 이름표에 붙인다 — 위반 **0회** (독립 2회 확인)

달라진 것은 제약을 넣은 위치뿐이다.[^a1]

> 모델이 지켜야 할 제약은 그 제약이 걸리는 데이터에 직접 붙인다. 따로 모아 둔 주의사항 목록에
> 적으면 잘 지켜지지 않는다.

**같은 뜻, 다른 낱말.** 같은 이치가 낱말 층위에서도 나온다. 「겁먹은 것으로 판단되면 태도를
완화한다」는 조건에 「위협이 아니다」라는 사실을 넣으면 조건이 켜지지 않고 오히려 꺼졌다. 같은
뜻을 「겁내고 있다」로 바꾸자 3회 중 3회 발동했다. **위협 축의 부정은 공포 축의 긍정이 아니다.**
판단 조건과 그 축의 어휘를 데이터로 묶어 관리하고, 그 어휘가 공용 프롬프트에 섞이면 자동 검사가
막는다.[^a2]

## 7.3 성능 변화를 재려면 입력이 고정돼야 한다

**출력 항목의 순서를 고정한다.** 모델은 앞의 토큰을 조건 삼아 뒤를 이어 쓰므로, 항목을 늘어놓은
순서가 곧 추론 순서다. 판단 근거를 먼저 쓰게 하면 숙고하는 구조가 되고, 결론을 먼저 쓰게 하면
뒤따르는 항목은 사후 정당화가 된다. 순서를 바꾸면 다시 측정한다.[^a3]

**측정할 값을 프롬프트에 미리 심지 않는다.** 어떤 개입이 판단을 바꾸는지 재는 중이라면, 그 판단의
답에 해당하는 문장을 프롬프트가 먼저 말해서는 안 된다. 말해 두면 이후의 변화가 원래 성향인지
개입의 결과인지 갈라낼 수 없다.

**조립 결과가 글자 하나까지 같아야 합격이다.** 개입의 효과를 말하려면 개입 말고는 아무것도
달라지지 않아야 한다. 끼워 넣는 문장은 들어온 순서와 관계없이 늘 같은 순서로 정렬한 뒤
조립한다. 이 검사 자체도 일부러 만든 변형 9종 중 8종을 걸러내 작동을 확인했다.[^a4]

## 7.4 모든 것을 LLM에 위임하지는 않는다

성능을 끌어올릴 수 있다고 해서 전부 맡기지는 않았다. 기준은 하나다 — **틀렸을 때 자동 검증으로
잡히는 자리인가.** 잡히지 않는 자리에는 모델을 두지 않는다.

지금까지 그 기준에 걸린 곳은 한 군데다. 시나리오 원고를 게임 데이터로 옮기는 변환 공정은
결정론적 프로그램만 실행한다. 원고 작성은 AI가 하고 사람이 그중에서 고르지만, 변환 단계에는
모델을 두지 않았다.

플레이어가 끼워 넣는 문장의 어휘가 공략의 성립 여부를 직접 가르기 때문에(7.2), LLM이 "뜻이
같다"고 판단한 표현으로 문장을 다듬으면 **검사는 예외 없이 통과하는데 성립해야 할 공략이
성립하지 않는** 상태가 된다. 자동 검증으로는 찾아낼 수 없다. 변환기는 문장을 원문 그대로 옮기며,
규격을 벗어난 원고는 해석을 시도하지 않고 실패로 끝낸다.[^a5]

검증이 닿는 자리에는 판정하는 일까지 맡겼다. 시나리오 품질 채점, 사전 정보를 주지 않은 AI로 단서
가독성을 확인한 것이 그 예다.

## 7.5 요약

| 기법 | 근거 | 절 |
|---|---|---|
| 응답 시간을 총량이 아니라 글자당으로 나눠서 본다 | 2배 차이 → 9% 차이 | 7.1 |
| 무엇이 어긋나는지부터 재서 목록으로 만든다 | 반복 재현 7종 | 7.2 |
| 같은 문장이라도 어디에 놓느냐로 결과가 갈린다 | 위반 2회 → 0회 | 7.2 |
| 판단 조건과 같은 낱말로 써야 조건이 걸린다 | 미발동 → 3회 중 3회 | 7.2 |
| 한 번 정한 규칙은 자동 검사가 지킨다 | 필수 항목 승격, 어휘 검사 | 7.2 |
| 프롬프트는 버전을 붙여 동결하고 글자 단위로 비교한다 | 변형 9종 중 8종 차단 | 7.3 |
| 틀렸을 때 자동 검증이 잡지 못하는 자리에는 모델을 두지 않는다 | 변환 공정 배제 | 7.4 |

**출력이 좋아진 것은 프롬프트를 잘 쓰게 되어서가 아니다. 측정 결과를 데이터 구조와 검사 도구로
옮긴 결과다.** 모델도 프롬프트 문구도 그대로 둔 채, 넘기는 자료의 구조와 낱말만 바꿔서 위반
10회 중 8회를 0회로 만들었다.
