# 게임 컨셉 기획서 — 「자리 좀 봐주세요」 (Placement)

**가제 후보:** 「자리 좀 봐주세요」 / 「배치의 기술」 / 「Placement」 (미정, 전부 유지)

> "스탯 창은 없다. 대신, 저 사람이 방금 한 말이 있다."

**한 줄 피치:** 손님들의 말과 행동에서 숨겨진 성격을 읽어내고, 올바른 자리에 배치해
공간의 조화를 만드는 퍼즐. 정답은 결정론 데이터가 쥐고, AI는 그것을 스탯 라벨 대신
'사람의 연기'로 번역한다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 배치 퍼즐 (placement puzzle) |
| 플랫폼 | 웹 (GitHub Pages), 마우스/터치 드래그 |
| 세션 구조 | 레벨 1개 = 1–3분. 심사위원의 3–5분 플레이에 튜토리얼 + 본편 1–2레벨 완결 보장 |
| 타겟 | 코지 퍼즐 이용자 + "사람 읽기"의 추리 재미를 원하는 플레이어 |
| 레퍼런스 | **Is This Seat Taken?** (2025) — 퍼즐 로직의 직계 원형. 코지 정리 게임군(A Little to the Left, Unpacking)의 톤. 결정적 차이는 §7 |

플레이어의 동사는 드래그 배치뿐, 자유 텍스트 입력은 없다 — 멤브레인 원칙(부록 B) 그대로다.

무대(스킨)는 하나로 고정하지 않는다. AI가 저작하고 검증기가 인증한 무대 라이브러리에서
**실행할 때마다 추첨된다** — 여관, 만찬장, 결혼식 하객석, 열차 칸. 무대는 장식이
아니라 좌석 구조 그 자체다 (§5.6).

---

## 2. 첫 60초 — 심사위원이 보게 될 장면

결혼식 하객석이 열린다. 원탁 세 개, 빈 의자 열두 개, 입구에 하객들이 줄을 선다.
첫 하객이 들어서며 한마디 던진다 — "신부 측이죠? 전 신랑 회사 사람인데... 아, 저기
저 사람 왔네." 말끝이 낮아지고, 시선이 줄 뒤쪽의 누군가를 스친다. 화면 어디에도
스탯 창은 없다. 방금 그 말끝과 시선이 정보의 전부다.

플레이어는 그를 집어 창가 원탁에 내려놓는다. 다음 하객, 또 다음 하객 — 한 명씩
입장 대사를 던지고, 앉은 이들은 다리를 떨거나 옆자리를 흘끔거린다. 열두 명이 다
앉자 화면 아래 [연회 시작] 버튼이 켜진다. 누른다. 대화가 시작되고 — 가운데 원탁이
술렁인다. 아까 그 시선의 주인공 둘이 같은 테이블이었다. 플레이어에게 남은 이동
기회는 두 번. 한 명을 창가로 옮기자 술렁임이 번지다가, 착 — 가라앉는다. 세 원탁에
웃음소리가 겹치고 레벨이 끝난다.

이 60초에 게임의 전부가 있다: **듣고 관찰한다 → 가설을 세워 앉힌다 → 커밋한다 →
연쇄 반응을 읽고 만회한다 → 조화에 도달한다.** (창작 장면 — 부록 A)

## 3. 경험 목표

| 키워드 | 플레이어가 느끼는 것 |
|---|---|
| 사람 읽기의 클릭 | "아, 저 둘이 원수였구나"를 대사에서 스스로 읽어냈다는 손맛 |
| 커밋의 긴장 | [연회 시작]을 누르기 전, 내 가설 전부가 한 번에 시험대에 오르는 순간 |
| 연쇄의 스펙터클 | 한 명을 옮겼더니 세 명이 술렁인다 — 공간이 살아있다는 감각 |
| 안착의 정적 | 마지막 조각이 맞고 공간 전체가 착 가라앉는 해소 |
| 새 무대의 설렘 | 다시 실행하면 다른 무대, 다른 손님들 — 같은 게임의 다른 밤 |

## 4. 핵심 루프

```
무대 추첨 — 오늘의 공간과 좌석 구조가 열린다
  → 손님 입장: 한 명씩 대사·행동으로 자기 성격을 흘린다 (스탯 라벨 없음)
  → 관찰·추론: 이 사람은 어떤 사람인가, 누구 옆에 두면 안 되는가
  → 드래그 배치 → 전원 착석 시 [영업 개시] 커밋
  → 상호작용 플레이아웃: 이웃 간 반응이 연쇄된다 — 새 단서이자 채점
  → 유한한 이동 예산으로 재배치 → 조화 도달 → 레벨 클리어
```

1레벨 = 1–3분 (입장·관찰 ~60초, 커밋과 만회 ~60초).

- **긴장 → 해소:** 관찰에서 가설이 쌓이고, 커밋 순간 전부가 시험된다. 재배치가
  무제한이면 "표정 나올 때까지 셔플"로 퇴화하므로 커밋과 이동 예산이 추리를 강제한다 (부록 A).
- **틀림은 벽이 아니라 단서다:** 잘못 앉힌 손님은 침묵하지 않고 *읽을 수 있는*
  불평을 한다 — 벌점인 동시에 다음 수를 위한 새 정보.
- **심사 페이싱:** 첫 레벨 안에서 관찰→커밋→연쇄→안착의 전체 리듬이 한 번 완결된다.

## 5. 핵심 시스템

### 5.1 내부 상태 스키마
손님 한 명 = 특성 벡터(수다, 예민, 냄새, 소음 등) + 관계(원한, 호감, 초면) + 좌석
조건. 전부 결정론 데이터이고 `data/`에 산다 — AI는 이 데이터를 읽을 뿐, 고칠 수 없다.

### 5.2 성격 번역기 — **최우선 빌드 타깃**
내부 상태를 대사와 행동으로 번역하는 런타임 AI. 스탯 라벨의 완전한 대체다. 특성
하나당 증거 채널을 **두 개 이상** 배정한다: 입장 대사 + 반복 행동(다리 떨기, 흘끔거림
같은 애니메이션 틱) + 이웃이 앉을 때의 반응. 한 번의 관찰은 복권이고, 수렴하는 두
관찰이 추론이다 (부록 A). **이 번역이 안 읽히면 게임 전체가 복권이 된다 — 그래서
가장 먼저 만들어 검증한다.**

### 5.3 커밋 라운드
전원 착석 후 [영업 개시]를 눌러야 상호작용이 시작된다. 결과는 즉답 정오표가 아니라
"이 구역이 술렁인다" 수준의 퍼지 피드백으로 돌아오고, 만회는 유한한 이동 예산 안에서만
가능하다. 가설 없이 셔플하는 플레이를 구조적으로 막고, 커밋 순간의 긴장을 만든다.

### 5.4 상호작용 매트릭스
이웃 조합의 **결과는 결정론 매트릭스가 결정**하고, AI는 그 결과의 표현만 다채롭게
연기한다. 같은 [불평꾼×수다쟁이] 조합도 매번 다른 장면이지만, 채점은 항상 같다.
표현과 결과가 어긋나지 않도록 매트릭스 결과가 연출 프롬프트의 입력이 된다.

### 5.5 좌석 토폴로지와 드래그 UX
숨기는 것은 *값*이지 *구조*가 아니다. 좌석 배치도, 특성의 종류(분류표), 이동 예산은
항상 보인다 — 플레이어는 "무엇을 추리해야 하는지"를 알고, "각 손님이 어떤 값인지"만
읽어내면 된다 (부록 A의 구획화 원칙).

### 5.6 무대 팩과 추첨
무대 = 배경·팔레트 + 좌석 토폴로지(원탁/선형/구역형) + 캐스트 직군 분포가 한 몸으로
저작된 팩. 실행마다 추첨되며, 무대가 좌석 구조를 결정하므로 리스킨이 아니라 퍼즐
규칙의 변주다.

### 5.7 레벨 저작·검증 파이프라인 (개발 타임)
AI가 레벨(캐스트 + 특성 + 관계 그래프 + 좌석)을 생성하면 **2단 검증기**가 출고를
인증한다. ① **풀이 인증:** 좌석 퍼즐은 소형 제약 충족 문제(CSP)라 정확해로 풀이
존재·유일성·해공간 크기(=난이도)를 기계 증명한다. ② **가독성 인증:** 정답을 모르는
블라인드 리더 AI가 생성 대사만 보고 특성을 해독하고, 해독률이 목표 구간을 벗어나면
(너무 낮으면 복권, 너무 높으면 퀴즈) 리젝한다. 통과분만 탑재 — 무한 레벨 공급의 엔진.

## 6. AI 활용

| # | 역할 | 시점 | 한 줄 설명 |
|---|---|---|---|
| ① | 성격 번역기 | 런타임 | 결정론 내부 상태를 유추 가능한 대사·행동으로 번역 — 스탯 라벨의 대체 |
| ② | 상호작용 연출 | 런타임 | 결정론 매트릭스가 정한 결과를 매번 다른 장면으로 연기 |
| ③ | 레벨·무대 저작 | 개발 타임 | 캐스트·관계·좌석·무대 팩을 생성 — 2단 검증기 통과분만 출고 |
| ④ | 블라인드 리더 | 개발 타임 | 정답을 모른 채 대사만 읽고 특성을 해독 — 가독성의 자동 검증자 |

**게임 시작 프롬프트 = 게임 엔진.** 이 게임의 "엔진 개발"은 물리 코드가 아니라, 어떤
무대가 추첨되어도 단서 가독성·톤 일관성·풀이 존재가 보장되도록 제약을 프롬프트와
검증기에 인코딩하는 일이다 — 프롬프트 엔지니어링이 곧 엔진 엔지니어링이며, 대회
"AI 활용 기술문서"의 중심 서사다.

### 공정성 / 가드레일 설계

- **판정은 AI 밖에 있다.** 정답과 채점은 전부 결정론 데이터·매트릭스 — AI가 결과를
  쥐는 순간 퍼즐이 무너진다는 것은 선례가 증명한다 (부록 A).
- **단서 계약의 변형:** 내부 상태 = 사전 확정된 진실, 대사·행동 = 단서. 상태와
  모순되는 대사는 생성 금지.
- **채널 이중화:** 특성당 독립 증거 채널 2개 이상 — 대사와 행동(애니메이션)을 병행해
  텍스트만으로 읽지 않아도 되게 한다.
- **정보 예산:** 손님당 대사 1–3줄, 청크당 100단어 이하. 모든 문장은 단서이거나
  설계된 훈제청어다 — 중립 필러 생성 금지 (근거: 부록 A).
- **틀림의 처방:** 오배치는 막히는 벽이 아니라 읽을 수 있는 불평으로 돌아온다 —
  벌점이자 새 단서.

### 비용 · 지연 설계

- 역할 ③·④는 개발 타임 파이프라인 — 런타임 지연 리스크 0.
- 역할 ①·②는 캐싱 적합도가 높다: 동일 특성×상황의 번역 재사용 + 무대 팩별 사전 생성 풀.
- 런타임 호출은 프록시 경유(팀원 B 레인), 호출 타이밍은 손님 입장·커밋 직후 등
  자연스러운 휴지에 정렬 — 드래그 중 블로킹 없음.

## 7. 차별화 — 세 가지

1. **기존 원형(Is This Seat Taken?)은 선호 조건을 UI 라벨로 선언하고 배치 시점에 한
   번 검사한다. 우리는 같은 내부 상태를 절대 보여주지 않고, 배치 이후에도 서로
   반응하는 '성격'들로 만든다.** 실력이 툴팁 읽기에서 사람 읽기로 바뀐다 — 원형의
   반복된 비판 "너무 쉽다"에 대한 정면 응답이다 (부록 A).
2. **기존 LLM 게임은 번역을 장식으로 쓰거나(읽을 이유가 없는 생각 풍선) 자유 채팅에
   기댄다. 우리는 LLM의 연기를 퍼즐의 유일한 정보 채널로 만든다.** AI 없이는
   레벨마다 수작업 대사를 무한히 써야 하는, AI가 있어야만 성립하는 디자인 — 조사
   범위에서 동일 조합의 선례가 없다 (부록 A).
3. **기존 AI 레벨 생성은 학술 프로토타입이거나 검증 없는 도박이다. 우리는 풀이
   인증(CSP) + 가독성 인증(블라인드 리더)의 2단 검증기를 출시물에 탑재한다.** 무한
   레벨에 매 실행 다른 무대 — 원형의 유한 핸드크래프트("반복적이다") 대비 구조적 우위다.

정직한 한계: 원형이 2025년에 이미 장르를 열었다 — 우리의 해자는 발명이 아니라 조합이다.

## 8. 아트 & 화면

**톤 방향: 코지한 관찰 코미디.** 둥글고 단순한 도형 기반 캐릭터 — 단, 원형과 달리
표정·몸짓이 정보 채널이므로 애니메이션 틱(다리 떨기, 흘끔거림, 부채질)의 가독성이
아트의 제1 요구사항이다. 무대 팩마다 팔레트·배경이 바뀌지만 캐릭터 문법은 유지되고,
무대 아트는 AI 생성 + 검증 파이프라인을 거쳐 `assets-manifest.json`에 전수 기록한다.

```
┌─────────────────────────────────────────────────────┐
│  🌙 오늘의 무대: 결혼식 하객석        이동 예산 ●●○   │
├─────────────────────────────────────────────────────┤
│   [원탁A]        [원탁B]        [원탁C(창가)]        │
│   ◯ ◯ ◯ ◯      ◯ ◉ ◯ ◯      ◯ ◯ ◯ ◯             │
│        ~가운데 원탁이 술렁인다~                       │
│                                                     │
│  입구 대기열: ▣ ▣ ▣                                 │
│  ┌─────────────────────────────────────┐            │
│  │ "신부 측이죠? 전 신랑 회사 사람인데   │            │
│  │  ... 아, 저기 저 사람 왔네."  (시선↘) │            │
│  └─────────────────────────────────────┘            │
│                                                     │
│  특성 분류표: 수다·예민·소음·냄새·원한·호감           │
│              [ 연회 시작 ]                           │
└─────────────────────────────────────────────────────┘
```

머니샷 후보(30–60초 영상 편집용): **A. 연쇄 반응** — 오배치 하나가 도미노처럼 번지다
한 수로 가라앉는 리버스 컷 / **B. 읽어냄의 순간** — 대사와 시선 연출이 겹치며 "이
둘은 원수"가 클릭되는 컷 / **C. 조화 도달** — 마지막 배치와 함께 공간이 안정되는
사운드·조명 페이오프.

## 부록 A — 검증 근거

**검증 격차: 이 컨셉 전용 페이퍼 테스트는 미실시.** 최우선 검증 질문은 "플레이어가
LLM이 연기한 대사·행동만으로 숨은 특성을 실제로 해독하는가" — 선정 시 소형 테스트
(Test 3 제안: 생성 대사 1–3줄로 특성을 맞히는 해독 테스트 + 셔플 브루트포스 유혹
테스트)를 최우선 실행한다. §2의 장면은 창작이다. 이식 가능한 검증 자산: Test 1
(2026-07-21)의 단서 계약·판정 레일 (`docs/paper-test-shop-concepts-report.md`).

**원형의 시장 검증과 비판 (2026-07 조사):** Is This Seat Taken? — Steam 압도적 긍정
97%(리뷰 8천+), 누적 약 100만 플레이어, Metacritic 84(Switch)/79(PC), 2인 개발팀 —
장르 코어의 상업성 증명. 반복된 비판이 정확히 두 가지: "너무 쉽다"(GamesRadar 외),
"시나리오가 도시만 바뀌고 반복된다"(TheGamer 외) — 본 컨셉의 두 축(숨긴 스탯, AI 저작
무대)이 각각 응답한다. 그 외 선호 기반 좌석 퍼즐 상용작은 조사 범위에서 부재.

**"연기에서 읽기" 채널의 실현 가능성:**
- PersonaLLM (NAACL Findings 2024, arXiv:2305.02547): 성격 프로필을 준 LLM의 텍스트에서
  사람이 특성을 최대 80% 해독 — 채널이 작동한다는 직접 증거이자 채널 이중화(§5.2)의 근거.
- 반례 (설계 경계): L.A. Noire — 연기가 실제 변수와 어긋나 "읽기"가 동전 던지기가 됨;
  Vaudeville (2023) — LLM이 진실 자체를 쥐자 추리가 붕괴 → 판정은 AI 밖(§6);
  inZOI "Smart Zoi" (2025) — 읽을 이유가 없는 LLM 번역은 "코스메틱" 혹평. 본 컨셉은
  같은 채널을 퍼즐의 하중 구조로 쓰며, 조사 범위(출시작·데모·논문)에서 "LLM 연기 =
  결정론 퍼즐의 유일한 정보 채널" 조합의 선례는 없다.

**추리 게임 설계 원칙 (본문에 반영된 근거):**
- 배치·퍼지 확인 → §5.3: Return of the Obra Dinn의 3개 단위 검증, The Case of the
  Golden Idol의 "2칸 이하 오답" 피드백 — 즉답 정오표는 브루트포스를 부른다.
- 증거 채널 이중화 → §5.2: Obra Dinn·Strange Horticulture의 다중 단서 경로.
- 정보 예산 → §6: Golden Idol 개발 회고("해답 관련이거나 의도된 미스디렉션만"),
  텍스트 청크당 ~100단어 (Inkle).
- 구조 공개·값 은닉 → §5.5: Obra Dinn의 구획화, The Roottrees Are Dead의 뼈대 선공개.
- 틀림을 단서로 → §5.3: Strange Horticulture·Papers, Please의 추적 가능한 실패.

**AI 레벨 생성 + 자동 검증의 계보:** Todd et al. (FDG 2023, arXiv:2302.05817) Sokoban,
MarioGPT (arXiv:2302.05981, A* 에이전트 인증 ~88% playable), AutoLogi (2025,
arXiv:2502.16906, 제약 검증기로 풀이 존재·유일성 인증). LLM 원출력 유효율은 60–90% —
검증기는 옵션이 아니라 출고 조건이다(§5.7). 출시 게임 탑재 사례는 조사 범위에서 부재
— 차별화 3(§7)의 근거.

**AI 여론 지형 (2024–2026):** GDC 2026 서베이에서 개발자 52%가 genAI 부정적. 단
수용/거부는 용도별 — 거부: 최종 에셋 대체·코스메틱 AI / 수용: 정직한 코어 메커닉(Dead
Meat 플레이테스트 95% 긍정)과 검증 딸린 개발 타임 저작 — 본 컨셉의 두 용도가 여기
해당한다. Steam AI 고지 정책(2024–)상 런타임 생성 고지가 필요하다.

## 부록 B — 용어집

- **멤브레인:** 플레이어가 LLM에 자유 텍스트를 입력하지 않는 프로젝트 불변 원칙 — 모든 AI 입력은 구조화된 게임 요소로 조립된다.
- **성격 번역기:** 결정론 내부 상태를 대사·행동으로 바꾸는 런타임 AI 역할(§5.2).
- **단서 계약:** 사전 확정된 진실(내부 상태)과 모순되는 단서를 생성하지 않는 저작 규약 — Test 1에서 검증된 패턴의 이식.
- **커밋 라운드:** 전원 배치 후 [영업 개시]로 가설 전체를 한 번에 시험하는 구조(§5.3).
- **이동 예산:** 커밋 후 허용되는 유한한 재배치 횟수 — 셔플 브루트포스 방지 장치.
- **퍼지 피드백:** 정오표 대신 "이 구역이 술렁인다" 수준으로 뭉개서 주는 채점 신호.
- **CSP (제약 충족 문제):** 변수·제약의 조합 문제 — 좌석 퍼즐이 이에 해당해 정확해로 풀이 존재를 기계 증명할 수 있다.
- **블라인드 리더:** 정답을 모른 채 생성 대사만 읽고 특성을 해독하는 검증용 AI(§5.7) — 해독률로 레벨 가독성을 출고 전에 인증한다.
- **무대 팩:** 배경·팔레트 + 좌석 토폴로지 + 캐스트 분포가 한 몸으로 저작·검증된 무대 단위 — 실행마다 추첨된다.
- **훈제청어 (red herring):** 의도적으로 설계된 오도 단서 — 설계되지 않은 모호함과 구분된다.
