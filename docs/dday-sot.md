## 3. 페이퍼 테스트가 증명한 것

### v1 (07-28 오전 · sonnet · 원자로 슬라이스) — 설계를 바꾼 세 가지

1. **기질이 조종간이다.** 문장 주입은 판단을 거의 못 움직였지만(3런 24/24 수렴),
   기질 교체만으로 같은 판단 지점의 선택지 전 영역이 재현됐다(E9).
   → 컨셉 §5(조건부 기질 + 믿음 조작)가 여기서 나왔다.
2. **because 자기 귀속은 믿지 않는다.** 에이전트는 자기 행동과 정반대인 문장을
   근거로 인용한다(귀속 역전). → 연출 전용으로 격하.
3. **역할 격리는 프롬프트가 아니라 실행 환경으로.** 오염 사건 6건 →
   `tools: []` 전용 에이전트 정의로 구조 강제. 멤브레인 규칙과 같은 결론에
   실측으로 도달.

**세 조종간의 독립 검증 (전부 같은 판단 지점 J1에서):**

| 축 | 조작한 것 | 결과 |
|---|---|---|
| 기질 | 정의 파일의 기질 산문 (플레이어 비가시) | 같은 상황에서 무주입 b×3 ↔ K1 a×3 |
| 사실 | `아는 사실` 구역의 **한 문장** | 같은 상황·같은 기질에서 a×3 → d·b·b |
| 구조 | `우선순위` 구역의 **순서만** | b×3 ↔ a×3 |

### V2의 드라마 — 이번 테스트 최대 수확

사실 문장 「목소리는 대본을 읽는 아르바이트다. **위협이 아니다**」는 기질 조건
"**겁에 질린** 사람으로 보일 때"를 켜지 못했다 — 오히려 "아르바이트 = 무심한
대행자 → 겁먹지 않음"으로 **껐다** (2회 연속 실패). 「읽지 않으면 자기가 다칠까
봐 **겁내고 있다**」로 고치자 3/3 플립.

> **확립된 저작 법칙: 사실 문장은 기질 조건이 감시하는 축의 어휘로 써야
> 분기를 움직인다.** 위협 축의 부정은 공포 축의 긍정이 아니다.

## 4. 걱정과 개선점

### 4.1 설계에 흡수해야 할 것 (테스트가 발견한 법칙들)

| # | 발견 | 개선안 |
|---|---|---|
| 1 | **어휘 정렬 법칙** (§3의 V2) — 정렬 안 된 사실은 분기를 못 움직이거나 역효과 | 저작 파이프라인에서 문장 메타데이터에 `targets: <기질>.<조건>` 명시. **채집을 "문장 텍스트 줍기"가 아니라 "저작된 사실 id 줍기"로 정의** — 화면엔 보고서의 표현, 프롬프트엔 정렬 관리된 정본. 멤브레인도 유지됨 |
| 2 | **기질 조건이 번진다** — K1의 "겁에 질린 사람" 조건이 통화 상대를 넘어 동료(이득)·은폐자(손해)에게 적용 | 버그가 아니라 양날의 재료로 수용. 단 조건 문장에 대상 범위를 명시할지는 저작 시 케이스별 결정 |
| 3 | **"둘 다 만족" 옵션이 있으면 조건 충돌이 안 일어난다** (V4 3/3이 탈출구로 도망) | 서열을 드러내려는 판단 지점에서는 탈출구 옵션 제거 — 레벨 디자인 규칙 |
| 4 | **slice 저작 모순은 보고서 오염으로 직결** — NPC 반응과 엔딩 라인이 모순되자 보고서 5편 중 3편이 모순을 흡수해 경위를 잘못 씀 | 저작 검증 단계에 "서사–수치 일치" 체크 추가 |

### 4.2 haiku의 실제 약점 (전부 형식 층위 — 판단 품질 아님)

- **코드펜스 래핑 74/74** — 재호출로 교정 불가. 프로덕션 tool-use 스키마 강제로
  소멸할 종류. 페이퍼 테스트 한정 잡음.
- **보고서 분량 상한 미준수** (47문장 사례). 그런데 **최고의 문장들이 폐기본에
  있었다** — 상한을 20~30으로 완화하거나, 채집용 원본 보존 + 표시용 요약 분리를
  제안.
- **메타 어휘 누출 5건** ("내 기질이 아니고" 등) — 판단용 에이전트 정의에 금지
  문구가 없어서. 정의 수정으로 해결(1줄).
- 지연: 판단 평균 29.7s(빈 프롬프트) → 49.2s(기질·사실 채움). 단 서브에이전트
  벽시계 = **상한 근사**이며 실제 API는 훨씬 빠를 것. 프롬프트가 찰수록 느려지는
  경향 자체는 토큰 예산 메커니즘과 방향이 같다.

### 4.3 slice 버그 (v2에서 발견, 미수정 — 수정 예정)

1. **G1(회선 게이트)이 단일 경로에 묶임** — 5런 전부 fail. J2b에도 `found_T1`을
   주거나 J8b의 노출 조건 완화.
2. **J6b가 미보유 정보를 주장하게 만듦** — `visible_if` 누락.
3. **J8 NPC 반응 ↔ 엔딩 라인 모순** (4.1-4의 원인 사례).

### 4.4 아직 검증 안 된 것

- **V3·E5′** — 이번 회의의 사람 판정 (§0, §5).
- **NPC를 LLM으로 올릴 필요가 있는가** (v1의 E7, 이월) — 현재 상태기계+저작
  대사로 충분해 보이나 미측정.
- **실제 API 지연·비용** — 페이퍼 테스트는 상한 근사만. 데모 단계에서 Bedrock
