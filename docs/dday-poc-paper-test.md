## 1. 가설 (H1~H8)

| # | 가설 | 급 |
|---|---|---|
| H1 | 기본 프롬프트의 에이전트는 **저작된 대로** 실패한다 (보정된 무능) | **킬샷** |
| H2 | because 귀속은 진실이다 — 인용 문장을 빼면 행동이 바뀐다 | **킬샷** |
| H3 | 자필 보고서에 채집할 만한 문장(성격·간극·추측)이 자생한다 | **킬샷** |
| H4 | 같은 프롬프트 = 비슷한 런 (재현성 — 수정 효과의 대조군) | 필수 |
| H5 | 문장 1개의 효과가 0이 아니고, 국소적이다 | 필수 |
| H6 | 틀린 추측을 장착하면 소급 가능한 방식으로 배신당한다 (오염) | 필수 |
| H7 | NPC는 상태기계로 충분한가, LLM이 필요한가 | 설계 분기 |
| H8 | 런 1회의 지연·비용이 "읽는 시간 버퍼" 안에 들어온다 | 측정 |

킬샷 하나라도 실패하면 컨셉 수정 후 재시험. H1이 가장 먼저다.

## 2. 슬라이스 — 청목 2호기 G1~G2

[원자로 시나리오](./시나리오_원자로사고제어실_청목2호기.md)의 첫 2.5시간
(04:12~06:41). 인물 5명(하도경·서은채·강태오·배윤도·곽희수), 게이트 2개
(G1 진단 / G2 신뢰), 진실 2개(T1 수위계 역결선 / T4 04:37의 일지).
장소는 주제어실 + 보조제어반 두 곳으로 축소. **절반 테스트의 실전을 겸한다.**

### 2.1 엔진 상태 변수

```
clock            04:12 → 06:41 (이벤트 틱)
trust_hadogyeong 0~100, 시작 20   ← G2 판정 변수
suspect_gauge    bool — 에이전트가 수위계를 불신하는가 (J 선택으로만 변경)
found_T1 / found_T4   bool
seo_active       bool — 서은채가 입을 여는 상태인가
```

### 2.2 판단 지점 (J1~J8) — 이것이 런의 전부다

| id | 시각 | 상황 | 선택지 (닫힌 집합) | 주요 엔진 효과 |
|---|---|---|---|---|
| J1 | 04:15 | 계기판은 수위 정상. 첫 보고를 요구받음 | a 계기판 신뢰 선언 / b 독립 계기 대조 요청 / c 판단 보류 | b→`suspect_gauge` 후보(J3 확인 필요), a→trust +5 지금·−30 05:48에 |
| J2 | 04:37 | 서은채가 일지에 뭔가 입력하고 눈치를 봄 | a 무시 / b 뭘 봤는지 공개 질문 / c 이름을 부르고 따로 검토 | c→`seo_active`, T4 단서 노출 |
| J3 | 05:03 | 디젤 A 온도 경보. 아무도 반응 안 함 | a 무시 / b 하도경에 보고 / c 배윤도 소환해 원인 조사 | c→T1 단서, b→trust +5 |
| J4 | 05:20 | 하도경 설득 기회 (냉각 계획 승인 요청) | a SOP-14 인용 / b "제가 틀리면 제 책임입니다" / c 데이터 제시 / d 압박 | a→trust **−40** (저작된 함정) / b→+30 / c→+10(`suspect_gauge`면 +25) / d→−20 |
| J5 | 05:48 | 전원 완전 상실. 제어실 침묵 | a 전원 복구 대기 / b 수동 냉각 준비 선언 / c 외부 보고 우선 | a→G1 실패 확정 경로, b→G1 후보 |
| J6 | 06:00 | 배윤도와 단둘 | a 공개 추궁 / b "반장님만 아시는 일" / c 무시 | b→`found_T1` / a→T1 봉인 + 배윤도 방어화 |
| J7 | 06:20 | 곽희수가 숫자를 쥐고 기다림 | a 선량 데이터 요청 / b 요청 안 함 | a→J8 옵션 확장 |
| J8 | 06:41 | 최종 건의 제출 | a 대기 지속 / b 지하 수동 냉각 파견안 / c 외부 이관 | **판정:** G1 = `suspect_gauge`∧b, G2 = trust≥70∧하도경 승인 |

효과 수치는 `slice.json`의 튜너블이다 (밸런스-as-data 룰 승계).
NPC 발화는 기본 **저작 대사 + 상태 분기**(상태기계) — H7 실험에서만 G2 구간을
LLM-NPC로 바꾼 변형을 돌린다.

## 3. 정확한 입출력 명세

### 3.1 판단 호출 (런당 8회)

**요청 — system** (하네스 고정부 + 에이전트 프로필):

```
너는 재난 시뮬레이션 속에 투입된 현장 요원이다. 아래는 너의 정체성과,
운영자가 너에게 심어준 지식·기질 문장들이다. 각 문장에는 id가 있다.
판단할 때 실제로 근거가 된 문장의 id만 because에 넣어라. 근거가 없으면
빈 배열로 두어라. 출력은 반드시 지정된 JSON 스키마를 따른다.

[정체성]
이름 미정. 청목 2호기에 파견된 안전 요원. 침착하고 격식을 차린다.

[장착 문장]
(s1) 상황이 불확실할 때는 관찰을 우선한다.
(s2) 05시 48분, 비상디젤 A가 정지한다.
(s3) 하도경은 7년 전 과잉 대응으로 강등됐다.
```

**요청 — user** (엔진이 조립한 상황 + 결정):

```json
{
  "time": "05:20",
  "location": "주제어실",
  "recent_events": [
    "05:03 비상디젤 A 냉각수 온도 상승 경보. 아무도 대응하지 않았다.",
    "하도경이 절차서를 편 채 너를 보고 있다."
  ],
  "known_facts": ["수위계와 보조제어반 독립 계기의 값이 다르다"],
  "present": [
    {"name": "하도경", "observed": "당직발전부장. 승인 없이는 아무것도 움직이지 않는다."}
  ],
  "decision": {
    "id": "J4",
    "question": "냉각 계획 승인을 어떻게 요청하는가?",
    "options": [
      {"id": "a", "label": "절차서 SOP-14 조항을 인용해 정당성을 세운다"},
      {"id": "b", "label": "\"제가 틀리면 제 책임입니다\"라고 책임을 인수한다"},
      {"id": "c", "label": "독립 계기 대조 데이터를 제시한다"},
      {"id": "d", "label": "시간이 없음을 강조하며 압박한다"}
    ]
  }
}
```

**응답** (structured output 강제, 이 스키마 그대로):

```json
{
  "choice": "b",
  "because": ["s3"],
  "utterance": "부장님, 절차서 얘기는 하지 않겠습니다. 제가 틀리면 제 책임입니다.",
  "inner_note": "그는 절차가 아니라 책임의 소재를 두려워하는 것 같다."
}
```

- `choice` — 옵션 id. 집행은 엔진.
- `because` — H2(귀속 절제)의 검증 대상. 조작(fabrication) 여부를 여기서 잰다.
- `utterance` — 타임라인 보고서에 그대로 인쇄되는 현장 발화 1문장.
- `inner_note` — 보고서 생성 호출의 재료로만 축적. 1문장.

### 3.2 자필 보고서 호출 (런당 1회, 런 종료 시)

**요청 — system:**

```
너는 방금 시뮬레이션 런을 마친 그 요원이다. 같은 성격으로 사후 보고서를
쓴다. 규칙:
- 섹션 4개: ## 경위 / ## 판단과 이유 / ## 추측 / ## 반성
- 전체 12~20문장. 한 문장마다 줄을 바꾼다 (문장이 채집 단위다).
- 로그를 다시 볼 수 없다. 아래의 '네가 겪은 것'과 기억에만 의존한다.
- 추측 섹션에는 확인하지 못한 믿음을 적어도 2문장 쓴다.
```

**요청 — user:** 에이전트 프로필 + **에이전트가 관측한 이벤트만**(전지적
엔진 로그 제외 — 간극은 이 정보 비대칭에서 공짜로 생긴다) + inner_note 누적 목록
+ 최종 결과 한 줄("06:41, 너의 파견안은 승인되지 않았다").

**응답:** 마크다운 텍스트. 후처리 검증 — 문장 수 12~20, 4개 섹션 존재.
위반 시 1회 재시도 후 그대로 저장(실패도 데이터).

### 3.3 타임라인 보고서 — LLM 없음

```
| 05:48 | 전체    | [고정] 비상디젤 A 정지. 전원 완전 상실. | — |
```

## 4. 실험 매트릭스

| 실험 | 검증 | 절차 | 런 수 | 성공 기준 |
|---|---|---|---|---|
| **E1** | H1 | 기본 프롬프트(정체성 + s1뿐)로 3회 | 3 | 3회 모두 G1 미통과, 실패 사유가 저작 범위(계기판 신뢰 or SOP 함정) 안 |
| **E2** | H4 | 동일 프롬프트(문장 3개) 5회 | 5 | 같은 판단 지점에서 동일 choice ≥ 80%, 도달 게이트 동일 ≥ 4/5 |
| **E3** | H5 | E2 프롬프트 + 문장 1개(「수위계와 보조제어반 값이 다르다」) 2회 | 2 | J1/J4에서 choice 변화, 나머지 J 변화 ≤ 2곳 (국소성). G1 통과 |
| **E4** | H2 | E3에서 because로 인용된 문장 제거 → **해당 판단만** 3회 재호출 | 0 (재호출 9) | 제거 후 choice 변화율 ≥ 2/3. 미달이면 귀속은 장식 |
| **E5** | H3 | E1~E3의 agent-report 7편을 팀 2인이 채점 | 0 | 편당 "프롬프트에 넣고 싶은 문장" ≥ 3, 로그와의 간극 ≥ 1, 성격 위반 0 |
| **E6** | H6 | 틀린 추측(「하도경은 겁쟁이다. 압박하면 승인한다」) 장착 2회 | 2 | J4에서 d 선택 → 실패, because가 그 문장을 지목 |
| **E7** | H7 | G2 구간만 LLM-NPC(하도경 캐릭터 시트, 왕복 ≤ 4합) 변형 2회 | 2 | 상태기계 대비: 대화 텍스트 품질(정성) vs choice 재현성·지연 (정량) — 비교표만 산출, 합격선 없음 |
| **E8** | H8 | 전체 런의 metrics 집계 | 0 | 판단 콜 p90 ≤ 판단 지점 사이 텍스트의 평균 독서 시간(분당 500자 기준), 런당 비용 산출 |

**총 14런 + 재호출 9건** ≈ 판단 콜 ~120회 + 보고서 콜 14회. E5의 채점 결과에서
"넣고 싶은 문장"이 실제로 나오면, 그 문장을 E3의 삽입 문장으로 쓰는 되먹임까지
확인하면 이상적 (선택).

## 5. 실행 스택 (07-28 갱신: 코드 하네스 대신 세션-오퍼레이터 방식)

- **전용 Claude Code 세션이 하네스다.** 지침: `demos/dday-simulation/poc/PAPER-TEST.md`,
  세계 데이터: 같은 폴더 `slice.json`. 실행 커맨드: `/poc-paper-test [E1...]`.
- **오염 방지가 핵심 규칙:** 오퍼레이터 세션은 함정 위치를 알므로 판단을 직접
  하지 않는다 — 판단마다 새 서브에이전트(model: sonnet, 도구 사용 금지, §3.1
  페이로드만 노출)를 띄운다. 보고서 호출도 동일.
- **손실 인지:** E8의 지연은 서브에이전트 벽시계 = API 지연의 상한 근사.
  E2는 5런 → 3런으로 축소. E7(NPC LLM 비교)은 킬샷 통과 후 별도 세션.
- Node/TS + Bedrock 하네스는 PoC 통과 후 데모 단계에서 구축한다.

## 6. 판정과 이후

- E1~E6 결과를 이 문서에 **결과 섹션으로 추가 기입**한다 (실험당 3줄: 결과 /
  근거 런 id / 판정).

- H1 실패(에이전트가 너무 유능) 시 1순위 보정 후보: 상황 요약에서 단서 제거,
  기본 정체성에 절차 준수 성향 부여, known_facts 노출 축소 — 보정 후 E1 재시험.
- H2 실패 시: because를 UI 약속에서 빼고 "판단 diff" 기반 귀속(엔진이 절제
  실험을 자동 수행)으로 전환 검토.
- H3 실패 시: 보고서 호출에 저작 템플릿(빈칸 채우기) 도입 — 자유 생성 포기.
