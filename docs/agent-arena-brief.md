# 통합 브리프 — 에이전트 아레나 (agent-roguelike × autobattler)

> **문서 상태:** 통합 세션 입력용 초안. 기획서가 아니다 — 2026-07-22 결정에 따라 병합 기획서는
> 쓰지 않고, 최종 판단은 데모 베이크오프가 한다. 이 브리프는 "무엇을 합치고, 무엇을 버리고,
> 무엇이 아직 열려 있는지"를 두 사람이 같은 그림 위에서 정하기 위한 준비물이다.
> 원본: [agent-roguelike](./game-concept-agent-roguelike.md) · [autobattler](./game-concept-autobattler.md)

---

## 1. 한 줄 컨셉

프롬프트·Skills·MCP를 카드로 드래프트해 **3–4기의 AI 에이전트 파티**를 조립하고, 분기가 있는
선형 맵을 타일 단위로 전진시키며, 타일마다 발생하는 이벤트(전투·퍼즐·탈옥·상점·도박)를
파티가 스스로 판단해 헤쳐나가는 것을 지켜보는 로그라이크.

싸우고 푸는 것은 플레이어가 아니라 플레이어가 빚은 에이전트들이다. 플레이어의 동사는
드래프트, 장착, 분기 선택 — 그리고 관전이다.

## 2. 왜 이 구조인가 — 통합의 논리

두 원본은 같은 핵심("좋은 에이전트를 만들어 미션을 시킨다")을 공유하지만, 서로 못 풀던
문제가 하나씩 있었다:

- **오토배틀러의 최대 리스크** — 실시간 다대다 전투를 3주 안에 구현할 수 있는가.
- **로그라이크의 아쉬움** — 과제 해결 단독으로는 덜 역동적이고, 에이전트가 1기라
  성격·시너지의 드라마가 없다.

**맵 스파인이 둘 다 푼다.** 전투는 유닛이 이동하지 않는 턴제(For The King 방식)가 되어
구현 난이도가 급락하고, 파티가 3–4기라 성격·시너지 관전은 살아남는다. 그리고 맵이 중립
스파인이라 **어느 쪽도 흡수당하지 않는다** — 오토배틀러는 전투 타일 + 드래프트 문법으로,
로그라이크는 과제 타일 + 자원 시스템으로 각자의 정체성을 갖고 들어온다.

턴제 전투는 기술적으로도 정합하다: LLM은 좌표·틱 단위 판단에 약하고 열거된 선택지의
고수준 판단에 강하다(오토배틀러 부록 A의 기술 근거 그대로). 턴제에서는 에이전트의 판단이
곧 "이번 턴 행동 하나를 고르는 것"이라, 의도 정책 레일이 행동 공간과 일치한다.

## 3. 스파인 — 맵과 전진

- **분기형 선형 맵.** 타일이 한 줄로 이어지고 2–3회 분기가 있다 (Slay the Spire의 맵을
  선형에 가깝게 압축한 형태). 분기 선택이 빌드와 상호작용한다 — "계산기 MCP 위주 파티니
  퍼즐 분기로 간다."
- **자동 전진 (제안).** Darkest Dungeon처럼 파티가 스스로 걷고, 타일에 안착하면 이벤트가
  발화한다. 플레이어 입력은 분기점에서만. 주사위·수동 이동은 심사위원의 3–5분에서 죽은
  시간을 만들고, 걷는 연출은 LLM 호출 지연을 숨기는 자연 휴지가 된다.
- **페이싱 하드 요구:** 첫 60초 안에 첫 이벤트에 도착해야 한다. 1번 타일은 강제 이벤트.

## 4. 파티 — 풀 아키텍처, 카드 외피

파티는 에이전트 3–4기. 각 기는 로그라이크의 재료 전부로 조립된다:

| 재료 | 게임 내 문법 |
|---|---|
| 프롬프트 조각 (성격·기질·전술) | 드래프트 카드 → 유닛에 장착 |
| Skills | 상점/보상 카드 → 슬롯 장착 |
| MCP (도구) | 상점/보상 카드 → 장비 장착 |
| 토큰 / 컨텍스트 게이지 | 유닛별 자원 게이지 — 채워질수록 지연·환각 |
| 컴팩션 / 클리어 | 게이지를 비우는 도박 이벤트 (승천 확률 유지) |

**외피는 전부 카드/장비 문법이다.** 노드 그래프·조건문·설정 패널 금지 (Bot Land 반면교사 —
오토배틀러 부록 A). 내부는 에이전트 엔지니어링, 화면은 카드 게임.

## 5. 이벤트 분류 — 타일 3군

Slay the Spire의 노드 분류(몬스터/이벤트/상점/휴식)와 구조가 겹친다. 약점이 아니라 이
구조가 검증됐다는 뜻이다.

| 군 | 타일 | 출신 |
|---|---|---|
| **도전** (런을 위협) | 전투 · 퍼즐 · jailbreaking(공방) | 로그라이크의 던전 3종 |
| **성장** (빌드를 깊게) | 프롬프트 카드 드로우 · MCP 상점 · Skill 상점 | 오토배틀러의 드래프트 문법 |
| **휴식/도박** | compact vs clear (게이지 정리 + 승천 확률) | 슬더슬 모닥불의 우리식 변형 |

**전투 타일:** 유닛이 이동하지 않는 턴제. 매 턴 각 에이전트가 자기 프롬프트 × 전장 상황을
해석해 행동을 고르고, 말풍선으로 의도를 말하고, 결정론 엔진이 실행한다. 「겁이 많다」를
단 힐러가 제 턴에 방어만 누르며 떠는 것 — 그 순간이 이 게임의 시그니처다.

전투 상대는 두 층이다: 일반 타일은 **몬스터**(스크립트/저작 인카운터), 상위 타일은
**상대 에이전트 파티** — 나와 같은 규칙으로 카드를 조합한 파티다. 오토배틀러의 상대
디렉터는 사라지지 않고 여기로 흡수된다. "나와 같은 일을 하는 AI와 겨룬다"는 차별화가
보스급 전투의 프레임으로 살아남는다.

## 6. 유지되는 원칙 (두 원본의 합집합 — 이미 합의된 것)

- **멤브레인:** 플레이어는 한 글자도 타이핑하지 않는다. 모든 프롬프트는 카드 조합이다.
- **귀속, 일관성 아님:** 판단은 원인 카드를 인용한다(리포트 + 말풍선 텔레그래프). "같은
  프롬프트 = 같은 행동"은 약속하지 않는다 — 카드로 소급되면 공정하다.
- **의도만 LLM, 실행은 엔진:** 닫힌 선택지 공간 + 결정론 실행 + 응답 지연 시 결정론 폴백.
- **비용·지연:** 유닛 판단은 병렬(벽시계 ≈ 1콜), 이동·전환 연출에 은폐, [조합 × 맥락 버킷]
  해석 캐시, 전부 프록시 경유(팀원 B 레인).
- **밸런스는 `data/`에 데이터로.**

## 7. 레퍼런스 매핑

| 레퍼런스 | 가져오는 것 |
|---|---|
| **Slay the Spire** | 분기 맵 런 구조 · 노드 분류(도전/성장/휴식) · 드래프트 3택의 빌드 긴장 |
| **Darkest Dungeon** | 자동 전진 + 타일 이벤트 발화 · **성격·기벽 때문에 파티원이 멋대로 행동하는 턴제 전투가 대중적으로 통한다는 증명** — affliction 모먼트가 우리 게임의 기본 상태다 |
| **For The King** | 파티가 맵 위를 전진하는 보드게임 문법 · 정지형 턴제 전투의 구현 스케일 |
| **Teamfight Tactics** | 라운드 드래프트 경제 · RNG를 확률 공개로 신뢰시키는 가독화 원칙 |

이 네 개가 재료의 시장 검증을 나눠서 든다. 우리가 얹는 유일한 신규 재료는 "파티원이
스크립트가 아니라 내가 문장으로 빚은 LLM"이라는 것 — 그리고 그 재료 자체도 Death by AI ·
Infinite Craft가 검증했다(오토배틀러 부록 A). 재료는 전부 검증, 조합은 미출시 — 이 결론은
통합 후에도 유지된다.

## 8. 열린 결정 — 통합 세션에서 정할 것

1. **강제 배분의 보존.** "나쁜 카드도 전부 누군가에게 붙여야 한다"는 오토배틀러의 시그니처
   퍼즐. 카드 드로우 타일에서 "N장 드로우, 전부 배분 의무"로 유지할 것인가.
2. **수직 슬라이스 컷라인.** 시스템 수가 원본 어느 쪽보다 많다(맵 + 전투 + 과제 + 상점 +
   자원). 데모 기준 제안: 타일 ~10개 · 분기 1회 · 전투 1종 + 과제 1종 + 도박 1종 · 파티
   3기 · 카드 ~12장. 여기서 무엇을 더 자를지.
3. **이동 방식 확정.** 자동 전진(§3 제안)으로 갈지, 최소한의 수동 요소를 남길지.

## 9. 데모가 증명해야 할 것 (베이크오프 기준)

- **핵심 검증 질문 (오토배틀러에서 승계):** 고강도 카드 2–3장을 단 에이전트의 판단이
  ① 예상 밖이면서 ② 카드로 소급 가능한가, 그 귀속이 재시도 욕구를 만드는가.
- **턴제 전투에서도 성격이 보이는가:** 이동 없는 전투에서 「겁이 많다」가 화면에 읽히는가 —
  행동 선택 + 말풍선만으로 충분한가.
- **타일 리듬이 지루하지 않은가:** 전진 → 이벤트 → 전진의 사이클이 3–5분 관전을 버티는가.

## 10. 리스크 감시 지점

| 리스크 | 메모 |
|---|---|
| 시스템 폭증 — 두 원본의 합집합은 3주를 넘는다 | §8-3 컷라인을 통합 세션에서 합의. 합집합이 아니라 교집합+스파인으로 |
| 첫 60초가 맵 걷기로 소모될 위험 | 1번 타일 강제 이벤트 (§3) |
| UI 밀도 — 3–4기 × (프롬프트+Skills+MCP+게이지) | 카드/장비 문법 강제. 상세는 유닛 선택 시에만 펼침 |
| 성격 관전의 재미가 턴제에서 죽을 위험 | §9의 검증 질문 2. 데모에서 실측 — Darkest Dungeon이 선례라는 것과 우리가 재현한다는 것은 다르다 |
