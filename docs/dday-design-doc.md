## 1. 한 장 요약

| 항목 | 내용 |
|---|---|
| 제목 | D-Day 시뮬레이션 (가칭) — 시나리오 「테러리스트의 전화」 축소판 |
| 장르 | 텍스트 추리물 × AI 에이전트 빌드 시뮬레이션 |
| 플랫폼 | 웹 (TypeScript, 데스크톱 브라우저, GitHub Pages 배포) |
| 1차 관객 | NHN AI 게임 대회 심사위원 — 로드 ~1초, 첫 60초가 승부처 |
| 세션 구조 | 런 1회 수 분(추정 — 실제 지연 실측 전) × 반복 (남은 런 수 = 게임 내 자원) |
| 런타임 모델 | haiku (판단 콜·보고서 콜 모두) |
| 팀 / 기간 | 2인 / 데모 ~3주 |

**피치:** "Source Code인데, 당신은 기차에 타는 사람이 아니라 **기차에 태울 정신을
만드는 엔지니어다**."

**게임의 정의 세 줄 (07-28 확정):**

- 하나의 task를 에이전트가 성공할 수 있도록 **프롬프팅하는 게임**
- 사건의 숨겨진 진실을 찾아내는 **추리 게임**
- 행동을 조종하지 않는다 — 보고서 2종에서 추출한 '사실'을 주입해
  **에이전트의 '판단'을 변화**시키는 게임

**차별점:** 반복 진입 구조(Source Code·엣지 오브 투모로우·12 Minutes)는 많지만,
*주인공의 행동이 아니라 주인공의 마음을 편집*하는 게임은 없다. LLM을 게임에
포장해 넣는 대신, prompt·context·agent를 용어 그대로 노출하는 노골적인 에이전트
게임 — AI 오케스트레이션 자체가 심사 대상인 이 대회에서 게임 컨셉과 기술 스택이
같은 것을 가리킨다.

**픽션 프레임:** 큰 재앙이 예정된 세계. 플레이어는 재앙 대비 책임자로서 재앙을
재현한 시뮬레이션에 AI 에이전트를 반복 투입한다. 시뮬레이션에서 성공하면 진짜
D-Day — 손댈 수 없는 단 한 번의 실전 런. UI의 D-Day 카운터(= 남은 런 수)가 이
프레임을 상시 노출한다.

## 2. 디자인 필러와 Non-goals

모든 설계 판단은 아래 세 필러로 심사한다. 충돌하면 위가 이긴다.

1. **조종하지 말고, 믿게 하라.** 플레이어는 에이전트의 행동을 클릭하지 않고
   타이핑하지도 않는다. 시뮬레이션이 산출한 문장을 골라 주입해 에이전트의 *믿음*을
   바꾸고, 바뀐 믿음이 판단을 바꾼다. (멤브레인 — 하드 룰)
2. **지는 게 콘텐츠다.** 모든 실패는 다음 빌드의 재료(문장)를 남긴다. 실패
   장면마다 "어떤 문장이 이 실패를 만들었나"가 소급 가능해야 하고, 더 멀리 간
   런이 더 깊은 문장을 캔다.
3. **두 겹의 진실.** 객관 로그(엔진의 사실)와 자필 보고서(에이전트의 해석) 사이
   간극이 정보이자 코미디이자 추리의 대상이다. 하나의 전지적 기록으로 합치지
   않는다.

**Non-goals (의도적으로 만들지 않는 것):**

- 플레이어의 자유 텍스트 입력 — 어떤 형태로도 없다 (멤브레인)
- 공간 이동·그래픽 시뮬레이션 — 에이전트는 한 발짝도 움직이지 않는다 (교환대 무대)
- NPC의 LLM화 — NPC는 상태기계 + 저작 대사 (필요성 미측정, 현재 안 함)
- 런 전체를 LLM 한 호출로 시뮬레이션 — 기각된 아키텍처
- Compact(문장 합성)·토큰 예산 퍼즐 — **Phase-2 후순위**, 데모 범위 제외
- 실시간 액션·타이밍 조작 — 관전은 관전이다

## 3. 코어 루프

```
에이전트 파일 편집 (문장 드래그: 아는 사실 / 가설 / 우선순위 / 절차 …)
  → 시뮬레이션 투입 — 라이브 관전 (손댈 수 없음)
  → 런 종료 → 보고서 2종 (객관 로그 + 자필 보고서)
  → 부검: 두 문서를 대조 — 망한 판단의 원인을 추리
  → 문장 채집 → 파일 수정 → 재투입 … D-Day까지
```

플레이어가 잡을 수 있는 조종간은 둘, 잡을 수 없는 것이 하나다.
셋 모두 같은 판단 지점에서 단독으로 분기를 뒤집음이 실측되었다
([RESULTS](../demos/dday-simulation/poc-terror/RESULTS.md) — 무대 텍스트는
한 글자도 바꾸지 않고).

| 조종간 | 누가 잡나 | 게임에서의 실체 |
|---|---|---|
| **사실** | 플레이어 | `아는 사실`·`가설` 구역에 채집 문장 주입 — 기질 조건을 켜고 끈다 |
| **구조** | 플레이어 | `우선순위` 구역의 순서 재배치 — 순서만 바꿔도 선택이 바뀐다 |
| **기질** | 저작자 (플레이어 비가시) | 에이전트의 판단 방식 그 자체. 레벨 디자인의 재료 |

**핵심 드라마:** 기질은 보이지 않고 고칠 수도 없다. 플레이어는 보고서에 흘러나온
단서로 기질을 추리하고, 그 기질의 조건을 겨냥한 사실을 주입해 판단을 젖힌다.
검증 안 된 추측을 주입하면 분기가 잘못 젖혀진다 — 오염은 연출이 아니라 메커니즘이다.

## 4. 시스템 명세

수치·문구·조건 등 모든 튜너블은 코드가 아니라 데이터로 산다
(레포 규칙 balance-as-data). 데모 단계의 데이터 원형은
[slice-terror.json](../demos/dday-simulation/poc-terror/slice-terror.json)이며,
프로덕션 스키마는 TODO 3 PRD에서 확정한다.

### 4.1 에이전트 파일 — 구역이 나뉜 프롬프트 문서

플레이어가 편집하는 유일한 오브젝트. 타이핑 없이 채집 문장을 **드래그·삭제·재배치**만 한다.

| 구역 | 역할 | 비고 |
|---|---|---|
| `역할` | 에이전트의 임무 정의 | 시작 시 주어짐 |
| `우선순위` | 지침 충돌 시 상위 항목 우선 | **순서가 곧 스펙** — 실측 V5 통과 |
| `절차` | 행동 규율 | 반성 문장의 승격처 (§4.2) |
| `중단 조건` | "~하지 않는다" | 예언의 승격처 — 「13:00에 무너진다」→ "13:00 이후 그 경로를 계획에 넣지 않는다" |
| `아는 사실` | 검증된 문장 | 판단 분기를 젖히는 주 조종간 |
| `가설` | 미검증 문장 | 도박 — 에이전트는 참으로 믿고 행동한다 |
| `보고 형식` | 보고서 작성 지침 | **성장 축** — 이 구역이 빈약하면 보고서도 부실하다. 〔관측〕〔추정〕〔전문〕 표식 지침을 갖추면 보고서가 채집하기 좋게 구조화된다 |

- 기질 구역은 **없다.** 기질은 파일 밖의 비가시 내부 로직이다 (§4.3).
- **결함 표시:** 시작 파일의 빈 구역·모호한 구역은 미리 라벨링하지 않는다.
  런이 그 결함을 문 뒤에 — 해당 보고서 문장과 링크되어 — 드러낸다
  (첫 튜토리얼 런만 예외).
- skill 분리는 보류: 지침이 여러 런에서 재사용되는 다단계 절차로 자라나면 그때
  이름을 얻고 졸업한다.

### 4.2 문장 채집

별도의 카드 시스템 없음 — 보고서 2종의 문장 자체가 재화다.
아래 타입 분류는 **제안 단계 (미확정)** — 채집 스키마와 함께 TODO 3에서 확정한다.

| 타입 | 예 | 채집 게이트 | 주 출처 |
|---|---|---|---|
| 예언 (미래 사실) | 「13:00에 무너지는 것은 폭탄이 아니라 주배관이다」 | 그 시각·그 진실까지 도달한 런 | 객관 로그 |
| 인물 사실 | 「린 딧은 위험이 아니라 일당 때문에 남는다」 | 그 인물과 그 방식으로 부딪힌 런 | 로그 + 보고서 |
| 과거 사건 | 「8년 전 같은 구간에서 한기석이 죽었다」 | NPC 잡담·문서·소문 조우 | 객관 로그 |
| 추측 | 「상황실장은 내 판단이 문서로 남는 게 싫은 것 같다」 | 자필 보고서에서 무료로 흘러나옴 | 자필 보고서 |
| 자기 관찰 | 「나는 12초 만에 회선을 잃었다. 첫 질문으로 위치를 물었기 때문이다」 | 실패의 고백 | 자필 보고서 |

- **채집의 정의 (구현 규칙):** 채집은 "화면의 문장 텍스트 줍기"가 아니라 **저작된
  사실 id 줍기**다. 화면에는 보고서의 표현이 보이고, 프롬프트에는 어휘 정렬이
  관리된 정본이 들어간다 (§4.3의 어휘 정렬 법칙 때문). 멤브레인은 유지된다.
- **추측의 도박성:** 장착하면 참으로 취급된다. 맞으면 지름길, 틀리면 오염. 다음
  런을 생존이 아니라 가설 검증에 쓰는 **정찰 런**이 유효 전략이다 — 검증되면
  추측이 사실로 승급.
- **반성 → 지침 승격:** 자필 보고서의 반성 문장을 `절차`/`중단 조건`으로 드래그하면
  규율로 굳는다. 지침조차 에이전트가 생성한 텍스트다.

### 4.3 기질 — 비가시 내부 로직과 저작 규칙

- **형식:** 분위기 형용사가 아니라 **조건문이 내장된 판단 절차** 산문.
  "A가 기본이다. 단, 조건 C로 *보일* 때는 B를 감행한다." 조건은 진실이 아니라
  에이전트의 지각에 걸린다. 정책은 저작이 갖고, LLM은 퍼지 조건의 평가만 한다.
- **상한:** 인물당 조건 1~2개 (haiku 전제의 하드 상한).
- **비가시·불변:** 캐릭터 시트도 공개 시스템도 없다. 자필 보고서가 기질의 단서를
  흘리는 것이 유일한 관측 채널이다. 시작 픽션 한 줄("요원 인사 파일의 절반은
  인계되지 않았다")로 에이전트 자체가 미지수임을 알린다.

**저작 법칙 (실측으로 확립, 위반 시 코어 루프가 죽는다):**

1. **어휘 정렬 법칙:** 사실 문장은 그것이 겨냥하는 기질 조건이 감시하는 **축의
   어휘**로 쓴다. 위협 축의 부정("위협이 아니다")은 공포 축의 긍정("겁내고
   있다")이 아니다 — 전자는 분기를 못 젖히거나 역효과, 후자는 3/3 플립.
   → 데이터 스키마에서 사실 문장마다 `targets: <기질>.<조건>` 메타데이터 명시.
2. **조건은 번진다:** 기질 조건은 저작자가 의도한 대상 너머로 적용된다(양날의
   재료로 수용). 대상 범위 명시는 케이스별 저작 결정.
3. **서사–수치 일치:** NPC 반응·엔딩 라인·수치 데이터가 모순되면 자필 보고서가
   그 모순을 흡수해 경위를 잘못 쓴다. 저작 검증 단계에 일치 체크 필수.

### 4.4 세계 엔진과 판단 지점

- **세계는 결정론 엔진이 돌린다.** 고정 타임라인·인물 상태·게이트·진실은 전부
  데이터. LLM은 **저작된 판단 지점에서만** 호출된다.
- 판단 호출 — 입력: 에이전트 파일(기질 + 지침/사실/가설) + 그 시점의 구조화된 상황
  요약. 출력(structured output): **닫힌 선택지** + 현장 발화 + 속마음 +
  **rejected(버린 선택지와 버린 이유)**.
- `because` 자기 귀속은 수집하되 **연출 전용** — 게임 로직 판정에 쓰지 않는다
  (실측: 에이전트는 자기 행동과 정반대인 문장을 근거로 인용한다).
- NPC는 상태기계 + 저작 대사. 인물마다 `원하는 것 / 지렛대 / 비밀`이 데이터다.
- 런 하나 = 작은 판단 호출 10~30번 + 런 끝의 긴 생성 호출 1번(자필 보고서).

### 4.5 보고서 2종

| | 객관 로그 | 자필 보고서 |
|---|---|---|
| 저자 | 엔진 (이벤트 로그에서 조립 — LLM 아님) | 에이전트 (haiku 1콜) |
| 성격 | 타임라인 사실 | 기질이 밴 해석·변명·반성 |
| 입력 | 전체 이벤트 | **에이전트가 관측한 것 + 속마음·rejected 누적만** — 간극은 이 정보 비대칭에서 공짜로 생긴다 |
| 게임 역할 | 사실 채집처, 부검의 기준 | 추측·자기 관찰 채집처, **기질 추리의 유일한 채널** |

- 자필 보고서 저작 요건: 판단마다 '판단과 이유' 3박자 강제 — "당시 나는 X라고
  믿었다 / 그래서 Y했다 / 지금 보니 Z".
- **분량 정책 (TODO 3에서 확정):** 실측상 분량 상한을 어기지만 최고의 문장들이
  폐기본에 있었다 — 상한 완화(20~30문장) 또는 채집용 원본 보존 + 표시용 요약
  분리안 중 결정.
- 판단용 에이전트 정의에 메타 어휘 금지 문구 필수 ("내 기질이 아니고" 누출 방지 —
  1줄로 해결되는 종류의 문제, TODO 3에서 반영).

### 4.6 점수 · 런 자원 · 엔딩

- **단일 지표:** 13:07 시점 안전선 밖(= 대피에 성공한) 인원 / 413. 개입 없는
  런은 61/413.
- **판정식:** 대피 완료 = 그 집단의 이탈 지시가 **13:00 − 소요시간(집단별
  4~14분) 이전에 발효**된 경우. 점수 = Σ(집단 인원 × 대피 완료 여부).
- 집단별 소요시간이 달라 **같은 총점도 다른 이야기**가 된다.
  마지막 1점(412→413)은 단 한 사람(강문호)의 몫 — 이 게임에서 가장 어려운 점수.
- **런 횟수 = 자원:** D-Day까지 남은 날짜가 곧 남은 런 수. UI에 상시 노출.
  총 런 수는 튜너블(데이터) — 수치 미정.
- **엔딩:** 시뮬레이션 성공 시 진짜 D-Day — 손댈 수 없는 단 한 번의 실전 런.
  내가 빚은 에이전트의 무편집 단독 공연 (심사 영상 클라이맥스 후보).
- **미정 (TODO 3/5에서 결정):** ① 실전 런 진입의 성공 기준(만점 필수인가,
  임계 점수인가) ② 런 자원을 소진하고도 성공 못 했을 때의 처리 — 준비 안 된
  에이전트가 그대로 실전에 투입되는 배드 엔딩이 픽션상 자연스러운 후보다.

### 4.7 LLM 아키텍처

- **모델:** haiku (판단·보고서 모두) — V0 기준선 통과 (스키마 24/24, tool 위반 0/82).
- **호출 경로:** 클라이언트 → 프록시 백엔드 → 모델. 클라이언트에 키를 심지 않는다.
- **역할 격리는 프롬프트가 아니라 실행 환경으로.** 시스템 프롬프트는 프록시가
  소유하고, 클라이언트는 구조화된 게임 요소만 보낸다. structured output 스키마
  강제 (페이퍼 테스트의 코드펜스 잡음은 tool-use 스키마로 소멸하는 종류).
- **지연 은닉 5규칙:**
  1. 결정론 이벤트는 저작 데이터라 즉시 출력 — 화면은 LLM 없이도 계속 살아 있다.
  2. 판단 지점은 타임라인상 미리 알려져 있다 — **선발사(prefetch)**. 플레이어가
     앞 줄을 읽는 시간이 다음 호출의 버퍼다.
  3. 기다림을 디제시스 안에 — "…무전 회신 대기 중"은 랙이 아니라 서스펜스다.
  4. 가장 긴 호출(자필 보고서)은 집계 화면(생존자 숫자 카운트업) 뒤에 숨긴다.
  5. 보고서 생성은 **SSE 스트리밍**으로 받아, 에이전트가 실제로 보고서를
     써 내려가는 듯한 UI 연출 안에 지연을 숨긴다 — 토큰이 도착하는 속도
     자체가 타자 연출이 되므로, 관전 화면=문서(§6)의 미학과도 맞는다.
     규칙 4와 병용한다: 집계 화면이 첫 토큰 지연(TTFT)을 먹고, 이어지는
     스트리밍 타자 연출이 나머지 생성 시간을 먹는다.
- 미드 액션을 LLM 응답에 블로킹하지 않는다 (레포 하드 룰).
- darkest-context의 "의도만 LLM, 실행은 엔진" 원칙은 승계하되, 코드는 승계하지
  않는다 — **LLM Layer는 새로 구현한다** (TODO 4).

## 5. 콘텐츠 스코프 — 「테러리스트의 전화」 축소판

원안: [시나리오\_테러리스트의전화.md](./시나리오_테러리스트의전화.md).
축소판 상세(열린 결정 3건 포함)는 별도 PR로 반영 예정 — 반영 시 이 섹션이 그
문서를 가리키도록 갱신한다.

| 축 | 원안 | 축소판 (확정 방향) |
|---|---|---|
| 인물 | 15명 | **10명** — 문정아·임하늘·차민석·남기훈은 언급만 되는 오프스크린 존재로 강등 |
| 숨겨진 진실 | 5개 | **4개** (T1 흡수) |
| 실패 게이트 | 7개 | **6개** (G2 지휘권 + G3 수사 방향 통합) |
| 판단 지점 | — | **미정** — 런당 판단 호출 10~30번(§4.4)과 정합하도록 TODO 3에서 확정 |

- **무대:** 유리방(상황실) 단일 공간 + 회선·CCTV로만 존재하는 7곳. 지도는 도시가
  아니라 교환대다. 첫 60초 훅: 첫 질문을 잘못 고르면 회선이 12초 만에 죽는다.
- **척추 (수용된 반전):** T3 — 13:00은 협박범이 정한 시각이 아니다. 이 진실이
  밝혀지는 순간 목표가 '막기'에서 '비우기'로 바뀌고, 이전 런들의 협상 시도가
  전부 소급 재해석된다. 훅은 60초의 몫, 반전은 3런째의 보상.
- **엔딩 규율:** 강문호가 나오는 이유는 감동이 아니라 **거래**여야 한다 — 기록을
  남길 사람이 밖에 생겼기 때문에 나온다. 신파 금지.

**레벨 디자인 규칙 (실측에서 획득):**

1. 서열을 드러내려는 판단 지점에는 "둘 다 만족" 탈출구 옵션을 두지 않는다 —
   탈출구가 있으면 조건 충돌이 일어나지 않는다.
2. 상황은 기질 조건의 **경계**에 배치한다 (5인인지 4인인지 애매한 장면) — 이것이
   이 게임에서 레벨 디자인의 정의다.
3. 저작 검증 체크리스트: 어휘 정렬(`targets` 명시) · 서사–수치 일치 · 게이트가
   단일 경로에 묶이지 않을 것 · `visible_if` 누락 없을 것 (slice 버그 3건의 재발 방지).

## 6. UX/UI

화면은 셋, 루프의 세 박자와 일대일이다.

| 화면 | 내용 |
|---|---|
| **빌드** | 에이전트 파일(구역 문서) + 채집 문장 보관함. 드래그·삭제·재배치만 |
| **관전** | 캐릭터 그림이 아니라 **스스로 써 내려가는 문서.** 타임라인 로그가 게임 시간의 박자로 한 줄씩 타이핑되고, 사이사이 에이전트의 무전·통화 발화가 도착한다. 손댈 수 없음 |
| **부검** | 보고서 2종 나란히 + **증거판 UI** — 보고서에서 문장을 오려 에이전트 파일에 핀으로 꽂는 '미제사건'식 조작이 곧 문장 채집의 물리적 감촉 |

- 상시 노출: D-Day 카운터(남은 런 수), 현재 시각/13:00 카운트다운.
- 게임의 소품은 전부 문서다: 명부, 타임라인 로그, 자필 보고서, 무전 기록, 매뉴얼,
  신문철. **아트 방향: 타이포그래피 + 문서 아트** (도장, 붉은 줄, 검게 칠한 명부).
- 무력감의 설계: 관전 중 "지금 왼쪽으로 가야 하는데!"의 무력감이 다음 빌드
  화면에서 프롬프트를 고치는 손맛으로 전환된다.
- **심사 경험:** 페이지 로드 ~1초(정적 배포, 에셋 최소). 데모는 1런이 아니라
  **3런째 상태에서 시작** — 채집 문장이 이미 몇 개 있고, 첫 60초 안에
  "문장을 꽂는다 → 판단이 바뀐다"를 보여준다.
- **영속 저장 없음:** 진행 상태(채집 문장·해금 진실·남은 런 수)는 세션 한정 —
  새로고침하면 초기화된다.
