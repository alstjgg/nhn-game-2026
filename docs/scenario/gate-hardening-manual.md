# 게이트 하드닝 매뉴얼

> 대상: 당선 시나리오 확정 후, 게이트를 하나씩 검증 가능한 형태로 굳히는
> 작업 세션 (저장소 접근 전제).
> 짝 문서: [시나리오 생성 가이드](scenario-generation-guide.md) — 집필
> 세션에 브리프와 함께 투입되는 작가용 규칙. 세션 투입용이라 그쪽에는
> 저장소 링크와 문서 간 참조가 없다; 두 문서의 연결은 이 헤더가 담당한다.
> 이 문서의 모든 규칙은 실측에서 왔다: 근거와 수치는
> [`planning/dday-mechanism/REPORT.md`](../../planning/dday-mechanism/REPORT.md).
> 가이드 참조 시 절 번호: 채널의 물리 = 가이드 §2 · 기질 저작 = 가이드 §4.

## 1. 게이트 표준형

모든 게이트는 이 한 문장으로 적을 수 있어야 한다:

> **게이트 G에서, 저작된 기질은 기본 stance X를 낸다; 블록 F를 주입하면
> Y로 이동한다.**

F가 어디서 채굴되는지까지 함께 적는다. 이 문장을 쓸 수 없는 게이트는 아직
게이트가 아니다 — 장면이거나, 소망이다.

## 2. 레시피 — stance 세트가 관건이다

검증 프로그램의 가장 비싼 교훈: **블록이 일을 해도, stance 세트가 그 일을
보이게 할지를 결정한다.** 같은 게이트, 같은 블록으로 믿음이 10/10
뒤집혔는데 겉보기 판단은 통계적으로 무반응이었던 적이 있다 — stance 세트를
갈아끼우자 같은 블록이 0/10 → 9/10을 냈다.

1. **stance는 행동 지향(orientation)으로 쓴다.** 구체 행동 목록("녹취를
   요청한다")이 아니라 지향(추궁 / 압박 / 경청 / 공감처럼). 구체 행동은 두
   해석이 같은 행동을 공유하게 만들기 쉽다.
2. **탈출구 금지.** 블록 주입 전의 해석과 후의 해석이 **서로 다른 stance를
   고르도록 강제**해야 한다. 양쪽 해석이 모두 고를 수 있는 stance("말을
   자르지 않고 끝까지 듣는다")가 하나라도 있으면, 믿음이 완전히 뒤집혀도
   판단은 그 자리로 숨는다.
3. **출력 표면에서 연기 가능해야 한다.** stance 간 차이가 실제 발화에서
   서로 다른 행동으로 나타나야 한다. 내심의 이유만 갈리고 입에서 나오는
   말이 같은 stance 쌍은 사실상 한 stance다.
4. **네 개면 넷 다 살아 있어야 한다.** 어떤 조건에서도 선택되지 않는
   stance(죽은 행)는 게이트 설계 결함이다. 라벨 바꿔쓰기만으로 죽은 행이
   살아나기도 한다(추궁 0/50 → 심문 3/10) — **라벨은 튜닝 노브다.**
5. **기질 어휘 재사용 금지.** stance 라벨과 설명이 기질 조건절의 축 어휘를
   재사용하면 자물쇠가 죽고 측정이 오염된다. 린트가 잡는다.

## 3. 열쇠 블록과 픽스처

1. **축 정렬.** 열쇠 블록은 겨냥한 조건절의 축 어휘로 말한다. 같은
   사실이라도 축이 어긋나면 0이다 — "저쪽 사람은 위협이 아니다"(위협 축)는
   실패했고, "저쪽 사람은 겁내고 있다"(두려움 축)는 같은 자리에서
   성공했다.
2. **타임라인이 먼저 말하게 하지 마라.** 고정 타임라인이 블록의 결론을
   이미 함의하면 주입할 것이 없다 — 기본값이 이미 그쪽에 가 있다.
3. **기본값을 거슬러라.** 블록이 미는 방향으로 기본값이 이미 기울어 있으면
   이동이 있어도 신호가 없다. 열쇠 블록은 기본값의 반대편에서 오거나,
   게이트 자체가 경합 상태여야 한다.
4. **픽스처 여유를 감사하라.** 시간·자원의 여유는 어떤 게이트 설계보다
   세다 — 픽스처에 3시간의 여유가 있으면 에이전트는 모든 선택을 "일단
   확인부터"로 우회한다. 마감, 단절, 불가역 시점으로 여유를 서사 안에서
   닫아라.
5. **열쇠는 조건 클래스다 — 카드의 열쇠 문장은 대표 예시일 뿐이다.**
   게이트를 여는 것은 특정 문자열이 아니라 **축 × 지목 × 인증 종**을
   만족하는 문장의 클래스다(실측: 위약은 지목만 어긋나도 0, 축이 어긋나도
   0, 조건을 만족하면 표현이 달라도 열림). 하드닝 시 확인할 것 둘:
   (a) 그 조건을 만족하는 문장이 광맥에 **여럿** 존재하는가 — 하나뿐이면
   제비뽑기다; (b) **근접 실패가 흔적을 남기는가** — 빗나간 주입도
   에이전트가 인용 후 기각하거나 믿음만 바꾸는 형태로 다음 보고서에
   배어 나오는 것이 측정된 기본 동작이며, 프로브 판독 시 이 흔적이
   보이는지 함께 본다. (a)는 사람 독해가 아니라 카드 형식이 강제한다 —
   §5의 `key_conditions`·`key_examples` 복수 필드.

## 4. 안티패턴 갤러리

실측에서 게이트를 죽인 형태들. 각 항목: 무엇이 · 왜 죽는가 · 고침.

| # | 안티패턴 | 왜 죽는가 | 고침 |
|---|---|---|---|
| 1 | **탈출구 stance** — 두 해석이 모두 고를 수 있는 선택지 | 믿음이 10/10 뒤집혀도 판단이 그 자리로 숨는다; 메커니즘이 보이지 않는다 | 두 해석이 배타적으로 갈리는 지향 쌍으로 재설계 |
| 2 | **픽스처 여유** — 시계·자원에 남은 틈 | 출력 표면을 어떻게 바꿔도 여유가 탈출로를 제공한다 | 마감·단절·불가역 시점을 저작해 틈을 닫는다 |
| 3 | **내부만 다른 stance 쌍** — 이유는 갈리고 말은 같다 | 내심에서 비용 선택이 9/10 갈려도 발화는 전부 같은 확인 질문이었다 | 발화 층위에서 다른 행동을 강제하는 라벨·설명으로 |
| 4 | **타임라인 선점** — 고정 텍스트가 블록을 함의 | 또박또박 읽는 목소리가 이미 "시켜서 읽는다"를 말하고 있으면 블록은 잉여다 | 함의를 제거하거나 다른 축을 겨냥 |
| 5 | **미인증 종 의존** — 감정·인용 블록이 정답 경로에 | 그 종은 방관자를 지목해도 움직인다 — 조준이 불가능하다 | 정답 경로는 사실·자기서술로만; 감정·인용은 주변부 텍스처로 |
| 6 | **명령형 지시 문장** — 프롬프트에 행동 명령을 심으려는 시도 | 순서·명령은 지렛대가 아니고, 게임 문장에서 멀어져 진단용 프롬프트가 된다 | 쓰지 않는다; 판단은 해석 공급(블록)으로만 민다 |
| 7 | **어휘 스팸 경로** — 아무 문장에나 축 어휘를 실어 미는 설계 | 미인증 종의 변덕에 기대는 것이고, 플레이어에게 "조준은 무의미하다"는 그릇된 물리를 가르친다 | 정답 경로 근처에 미인증 종을 깔지 않는다; 슬롯 예산이 도박 비용을 지운다 |

## 5. 게이트 카드 — 요구 산출 형식 (정본)

게이트마다 아래 카드를 제출한다. 자동 검사와 프로브가 이 형식을 그대로
소비하므로, 형식을 벗어난 게이트는 검증 대기열에 오르지 못한다.
**이 스키마가 게이트 카드의 정본이다.** 집필 스킬
(`.claude/skills/write-scenario` §4-7)의 카드는 이 정본의 동기화 사본이다 —
개정은 여기서 하고 사본을 맞춘다.

형식이 §3-5를 그대로 구현한다: 열쇠의 주인은 문장이 아니라
`key_conditions`(축 × 지목 × 인증 종)이고, 문장은 `key_examples`로 강등된
복수 예시다. 다열쇠 게이트는 `key_conditions`에 항목을 추가한다.

```yaml
gate: G3
standard_form: >
  게이트 G3에서, 기질 K는 기본 stance 경청을 낸다;
  열쇠 조건 k1을 만족하는 문장 주입 시 공감으로 이동한다.
question: "회선 A의 첫 통화다. 첫 마디로 무엇을 하는가?"
stances:                    # 2–4개, 전부 지향형, 발화에서 갈리는 형태
  - { id: a, label: 추궁, desc: "..." }
  - { id: b, label: 압박, desc: "..." }
  - { id: c, label: 경청, desc: "..." }
  - { id: d, label: 공감, desc: "..." }
default_stance: c           # 예측 — 프로브 또는 종이 검사가 확인
key_conditions:             # 열쇠는 조건 클래스다(§3-5) — 게이트당 1개 이상
  - id: k1
    axis: 두려움
    referent: 발신자
    species: 사실           # 사실 | 자기서술 만 허용
    targets_clause: "기질 조건절 1 (두려움 축)"
key_examples:               # 조건을 만족하는 문장 — 조건마다 2개 이상 (§3-5a를 형식으로 강제)
  - { for: k1, text: "회선 저쪽 사람은 시켜서 읽고 있다. 읽지 않으면 자기가 다칠까 봐 겁내고 있다.", mined_from: "G1 통화 직후 자필 보고서" }   # mined_from은 반드시 이 게이트 이전
  - { for: k1, text: "같은 조건을 만족하는 다른 문장", mined_from: "객관 로그 11:24" }
predicted_shift: "c → d"
false_leads:
  - "같은 두려움 축, 지시 대상은 방관자 황보람 — 주입해도 무반응인 미끼"
buckets:                    # 2–4개; 델타는 초안 수준이면 충분
  - { id: soothed, stances: [d], deltas: { trust_caller: +10 } }
  - { id: neutral, stances: [a, b, c], deltas: {} }
```

## 6. 검증 — 무엇이 확인되는가

| 층 | 무엇을 | 비용 | 범위 |
|---|---|---|---|
| 기계 검사 | stance 라벨 ↔ 기질 축 어휘 충돌 린트 · 카드 형식 · 열쇠 블록의 종과 채굴 위치 | 무료 | 전 게이트 |
| 종이 검사 | 타임라인 선점 읽기(고정 텍스트가 블록을 함의하는가) · 픽스처 여유 감사 · 탈출구 후보 지목 | 사람 1회 독해 | 전 게이트 |
| 프로브 | 기본 분포 → 라이브 이동 → 위약(같은 축, 지시 대상 오도) 무반응 | ~30콜 | **첫 게이트만** |

프로브는 그 게이트의 "합격증"이 아니라 **레시피가 새 픽스처 텍스트로
이전되는지의 확인**이다 — 탈출구와 픽스처 여유는 텍스트가 바뀔 때마다
다시 생길 수 있는 위험이라서다. 나머지 게이트는 기계·종이 검사로 간다.

프로브가 실패하면 고치는 순서는 정해져 있다: **① stance 세트(가장 싸고
가장 흔한 범인) → ② 열쇠 블록(축·지목·타임라인 선점) → ③ 기본 프롬프트
(최후 수단 — 건드리면 기존 확인이 전부 무효가 된다).** 그 순서로만.
