# 게임 기획서 — 약사 (Apothecary)

**가제 후보:** 「뒷골목 약방」 / 「오늘의 처방」 / 「Apothecary」 (미정)

> "손님이 말하는 병과, 손님이 앓는 병은 다르다."

---

## 1. 개요

**한 줄 피치:** 손님의 말과 행동에서 *진짜* 문제를 읽어내고, 재료와 방법을 골라 약을 지어
내보내는 추론형 상점 운영 게임. 손님을 만들어내고, 내 판단의 결과를 돌려주는 것은 AI다.

| 항목 | 내용 |
|---|---|
| 장르 | 추론형 상점 경영 시뮬레이션 |
| 플랫폼 | 웹 (GitHub Pages — 링크 클릭 즉시 플레이) |
| 세션 구조 | 손님 1명 ≈ 2분. 심사 기준 3–5분 플레이에 손님 3명 + 결과 2건 도착 보장 |
| 타겟 | Potion Craft·Strange Horticulture류 추론 게임 팬, 코지 심 관객. "아픈 사람, 숨은 원인"이라는 훅은 장르 지식 없이도 통한다 — 처음 보는 심사위원 기준으로 설계 |
| 레퍼런스 | Potion Craft, Strange Horticulture (조제·추론의 감각) / Is This Seat Taken? (코지 톤) — 결정적 차이는 §7 |

플레이어는 AI에게 자유 텍스트를 입력하지 않는다. 모든 입력은 관찰·대화 선택지·재료·방법이라는
게임 동사로 이루어진다. 이 원칙을 이 문서에서 **멤브레인**이라 부른다 (부록 B).

## 2. 첫 60초 — 심사위원이 보게 될 장면

문이 열린다. 젊은 여자가 카운터에 팔을 얹는다. "제일 독한 수면제 주세요."

화면에는 손님의 초상과 대사, 대화 선택지 세 개, 그리고 [관찰] 버튼이 있다. 관찰하면 —
손끝에 찻물 얼룩. 왜 못 주무시냐고 직접 물으면 말을 돌린다. 대신 하루 일과를 묻자, 자정마다
홍차를 우리며 옆집 이야기를 곱씹는다는 말이 흘러나온다. 질문을 하나 고를 때마다 손님의
인내심 게이지가 줄어든다.

말하는 병은 불면. 진짜 문제는 자기 전의 각성 습관과 화. 독한 수면제 대신 순한 진정차를
조제해 [건네기]를 누른다. 손님은 반신반의하며 문을 나선다. 결과는 지금 나오지 않는다.

다음 손님을 응대하던 중, 문이 다시 열린다. 그 여자다. 며칠 만에 얼굴이 맑다. 홍차를
끊었다고 한다.

이 60초에 게임의 전부가 있다: 관찰 → 우회 질문 → 진단 → 커밋 → 지연된 결과의 귀환.
(이 장면은 창작이 아니라 페이퍼 테스트 실플레이의 재구성이다 — 부록 A.)

## 3. 경험 목표

| 키워드 | 플레이어가 느끼는 것 |
|---|---|
| **진단의 긴장** | 제한된 질문 안에서 진짜 문제를 읽어내야 하는 압박 |
| **커밋의 무게** | [건네기] 전에는 아무것도 확정되지 않고, 누른 뒤에는 되돌릴 수 없다 |
| **지식의 클릭** | "꽃은 우리고, 뿌리는 달인다" — 실패에서 배운 법칙이 다음 손님에게 통하는 순간 |
| **되돌아오는 운명** | 내 판단을 들고 나간 손님이 어떤 얼굴로 돌아오는가 |
| **틀린 답 없음** | 사망도, 부작용도, 오용도 실패 낙인이 아니라 내 판단의 결과이자 새 분기다 |

## 4. 핵심 루프 (1사이클 ≈ 2분)

```
손님 입장
  → 관찰 + 분기 대화 (인내심 예산 안에서)
  → 진단 가설 수립
  → 조제 (재료 선택 × 방법 선택)
  → [건네기] — 명시적 커밋
  → …지연… → 결과 도착 (재방문 / 문앞 쪽지 / …)
  → 지식·평판·단골 관계 변화 → 다음 손님
```

- **사이클은 겹친다.** 손님 N의 결과는 손님 N+1~N+2를 응대하는 중에 도착한다. 지연된
  결과는 대기 시간이 아니라 가게의 리듬이 된다.
- **긴장과 해소가 2분 안에 완결된다.** 인내심 안에서의 진단 압박(긴장) → 조제가
  맞아떨어지는 순간과 "아, 껍질은 달여야 했구나"라는 깨달음(해소).
- **심사 페이싱:** 첫 손님의 결과는 특히 빠르게, 다음 손님 응대 중에 돌려준다.

## 5. 핵심 시스템

### 5.1 대화와 관찰

대화 선택지는 AI가 직전 대화에서 갈라지는 형태로 생성하고, 플레이어는 선택만 한다.
직접 질문("어디가 아프세요?")은 회피당하고, 우회 질문(하루 일과, 최근 있었던 일)이 단서를
연다. [관찰]은 대사 밖의 단서 — 손끝의 얼룩, 옷차림, 냄새 — 를 보여준다.

### 5.2 인내심

질문은 자원이다. 질문마다 인내심이 깎이고, 너무 캐물으면 손님이 짜증을 내거나 나가버린다.
"선택지를 전부 클릭"이 최적해가 되지 않게 하는 장치 — 무엇을 물을지가 곧 선택이 된다.

### 5.3 조제 — 최우선 빌드 타깃

재료(10±α종)에는 물성 태그가 있고, 조제 방법(우리기 / 달이기 / 빻기 …)이 결과를 바꾼다.
같은 캐모마일도 우리면 진정차, 달이면 망친 쓴물이다. 이상한 조합은 이상한 결과를 낳는다
(창발 조합). 실패와 멘토의 힌트로 배운 법칙은 **코덱스**에 쌓여 다시 찾아볼 수 있다.

페이퍼 테스트의 최우선 지적이 "조제 자체의 재미 부족"이었다 (부록 A). 조제가 "두 개를 파는
느낌"이면 실패다 — 이 시스템을 최우선 빌드 타깃으로 선언한다.

### 5.4 [건네기] 커밋

[건네기] 이전에는 아무것도 해소되지 않는다. 손님이 멋대로 약을 먹고 가버리는 일은 없다.
테스트에서 확인된 하드 UX 룰이다.

### 5.5 결과 채널과 지연

결과는 세계의 채널로 도착한다: 재방문, 문앞 쪽지, 신문 기사, 거리의 소문. 채널당 텍스트는
80자급으로 짧게 유지한다.

### 5.6 멘토

가게의 스승 캐릭터가 옆에서 조잘댄다. 역할은 세 가지 — 판정 이유를 세계의 언어로 해설
(공정성을 읽을 수 있게), 레시피 지식 전달(코덱스 해금), 자연스러운 튜토리얼. 테스트에서
그 자체로 매력 포인트였다 (부록 A).

### 5.7 평판 = 손님 집단, 그리고 루트

단골 개인의 호감도에 머물지 않는다. 누적된 판단이 **누가 이 가게에 오는가**를 바꾼다.
"엔딩"은 별도 시나리오가 아니라 평판·지식·손님 집단의 누적 상태가 도달하는 방향이다.
모든 루트는 동등하게 유효하다.

- **명의(名醫)** — 정확한 진단의 누적. 먼 마을에서 난치 환자가 찾아오고, 가게 앞에 줄이 늘어선다.
- **지식 탐구** — 결과보다 법칙. 실험적 조제로 코덱스를 채워, 후대에 남을 약전(藥典)의 저자가 된다.
- **뒷골목** — "조용한 일"의 조제 의뢰가 들어온다. 어느 날 문에는 감사 쪽지 대신 지폐 다발이 꽂혀 있다.
- **중독의 왕** — 잘 듣는 약, 너무 잘 듣는 약. 가게는 번창하고, 마을의 눈빛이 흐려진다.

구현은 경량으로 간다: 분기 시나리오가 아니라 평판 축 + 손님 풀 전환 + 에필로그 비네트.
비네트 작문은 AI 역할 ④(§6)의 자연스러운 확장이다.

## 6. AI 활용

런타임 AI의 역할은 네 가지다:

| # | 역할 | 한 줄 설명 |
|---|---|---|
| ① | 손님 저작 | 이름·외형·성격·증상 호소, 그리고 숨은 진짜 문제를 가진 손님을 생성 |
| ② | 분기 대화 생성 | 직전 대화에서 갈라지는 다음 선택지 3개를 생성 |
| ③ | 결과 판정 | [준 약의 물성] × [숨은 문제] × [위험도]로 결과를 결정 |
| ④ | 결과 서술 | 결과 비네트와 멘토의 해설 대사를 작문 |

### 공정성 설계 — AI는 레일 위에서만 판단한다

- **단서 계약:** 손님을 제시하기 *전에* [진짜 문제 / 단서 2–3개 / 레드헤링 ≤1 / 위험도
  1–5]를 확정한다. 소급 수정은 금지 — 단서는 계약이다.
- **놓친 단서 인용:** 나쁜 결과의 서술은 플레이어가 놓친 단서를 반드시 인용한다. 결과가
  "모델의 변덕"이 아니라 "내 오독"으로 읽히게 하는 공정성 엔진이다.
- **정오 낙인 금지:** 내부 등급(적중/부분/불일치)은 결과의 심각도를 정하는 데만 쓴다.
  "정답/오답" 표시는 절대 노출하지 않는다 — 틀린 답 없음(§3)의 구현이다.

이 세 규칙은 이론이 아니라, 페이퍼 테스트에서 판정을 공정하게 느끼게 만든 바로 그
가드레일의 전사다 (부록 A).

### 비용·지연 설계

- 발화 단위가 아닌 **판단 단위**의 희소 호출. 지연은 "결과가 나중에 도착하는" 게임 리듬에
  자연스럽게 숨는다.
- 동일 [재료×방법] 조합의 물성 판정은 **캐시**한다. 결과가 학습 가능해지고, 반복 플레이에
  전략이 생긴다.
- 손님 풀은 [런타임 생성]과 [사전 생성+검증 후 탑재]를 혼합한다 — 품질 보증과 지연·비용
  관리의 밸브.
- 모든 호출은 프록시 서버 경유(팀원 B 담당). 클라이언트에 키를 심지 않는다.

## 7. 차별화 — 세 가지

1. **판매가 이야기의 시작이다.** 기존 상점 심(Recettear, Moonlighter, Adventurer Shop
   Simulator …)은 계산대에서 이야기가 끝난다 — 손님에게 운명이 없다. 이 게임에서 손님은
   내 판단을 들고 문을 나서고, 그 운명이 되돌아온다.
2. **모든 손님이 나만의 손님이다.** 추론형 상점 게임(Potion Craft, Strange Horticulture)은
   "숨은 니즈 읽기"가 사랑받는다는 걸 증명했지만, 전부 손으로 쓴 유한 스크립트다. AI 저작은
   손님·단서·후일담을 플레이어마다 고유하게 만든다. 내 약방의 역사는 나만의 것이다.
3. **판돈은 있고, 타이핑은 없다.** 기존 AI 게임의 지배적 형태 — 자유 텍스트 챗봇 — 를
   삭제했다. 게이머가 싫어하는 것은 AI가 아니라 챗봇이다 (부록 A).

정직한 주석 하나: 기술적 해자는 없다. 해자는 루프 설계와 가드레일 공예이고, 대회 규모에서는
그것으로 충분하다.

## 8. 아트 & 화면

**톤 방향: 코지한 표면, 어두운 바닥.** 낮의 약방은 따뜻하다 — 나무 카운터, 마른 약초 다발,
조잘대는 멘토. 그러나 뒷골목·중독 루트가 열리면 같은 화면의 조도와 손님의 얼굴이 달라진다.
아늑함이 디폴트, 그늘은 플레이어가 선택한 만큼.

화면 구성(텍스트 목업):

```
┌────────────────────────────────────────────────┐
│  카운터 너머 — 손님 초상 + 대사          평판 ✦   │
│                              인내심 ▮▮▮▯▯      │
├────────────────────────────────────────────────┤
│  [선택지 1]  [선택지 2]  [선택지 3]  [관찰]        │
├────────────────────────────────────────────────┤
│  재료 선반 (10칸)   방법: 우리기 · 달이기 · 빻기    │
│  코덱스 📖                        [ 건네기 ]     │
└────────────────────────────────────────────────┘
```

한 화면에 게임의 모든 동사가 있다. 화면 전환 없이 관찰 → 대화 → 조제 → 커밋이 이어진다.

## 9. 스코프 & 3주 마일스톤 (제안)

> 최종 컷라인은 컨셉 확정 후 분해 단계에서 확정한다. 아래는 실현 가능성 판단을 위한 제안이다.

**수직 슬라이스 (Must):**
손님 파이프라인 8–12명(단서 계약 포함) · 분기 대화 + 관찰 + 인내심 · 재료 10종 × 방법
2–3종 · 판정기(레일 + 놓친 단서 인용) · 결과 채널 2종(재방문, 문앞 쪽지) · 멘토 ·
[건네기] 커밋 UX · 코덱스

**확장 (Nice):**
평판 축 + 손님 풀 전환 · 에필로그 비네트 · 신문/소문 채널 · 비율/정밀 조제 · 단골 라포 심화

| 주차 | 목표 |
|---|---|
| 1주차 (~07/29) | 핵심 루프 수직 슬라이스 — 손님 3명을 입장부터 결과까지 관통. 조제 깊이 우선 |
| 2주차 (~08/05) | 콘텐츠 폭 — 손님 8–12명, 결과 채널, 멘토·코덱스, (여유 시) 평판·에필로그 |
| 3주차 (~08/10) | 기능 동결. 폴리시 + 제출물(영상 30–60초, 소개·기술 문서, 밸런스 튜닝) |

기술 노트: 웹 네이티브(Vite + TS strict, 엔진은 컨셉 확정 후 선정). 밸런스 수치는 전부
`data/`에 데이터로 둔다.

| 리스크 | 대응 |
|---|---|
| AI 판정이 자의적으로 느껴질 위험 | 단서 계약 + 놓친 단서 인용 + 정오 낙인 금지(§6). 적대적 플레이 3종 테스트에서 공정성 확인 (부록 A) |
| 조제 자체가 재미없을 위험 | 테스트에서 확인된 최대 격차. §5.3을 최우선 빌드 타깃으로 선언 |
| "전부 클릭"이 최적해가 되는 문제 | 인내심 비용으로 구조적 차단(§5.2) |
| AI 지연·비용 | 판단 단위 호출 + 판정 캐시 + 사전 생성 하이브리드(§6) |
| 커밋 전에 결과가 새는 UX | [건네기] 이전에 아무것도 해소되지 않는다는 하드 룰(§5.4) |

## 부록 A — 검증 근거

### 페이퍼 프로토타입 테스트 (2026-07-21)

핸드플레이 11명 손님(대장장이 6 / 약사 5 / 판정 스트레스 테스트 3플레이). 전체 리포트:
`docs/paper-test-shop-concepts-report.md`. 이 기획서의 아키텍처는 이 테스트 결과의 반영이다.

- **H1 손님 저작 — PASS.** AI가 성격이 드러나는, 추론 가능한 숨은 문제를 가진 손님을
  일관되게 만들어냈다. "NPC들의 대사와 반응. 성격이 보이는 대사들이 좋았고, 내가 행동을
  하면 그거에 맞게 반응하는 것을 보는 게 재밌었어." §2의 장면은 이 테스트 실플레이(손님
  '델핀')의 재구성이다.
- **H2 플레이 재미 — PASS (조건부).** "관찰과 대화가 재밌었어" / "재방문한 손님 응대가
  흥미로웠다. 하나를 고쳤더니 문제가 더 생긴 느낌." 조건: 조제 깊이 보강 — "약을 제조하는
  재미는 아직 부족한 느낌이었다." (§5.3의 근거)
- **H3 판정 공정성 — PASS (강).** 의도적 엣지 플레이 3종(그럴듯하지만 틀린 처방 / 옳은
  약을 오용할 성격의 손님 / 독약 의뢰에 가짜 약으로 응수) 전부 정합적으로 해소.
  "판정이 공정하고 일리있다고 느꼈어. 납득됐고, 재밌었어." 특히 대본에 없던 창의적
  해법(무해한 위장 조제)을 판정기가 받아낸 것은 결정론 시뮬이 구조적으로 못 하는 일 —
  이 아키텍처의 존재 증명이다.
- **테스트가 도출한 핵심 교정:** "틀린 답이라는 것은 없으면 좋겠어. 사람이 죽은 것도,
  다치는 것도, 오용하는 것도 전부 그냥 '내 판단의 결과'인 거지." → §3의 "틀린 답 없음",
  §6의 정오 낙인 금지가 그 반영이다.

## 부록 B — 용어집

- **멤브레인** — 플레이어와 AI 사이의 막. 플레이어는 자유 텍스트를 입력하지 않고, 모든
  입력은 구조화된 게임 동사(관찰·선택지·재료·방법·건네기)로만 AI에 전달된다.
- **단서 계약** — 손님 제시 전에 숨은 문제와 단서를 사전 확정하고 소급 수정을 금지하는
  규칙. 판정 공정성의 뿌리.
- **인내심 예산** — 손님마다 질문에 쓸 수 있는 한도. 질문을 자원으로 만들어 "전부 클릭"을
  차단한다.
- **판정 캐시** — 동일 [재료×방법] 조합의 판정 결과를 저장·재사용하는 것. 비용 절감과
  "법칙의 학습 가능성"을 동시에 얻는다.
- **결과 채널** — 판단의 결과가 도착하는 세계 내 경로(재방문, 문앞 쪽지, 신문, 소문).
- **코덱스** — 실패와 멘토의 힌트로 해금되는 레시피 지식 노트. "껍질은 달인다" 같은 법칙이
  쌓인다.
- **수직 슬라이스** — 폭은 좁아도 입장부터 결과까지 전 층을 관통하는 최소 완결 빌드.
