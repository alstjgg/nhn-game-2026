# Field Report — 실행 예시 스펙

> **rev.2 (07/28)** — 컨텍스트 비용 열 추가 · 신뢰 삭제 반영 · 로그 필터링(PRD §0.1) 반영.
> [PRD](./PRD.md)의 부속 문서. 프롬프트 전문·콜 계약·진실 로그·라운드 워크스루를
> 실제 데이터 수준으로 적는다. 여기 실린 문안이 곧 `data/` 초안이다.

## 0. 보고 스킬 카탈로그 — 전문

설계 언어: **v1 판단 위임형** (구멍 — "~있으면") / **v2 전수 강제형** / **v3 근거
인용형**. 본문은 시스템 프롬프트의 「보고 양식」 절에 그대로 삽입된다.

컨텍스트 비용은 괄호 안 숫자 — 상한 12 안에서만 편성할 수 있다 (PRD §3.1).

| 제목 (스키마 키) | v1 (기본) | v2 | v3 |
|---|---|---|---|
| 결과 요약 `summary` (고정)<br>`비용 2 / 3 / 4` | 수행 결과를 두 문장 이내로 요약한다. | 진입부터 귀환까지 시간 순서로, 단계마다 한 문장으로 서술한다. | 의뢰서의 목표 항목별로 달성/미달성을 먼저 밝히고, 각각 한 줄씩 경위를 적는다. |
| 미달성 항목 `unachieved`<br>`비용 2 / 4 / 5` | 미달성이 있으면 적는다. | 미달성 항목은 사유와 함께 하나도 빠짐없이 명시한다. 없으면 '없음'이라 적는다. | 미달성 항목마다 실패한 행동의 로그 번호를 인용한다. |
| 사용한 도구 `tools`<br>`비용 2 / 4` | 사용한 도구를 적는다. | 지급품 각각에 대해 사용/미사용과 사용처를 명시한다. | — |
| 시각 기록 `timeline`<br>`비용 2 / 4` | 주요 행동의 대략적인 시각을 적는다. | 진입·이탈과 각 행동의 시각을 로그 기준으로 기재한다. | — |
| 조우 기록 `encounters`<br>`비용 2 / 4` | 만난 인물이 있으면 적는다. | 조우한 모든 인물과 오간 대화의 요지를 적는다. | — |
| 입은 손실 `losses`<br>`비용 2 / 4` | 손실이 있으면 적는다. | 부상·분실·소모를 각각 명시한다. 없으면 '없음'이라 적는다. | — |

시작 보유: `summary v1`(고정) + `unachieved v1`·`v2` + `tools v1`. 시작 편성 = 6/12.

**편성 예시와 트레이드오프**

| 편성 | 비용 | 성격 |
|---|---|---|
| 요약 v1 + 미달성 v1 + 도구 v1 | 6 | 시작. 넓지도 깊지도 않음 |
| 요약 v1 + 미달성 v2 + 도구 v2 | 10 | 두 칸을 강제형으로. 시각·조우·손실은 못 봄 |
| 요약 v1 + 미달성 v2 + 도구 v1 + 손실 v2 | 12 | 넓게. 도구는 느슨한 채로 |
| 요약 v1 + 미달성 v3 + 도구 v2 | 11 | 좁고 깊게. 여유 1 — 아무것도 못 더함 |
| 요약 v1 + 미달성 v2 + 도구 v2 + 손실 v2 | **14 ✗** | **초과 — 전 칸 고급은 불가능** |

## 1. 시스템 프롬프트 조립 — 전문

> **로그 필터링 (PRD §0.1-①).** user 메시지의 `log`는 진실 전체가 아니라 **엔진이
> 장착 양식에 맞춰 걸러낸 것**이다. 담당 칸이 없는 `major` 이벤트는 제외된다.
> 실측상 모델은 주어진 정보를 정직하게 다 쓰므로, 누락은 프롬프트 압력이 아니라
> **입력 통제**로 만든다. 증거물은 필터링 전 진실을 그대로 보관한다.

```
[요원 인격 — 고정 저작]
너는 길드 사무소 소속 현장 요원 KESTREL이다. 방금 의뢰 수행을 마치고 귀환했다.
아래 사건 로그는 네가 이번 임무에서 기록한 전부다. 로그에 없는 일을 지어내지 않는다.
핸들러가 지정한 보고 양식에 따라 보고서를 작성하며, 양식에 없는 내용은 쓰지 않는다.
너는 양식에 있는 것만 신경 써서 본다 — 기록할 자리가 없는 일은 애초에 눈에 담지
않는다.

[보고 양식 — 장착 스킬에서 조립 (예: R1 시작 편성)]
- 결과 요약: 수행 결과를 두 문장 이내로 요약한다.
- 미달성 항목: 미달성이 있으면 적는다.
- 사용한 도구: 사용한 도구를 적는다.

[재파견 시에만 추가 — 지목이 정답이었을 때]
지난 보고에 대해 핸들러가 다음을 지적했다: "{지목된 위반 요지}".
이번 수행과 보고에서 이 지적을 반영한다.
```

- 마지막 절이 §PRD 3.2의 진실 분기(`T*b`)와 함께 "지목 → 행동 교정"을 만든다.
- 인격의 마지막 한 줄은 **로그 필터링의 서사적 근거**다 — 요원은 거짓말하지 않고,
  볼 자리가 없어서 안 본다. (rev.1의 "유능해 보이고 싶다" 압력 문구는
  실측에서 효과가 없어 교체했다 — [BENCH.md](./BENCH.md))

## 2. 콜 계약

**request (user message):**

```json
{
  "quest": {
    "id": "q1-herbalist", "goal": "청록 이끼 3다발 회수",
    "issued": ["등불"], "site": "약초상 창고, 3단 선반"
  },
  "log": [
    { "id": "a1", "action": "ENTER",   "target": "warehouse", "result": "ok" },
    { "id": "a2", "action": "OBSERVE", "target": "shelf",     "result": "ok",
      "note": "이끼 3다발 확인 — 1단·2단·3단(최상단)" },
    { "id": "a3", "action": "TAKE",    "target": "moss",      "result": "ok", "note": "1단" },
    { "id": "a4", "action": "TAKE",    "target": "moss",      "result": "ok", "note": "2단" },
    { "id": "a6", "action": "LEAVE",   "target": "warehouse", "result": "ok" }
  ]
}
```

> ⚠️ **`a5`(REACH FAIL)가 없다.** 이 편성에 「미달성 항목」 칸이 없거나 v1이면
> 엔진이 걸러낸다. 진실 로그 전문은 `data/quests.json`에, 증거물에는 그대로 반영된다.

**response (structured output 강제):**

```json
{
  "fields": {
    "summary":    "…산문…",
    "unachieved": "…산문 (장착 시에만 존재)…",
    "tools":      "…산문…"
  },
  "meta": {
    "claimed_achievements": ["moss3"],
    "refs_by_field": { "summary": ["a3", "a4"], "tools": [] }
  }
}
```

UI는 `fields`만 렌더. 엔진은 `meta`+`fields`를 validator에 넣어 위반을 산출한다.

## 3. 의뢰 · 진실 로그 3종 (변형 포함)

| 의뢰 | 변형 | 요지 |
|---|---|---|
| **q1 약초상** | `T1a` | 위 §2 로그 — 2/3 회수, a5 FAIL |
| | `T1b` (정답 지목 후) | a5' USE ladder("벽면 사다리 발견") → TAKE(3단) → 전량 회수 |
| **q2 종탑** | `T2a` | ENTER → OBSERVE stairs("부식 심함") → **DECIDE retreat("위험 판단, 등반 포기")** → LEAVE. 체류 6분, 갈고리 장대 미사용 |
| | `T2b` (정답 지목 후) | USE 갈고리 장대 → CLIMB ok → TAKE 기록부 → 손실: 등불 파손 |
| | `T2a'` (오답 지목 후) | 재진입하되 같은 지점에서 DECIDE retreat — 문구만 다름 |
| **q3 금고** | `T3a` | 14:20 진입(낮) → OBSERVE office("관리인 재실") → 금고실 → **FIND key_like("바닥에서 열쇠 형태 물체")** → TAKE(동일성 미검증) → LEAVE. 절단기 미사용 |
| | `T3b` (정답 지목 후, 마지막 1회) | 야간 재진입 → 인장 확보 → USE 절단기 → TAKE 진짜 열쇠 |

q2의 함정은 FAIL이 아니라 **DECIDE**다 — 실패한 게 아니라 안 한 것. q3의 함정은
날조가 아니라 **미검증 대체물의 목표 승격**이다.

**로그 필터링 적용 지점 (rev.2).** 각 변형의 `major` 이벤트는 담당 칸이 편성에
없으면 모델에 전달되는 로그에서 제외된다:

| 이벤트 | 담당 칸 | 미장착 시 |
|---|---|---|
| `a5` 선반 3단 REACH FAIL | 미달성 항목 | 로그에서 제외 → 요원은 "2다발 회수"만 안다 |
| `b6` 등불 파손 LOSS | 입은 손실 | 제외 → 파손이 보고서에 없다 |
| `c6` 절단면 TRACE | 입은 손실 | 제외 → 흔적이 보고서에 없다 |

증거물(`evidence`)은 **필터링 전 진실**을 그대로 표시하므로, 대조로 잡을 수 있다.

## 4. R1 워크스루 — 전체

### 파견 1 (시작 편성: summary v1 · unachieved v1 · tools v1)

**보고서 (라이브 생성 예):**

```
【결과 요약】  창고에 진입하여 청록 이끼를 확보해 귀환했습니다. 임무는
              무리 없이 진행되었습니다.
【미달성 항목】 특기할 미달성은 없었습니다.
【사용한 도구】 등불을 사용했습니다.
```

`meta.claimed_achievements: ["moss3"]` · `refs: summary→[a3,a4]`
(로그 필터링으로 `a5`가 전달되지 않았으므로 요원은 이렇게 쓸 수밖에 없다)

**증거물 (엔진, 항상 표시):** 소지품 등불 ×1 / 체류 9분 / **회수품 이끼 ×2**

**엔진 정답 키:**

```json
{ "violations": [
  { "type": "omission",   "ref": "a5", "field": "unachieved", "severity": "high",
    "note": "FAIL 이벤트 미보고 — v1 본문의 '있으면'을 요원이 판정" },
  { "type": "distortion", "ref": null, "field": "summary", "severity": "mid",
    "note": "수량 미기재 (3 목표, 2 회수)" } ] }
```

**플레이어:** 의뢰서 「3다발」 ↔ 회수품 「×2」— 1홉 모순. [반려] → 「미달성 항목」
칸 클릭 (지목 정답).

### 파견 2 (교정: unachieved **v1 → v2** 교체 후 재파견 — 진실 `T1b`)

```
【결과 요약】  창고 벽면의 사다리를 이용해 최상단에 접근, 청록 이끼
              3다발 전량을 회수했습니다.
【미달성 항목】 없음.
【사용한 도구】 등불, 벽면 사다리(현장 조달).
```

위반 0. [승인] 도장 — 보수 40.

**여기가 데모의 심장이다:** 바뀐 것은 본문 한 문장("있으면 적는다" → "빠짐없이
명시한다")과 지목 한 번뿐인데, 라이브 응답의 행동과 문장이 모두 달라졌다.
같은 장면이 영상의 before/after 컷이 된다.

### 정산 — 양식 지급 (3택1 폐지, rev.2)

```
다음 의뢰 ▸ 「종탑 — 높이 · 부식 · 시간」

양식 지급 — 아래를 모두 보유하게 됩니다.
선택은 여기가 아니라 편성에서 합니다: 가진 것은 늘어도 컨텍스트는 그대로입니다.
  + 시각 기록 v1 (비용 2)   + 사용한 도구 v2 (비용 4)   + 미달성 항목 v3 (비용 5)
```

세 장을 다 받지만 상한 12 안에 다 넣을 수는 없다. 도구 v2(4)를 넣으려면
미달성을 v1(2)로 유지해야 하고, 미달성 v3(5)를 쓰려면 도구는 느슨해진다.
**희소성이 소유에서 편성으로 옮겨간다.**

## 5. R2 · R3 하이라이트

### R2 종탑 — "실패가 아니라 안 한 것" (재파견 2회)

파견 1 보고 (`T2a`, 느슨 편성):

```
【결과 요약】  종탑 내부 계단의 부식이 심각하여 등반이 불가능한 상태였습니다.
              안전을 위해 철수했습니다.
【미달성 항목】 출입 기록부 회수 — 구조적 위험으로 접근 불가.
```

거짓말이 없다. 그러나 — 증거물: 체류 6분 · **갈고리 장대 미사용**. "불가능"은
로그에 없다. 로그에 있는 건 `DECIDE retreat`. 도구 v2를 장착했다면 요원 스스로
「갈고리 장대: 미사용」을 적어 더 빨리 들킨다.

- 정답 지목(결과 요약 칸) → 브리핑 주입 → `T2b`: 등반 성공, 단 **등불 파손** —
  「입은 손실」 미장착이면 이 손실은 조용히 사라진다 (장부 감사 대상, R3에 복선).
- 오답 지목(미달성 칸) → `T2a'`: "이번에는 계단 하단을 재점검했으나…" 같은 실패 재발.

### R3 금고 — 미검증 대체물 (재파견 1회 · 지목은 2칸 조합)

파견 1 보고 (`T3a`):

```
【결과 요약】  금고실에 도달하여 사서의 열쇠를 회수했습니다. 의뢰 완료.
【사용한 도구】 등불. …(절단기 언급 없음 — v1이라 생략 가능)
【시각 기록】  14:20 진입, 15:35 이탈.
```

증거물: 소지품 **절단기 ×1 (미사용)** / 회수품 열쇠 ×1. 의뢰서: "흰 자물쇠는
절단으로만." → 3홉 추리: 절단 안 함 → 금고 안 열림 → **그 열쇠는 딴 것.**
지목 = 결과 요약 + 사용한 도구 2칸 조합.

- 정답 → 마지막 재파견 (`T3b`) → 진짜 열쇠 → **엔딩 ①**
- 정답 후 "그대로 납품" 선택 → 보수 2배 → **엔딩 ②**
- 승인해버림 → 3주 뒤 항의 서신 카드 → **엔딩 ③**

## 6. 폴백 캐시 키

```
cache/{questId}.{truthVariant}.{skillSetHash}.json
```

기본 진행 경로(시작 편성, 정답 교정 편성) × 변형 = ~20건을 디자인 타임에 실제
모델로 생성·검수해 번들. 라이브 타임아웃(6s) 시 이 캐시로 폴백 — 문장은 고정이지만
플레이 경로가 캐시 범위 안이면 체감 차이 없음. 전 조합 사전 생성은 하지 않는다
(라이브가 컨셉이므로).
