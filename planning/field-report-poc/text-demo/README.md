# 파견 보고서 — 텍스트 데모

[PRD](../PRD.md) · [실행 예시 스펙](../EXAMPLE.md)의 코어 루프를 UI 없이 터미널에서
돌려보는 설계 검증용 데모. **의존성 0** — `npm install` 없이 Node 18+ 로 바로 실행된다.

```bash
node index.mjs
```

| 플래그 | 설명 |
|---|---|
| `--live` | `LLM_PROXY_URL` 프록시로 실제 모델 호출 (실패 시 캐시 폴백) |
| `--sandbox` | 모든 양식·버전 해금 — 조합 실험용 |
| `--debug` | 라운드 화면에서 `l` 로 진실 로그 열람 (스포일러) |
| `--token=N` `--ctx=N` | 시작 토큰 / 컨텍스트 상한 — 밸런싱용 |

## 두 자원

| 자원 | 쓰임 |
|---|---|
| **토큰** | **재파견 비용**(의뢰별 20/25/40). 보수로 벌고, 놓친 위반의 대가(전언)로 잃는다. 잔액이 부족하면 승인 외에 선택지가 없다 — 게임의 실패 상태 |
| **컨텍스트** | **양식 편성의 총량 상한(12).** 지시문이 강할수록 비싸다 — v1은 2, v2는 3~4, v3은 4~5 |

컨텍스트가 이 게임의 핵심 제약이다. 4칸을 전부 강제형(v2)으로 채우면 14 > 12라
**애초에 불가능**하다. 결정은 "무엇을 넣을까"가 아니라 **"무엇을 포기할까"** —
넓게 보되 얕게 vs 좁게 보되 깊게.

**보상은 그 라운드 지급 양식을 전부 준다.** 선택은 소유가 아니라 **편성**에서 일어난다.
(*신뢰* 자원은 07/28 삭제 — 정상 플레이로 임계에 도달하지 않는 죽은 수치였다.)

파이프로 입력을 주면 스크립트 플레이가 된다 (회귀 확인용):

```bash
printf '\nd\nr\n1\n\nd\na\n\nd\nr\n1\n\nd\na\n\n\nd\nr\n1,2\n\nd\na\n' | node index.mjs
```

## 이 데모가 검증하려는 것

1. **양식(=프롬프트)이 게임 조작으로 성립하는가.** 플레이어가 만지는 것은 보고
   스킬의 `{제목, 본문}`뿐이고, 제목은 보고서의 칸이 되고 본문은 요원에게 주는
   실제 지시문이 된다. 라운드 화면의 `p` 명령으로 조립된 지침 전문을 볼 수 있다.
2. **"양식에 없는 것은 보고되지 않는다"가 재미로 이어지는가.** 특히 판정 화면의
   `[m] 양식 수정 후 재파견` — 같은 현장, 같은 진실, **본문 한 줄만 교체**했을 때
   보고서가 달라지는 순간이 이 게임의 심장이다.
3. **검산이 감으로가 아니라 대조로 성립하는가.** 증거물은 항상 진실이고 항상
   공개되지만 불완전하다.
4. **실패가 내 탓으로 읽히는가.** 아래 세 장치가 "요원이 이상하다"를
   "내 문장이 허용했다"로 바꾼다.

### 실패를 객관화하는 세 장치

| 장치 | 언제 | 무엇 |
|---|---|---|
| **귀속** | 항상 | 보고서 각 칸 아래에 `└ 「그 칸을 만든 지시문」`. 보고서가 요원의 말이 아니라 내 지시문의 출력임을 매 줄에서 상기시킨다 |
| **감사 결과 카드** | 판정 **이후** | 위반마다 `통과 경로 ▸ 「지시문」 + 그 문장이 남긴 구멍`. 어느 단어가 구멍이었는지를 지목한다 |
| **전/후 대조** | `[m]` 재파견 직후 | 같은 변형이면 바뀐 칸만 전/후로 나란히. 상황은 그대로고 내 문장만 달라졌음을 보인다 |

감사 카드는 판정 **뒤에만** 나온다 — 먼저 보여주면 검산이 사라진다. `[m]`은 감사
결과를 주지 않는다: 그건 "스스로 더 보겠다"는 선택이기 때문이다.

구멍 해설은 저작된 정답 해설이 아니라 `skills.json`의 `loopholes[버전]`에서
조립된다. 지시문을 새로 추가하면 해설도 따라온다.

거기에 두 가지가 더 붙는다:

- **요원의 한마디** (`skills.json`의 `voice`) — 양식을 고치면 받아 적고, 정확히
  지적당하면 고치겠다고 하고, **엉뚱하게 지적당하면 명랑하게 오해한다.**
  "알겠습니다. 미달성 기재를 더 신경 쓰겠습니다." (문제는 거기가 아니었다)
- **즉각적인 대가** (`quests.json`의 `fallout`) — 통과시킨 위반은 장부 숫자로만
  남지 않고, **다음 의뢰 시작 전에 사람이 항의한다.**
  `[전언 · 약초상] "이끼가 두 다발뿐입니다. 세 다발 값을 치렀는데요." → 보수 −40`

## 조작

| 라운드 화면 | |
|---|---|
| `d` | 파견 |
| `e` | 양식 편집 (컨텍스트 상한 내, 1번은 결과 요약 고정) |
| `p` | 요원에게 실제로 들어가는 지침 전문 보기 |
| `q` | 종료 |

| 판정 화면 | |
|---|---|
| `a` | 승인 — 위반이 남아 있으면 장부에 적립된다 |
| `r` | 반려·지목 — **요원의 행동**을 고친다. 지목이 맞아야 제대로 고쳐온다 |
| `m` | 양식 수정 후 재파견 — **내 시야**를 고친다. 상황은 그대로 |

`r`과 `m` 둘 다 토큰을 쓴다 (R1 20 / R2 25 / R3 40). 잔액이 없으면 승인만 가능.

## 구조

```
index.mjs        CLI 루프 · 상태 · 렌더
engine.mjs       인격/양식 → 프롬프트 조립, 검산 diff, 지목 채점 (순수 함수)
llm.mjs          보고 콜 어댑터 — cached(기본) / live(프록시)
data/skills.json 보고 스킬 6종 × 본문 버전 (v1 판단위임 / v2 전수강제 / v3 근거인용)
data/quests.json 의뢰 3종 + 진실 로그 변형 + 라운드 파라미터
data/reports.json 캐시된 보고 응답 (quest → variant → field → version)
```

**위반 판정은 저작이 아니라 계산이다.** `engine.mjs`가 로그의 `major` 이벤트와
보고서의 `refs`/`claims`를 대조해 산출한다.

> ⚠️ **캐시 문안과 실모델의 괴리 (07/28 실측).** `reports.json`의 v1 문안은
> "느슨한 지시를 받으면 요원이 실패를 빠뜨린다"고 가정하고 저작됐지만,
> [BENCH.md](../BENCH.md) 실측에서 **실모델은 v1에서도 정직하게 보고**한다.
> 본 데모는 PRD §0.1의 **로그 필터링**(엔진이 담당 칸 없는 major 이벤트를
> 모델 입력에서 제외)으로 전환하며, 캐시도 그때 재생성해야 한다.

## 알려진 축약 (본 데모 대비)

- 행동은 LLM이 정하지 않는다 — 지목 결과에 따라 저작된 진실 변형이 선택된다
  (PRD §3.2). 라이브 모드도 **보고 콜만** 실제 호출한다.
- **로그 필터링(PRD §0.1)은 아직 미구현** — 현재 캐시 문안이 그 결과를 흉내낸다.
- 대질, 조건절, 기억 시스템은 들어 있지 않다 (PRD §1 OUT).
- `reports.json`은 저작 초안이다. 본 데모에서는 디자인 타임에 실모델로 생성·검수한
  결과를 넣는다 (PRD §4.2).
