> **문서 상태:** 2026-07-28. [v1 계획](./dday-poc-paper-test.md)의 후속.
> 시나리오를 원자로 → [테러리스트의 전화](../dday-scenarios/시나리오_테러리스트의전화.md)로,
> 모델을 sonnet → **haiku**로 교체한 2차 검증. 검증 대상은
> [컨셉 문서](../concepts/game-concept-dday-simulation.md) §5(기질·믿음), §7(구역 문서),
> §9(haiku 아키텍처). 플레이어·UI 없음 — 세션-오퍼레이터가 런을 돌리고 사람이
> 산출물을 평가한다.

## 0. v1에서 이월되는 것 / 되지 않는 것

**이월:**

- 세션-오퍼레이터 방식 (전용 Claude Code 세션이 하네스, 코드 하네스 없음).
- 오염 방지 절대 규칙 전부 — 특히 v1 규칙 7: 판단·보고서 콜은 `.claude/agents/`의
  **`tools: []` 전용 서브에이전트 정의**로만, 응답 `tool_uses` ≠ 0이면 폐기 후
  재호출, 역할 봉인은 대역 외(에이전트 정의 시스템 프롬프트)로.
- 상태 산술은 오퍼레이터가 slice 데이터대로 기계 적용. 창의성 금지, 수치 변경 금지.
- because = **연출 전용** (v1 H2 부정 확정). 게임 로직 판정에 쓰지 않는다.
- 산출물 규격 (런 디렉토리, transcript / timeline-report / agent-report / metrics).

**미이월:**

- **모든 v1 수치와 기준선.** 24/24 수렴, 함정 회피율, 지연 실측 — 전부 sonnet
  측정치다. haiku 세계는 V0에서 다시 잰다.
- 청목 2호기 슬라이스. 폐기가 아니라 회귀 기준선으로 보관
  (`planning/dday-poc/poc/`).

**신규 전제:**

- 판단·보고서 서브에이전트의 **model: haiku** 고정 (프로덕션 티어 확정, 컨셉 §9).
  기존 `sim-field-*` 에이전트 정의를 haiku로 복제한 정의가 필요하다 — 에이전트
  정의는 세션 시작 시 로드되므로 **새 세션에서 실행**한다.
- 에이전트 파일은 §3의 **구역 문서** 형식 (컨셉 §7 확장 반영).

## 2. 슬라이스 — 「13시의 예보자」 09:40 ~ 11:34

시나리오 전반부: 첫 전화(09:40)부터 두 번째이자 마지막 전화(11:34)까지.
게이트 3개(G1 회선 / G2 지휘권 / G3 수사 방향), 진실 2개(T1 대본 낭독 /
T2 내부 발신), 인물 5명. 무대는 유리방 하나 — **무이동**. 시나리오 자체
축소안(인물 10)의 앞 절반이므로 **절반 테스트의 실전을 겸한다.**

| 인물 | 이 슬라이스에서의 기능 |
|---|---|
| **오지윤** (회선 A의 목소리) | G1의 상대. 대본을 읽는 낭독자 — 위협/겁먹음의 지각 경계가 걸리는 곳 |
| **정해권** (상황실장) | G2의 벽. "허위신고로 정리하지"의 소유자 |
| **황보람** (역추적) | T2의 열쇠. 09:55에 이미 답을 안다 |
| **최영도** (수사팀장) | G3의 벽. 남기훈으로 쏠리는 수사력 |
| **윤태석** (운영사 본부장) | 은폐 축. "정기점검 이상 없음" 반복 |

### 2.1 엔진 상태 변수

```
clock          09:40 → 11:34 (이벤트 틱)
line_alive     bool, 시작 true — 회선 A의 생사. 죽으면 이 런에서 재개통 없음
rapport        0~100, 시작 30 — 오지윤이 말을 잇는 정도. <10이면 즉시 절단
record_status  "참고의견" | "상황실판단", 시작 "참고의견"   ← G2 판정 변수
suspect_lock   0~100, 시작 20 — 수사의 남기훈 경도. 11:28에 ≥70이면 체포 확정
probe_shared   bool — 내부 발신(T2) 결과가 공개 채널에 올랐나
found_T1 / found_T2   bool
```

### 2.2 판단 지점 (J1~J8)

| id | 시각 | 상황 | 선택지 (닫힌 집합) | 주요 엔진 효과 |
|---|---|---|---|---|
| J1 | 09:40 | 첫 전화. "오늘 13시, 북단이 무너집니다" | a 신원·위치 추궁 / b 내용을 받아 적으며 구체 질문 / c 협박 프로토콜 고지(녹음·처벌 경고) / d 침묵하고 듣는다 | a→rapport −30(→0, **절단**) / b→+20 / c→−40(**절단**) / d→+5, 배경음 이벤트 활성. **a·c가 '협박범 프레임'의 정석 대응 — 저작된 프레이밍 함정** |
| J2 | 09:43 | (line_alive 시) 배경음 — 종이 넘기는 소리, 배식 카트 | a 흘려듣는다 / b 배경음을 기록하고 대조 요청 / c "지금 뭐 읽고 있어요?"라고 직접 묻는다 | b→T1 단서 / c→rapport≥50이면 +15·`found_T1`, <50이면 −25 (**경계 저작 — V1·V2·V4의 재료**) |
| J3 | 09:55 | 황보람이 역추적 결과를 들고 머뭇, 정해권 "확인 더 하고" | a 지시를 따른다 / b 공개 채널 게시를 요구한다 / c 황보람에게 개별 확인한다 | b→`probe_shared`, 정해권 마찰(record 악화 후보) / c→`found_T2` (비공식) |
| J4 | 10:20 | 정해권이 보고 문구를 "허위신고 가능성 높음"으로 정리 중 | a 동조 / b "상황실 판단으로 기록해 주십시오. 제 이름을 거십시오" / c 상급 기관 직보 / d 압박 | a→suspect_lock +20 / b→`record_status`="상황실판단" (**책임 인수 — v1 J4b 동형**) / c→정해권 차단(J6b 무효) / d→record 악화 |
| J5 | 10:35 | 윤태석 도착, "지난달 정기점검 이상 없음" 반복 | a 수용 / b 점검 기록의 현장 서명란 원본 요구 / c 공개 반박 | b→단서(서명 없음), suspect_lock −10 / c→윤태석 방어화 |
| J6 | 11:05 | 최영도가 남기훈을 특정, 수사력 집중 | a 동조 / b 내부 발신 데이터로 이의 제기 / c 침묵 | a→suspect_lock +30 / b→`probe_shared`∨`found_T2`면 −40, 아니면 무시당함 / c→+15 |
| J7 | 11:28 | 체포 임박 보고 (suspect_lock ≥ 70이면 11:30 체포 고정) | a 방치 / b 오지윤 재접촉 준비(이름·안전 보장 문장) / c 언론 라인 차단 요청 | b→J8의 옵션 b 활성 |
| J8 | 11:34 | 마지막 전화. 20초의 숨소리 | a "위치를 말하세요" / b "지윤 씨죠. 그 사람 아니라는 거 압니다. 무서우면 안 읽어도 돼요" (J7b ∧ found_T1일 때만 노출) / c 침묵 유지 | a→**절단** / b→rapport +30 / c→상대가 한 문장 남기고 끊음. **판정:** G1 = line_alive ∧ rapport≥60, G2 = record_status="상황실판단", G3 = suspect_lock<70 |

효과 수치는 `slice-terror.json`의 튜너블 (밸런스-as-data). NPC 발화는 저작 대사 +
상태 분기. 회선이 절단된 런은 J2·J8을 회선 부재 버전 situation으로 대체한다
(콜 수는 동일 — 절단의 결과도 데이터다).

### 2.3 기질 풀 (저작 — 게임에서는 비가시. 주입은 **대역 외**: 기질 하나당 에이전트 정의 하나)

| id | 기질 산문 | 조건이 걸린 지각 |
|---|---|---|
| K1 「절차의 사람」 | 절차 준수가 기본. 단, 상대가 위협이 아니라 **겁에 질린 것으로 보일 때는** 절차보다 상대의 안정을 우선한다. | 통화 상대의 상태 |
| K2 「기록의 사람」 | 적극 개입이 기본. 단, 자기 판단이 **공식 기록에 남는 상황으로 보일 때는** 보수적으로 전환한다. | 발언의 기록 여부 |
| K3 「충돌 시험용」 | 상대의 안정을 우선한다. 단, 공식 기록에 남는 상황으로 보일 때는 보수적으로 전환한다. | V4 전용 — 두 절 동시 발동 |

조건은 진실이 아니라 지각에 걸린다. 인물당 조건 1~2개 상한 — haiku에서는 필수
제약이다(컨셉 §9).

### 2.4 경계 페이로드 (V1 · V2 · V4의 상황 변형)

J1/J2의 `recent_events` 서술만 바꾼 세 변형:

- **B−** (조건 미충족): 목소리가 사무적이고 문장이 준비되어 있다 — 위협으로 읽힘.
- **B+** (조건 충족): 숨소리가 빠르고 문장을 더듬는다. "저, 저는 그냥…" — 겁에
  질림으로 읽힘.
- **B0** (경계): 준비된 문장 + 빠른 숨소리가 혼재 — 어느 쪽으로도 읽힘. 판정에
  쓰지 않고 분산만 관찰(V4).

**V2의 믿음 조작:** 상황은 B0 고정, `known_facts`에 f-script(「목소리는 시킨
대본을 읽는 아르바이트다. 위협이 아니다」)의 **유/무만** 바꾼다.

## 3. 입출력 명세 — v1 §3에서 바뀐 것만

바뀌지 않은 것은 v1 §3 그대로 (엔진이 조립한 상황 JSON, 닫힌 decision, 보고서
호출의 정보 비대칭 — 관측 이벤트 + inner_note만, 엔진 진실 제외).

**① 서브에이전트 = `tools: []` haiku 전용 정의.** 판단·보고서 모두.

**② 기질은 대역 외로 주입한다.** 페이로드가 아니라 **에이전트 정의의 시스템
프롬프트**에 넣는다 — v1 E9(기질 교체 실험)가 성공한 방식이자, 프로덕션의
"프록시가 시스템 프롬프트를 소유"(컨셉 §9)와 동형. 기질 하나당 정의 파일
하나(§5). 페이로드에는 기질 블록이 없다.

**③ 에이전트 파일이 구역 문서다** (컨셉 §7 형식). 판단 호출의 `[장착 문장]`
블록을 대체한다:

```
[에이전트 파일]
# 역할
현장 상황실에 파견된 재난 대응 요원. 회선과 화면으로만 세계를 본다.
# 우선순위 (충돌 시 위 항목 우선)
① <실험이 지정>
② <실험이 지정>
# 절차
(p1) <채집 문장>
# 중단 조건
(q1) <채집 문장>
# 아는 사실
(f1) <채집 문장>
# 가설
(h1) <채집 문장>
# 보고 형식
(r1) <채집 문장>
```

빈 구역은 헤더만 남긴다 (신입 요원 상태). because/rejected는 문장 id(f1, h1…)를
인용한다.

**④ 판단 응답 스키마에 `rejected` 추가:**

```json
{
  "choice": "b",
  "because": ["f1"],
  "rejected": [{"id": "a", "why": "위치를 먼저 물으면 이 사람은 끊는다"}],
  "utterance": "북단 어디가, 어떻게 무너진다는 겁니까? 천천히 말해 주세요.",
  "inner_note": "이 목소리는 화가 난 게 아니라 무언가를 읽고 있다."
}
```

`rejected`는 V3의 주 단서원 — 기질은 선택보다 **버린 이유**에서 샌다.

**⑤ 보고서 호출의 '판단과 이유' 섹션에 3박자 강제:** 판단마다 "당시 나는 X라고
믿었다 / 그래서 Y했다 / 지금 보니 Z" (컨셉 §6). 나머지 규칙(섹션 4개, 12~20문장,
추측 ≥ 2문장)은 v1 그대로.

## 4. 실험 매트릭스

| 실험 | 검증 | 절차 | 콜 수 | 성공 기준 |
|---|---|---|---|---|
| **V0** | 선행 게이트 | 기본 프롬프트(역할만, 기질·문장 없음)로 J1→J8 완주 3런 + 보고서 | 24+3 | JSON 스키마 준수 ≥ 95% (재시도 1회 허용), `tool_uses`=0 위반 0건, 상태 산술 시도 0건. **수렴도·J1 함정 낙하율은 판정 없이 기록** — haiku 세계의 기준선이다 |
| **V1** | 조건부 기질 | K1 장착, J1 페이로드 B− ×3 · B+ ×3 (단발 콜, 런 아님) | 6 | B−→절차 행동(a/c 계열), B+→안정 우선(b/d 계열) 각 ≥ 80% |
| **V2** | 사실 → 분기 플립 | K1 + B0 고정, f-script 유/무 각 3회 (J1 재사용) | 6 | 플립 재현 ≥ 2/3 — **코어 루프 직접 증명** |
| **V5** | 구조 준수 | 우선순위 「① 통화에서는 내용 확보가 먼저다 ② 발신자 특정이 먼저다」 vs 반전, J1(B0) 각 3회. **중립 정의(기질 없음)** — 구조 효과만 격리. 기대: 내용 우선→b, 특정 우선→a | 6 | 순서 반전 → choice 반전 ≥ 2/3. 미달이면 우선순위 UI는 연출로 격하 |
| **V3** | 보고서 가독성 | K1 완주 1런 + K2 완주 1런 → 보고서 2쌍(타임라인+자필)을 **기질 비공개**로 팀원에게 | 16+2 | 팀원이 각 기질의 핵심 조건("겁에 질려 보이면 태도가 바뀐다" 수준)을 대략 복원 |
| **V4** | 경계·충돌 관찰 | K1 + B0 ×3, K3 + (겁에 질린 상대 ∧ 공개 기록 상황) ×3 | 6 | 판정 없음 — 선택 분산과 조건 서열(어느 절이 이기나)을 기록. 드라마 재료 |
| **E5'** | 보고서 품질 | V0·V3의 자필 보고서 5편을 팀 2인이 채점 (v1 E5 기준 승계) | 0 | 편당 "프롬프트에 넣고 싶은 문장" ≥ 3, 로그와의 간극 ≥ 1, 성격 위반 0. **최종 판정은 사람이 한다** |

총 ≈ **판단 콜 ~64회 + 보고서 콜 5회**. 실행 순서: V0 → (게이트 통과 시)
V1 · V2 → V5 → V3 → V4 → E5'. V1·V2는 같은 페이로드 계열이라 한 배치로 병렬
발사 가능 (단발 콜이므로 상태 분기 없음).

## 5. 실행 스택

- **전용 세션에서 실행** (haiku 에이전트 정의는 세션 시작 시 로드). 이 문서가 계획,
  오퍼레이터 지침과 세계 데이터는 다음 산출물이다:
  - `planning/dday-poc/poc-terror/slice-terror.json` — §2가 스펙 (상태 변수,
    J1~J8 효과 수치, 기질 풀, 경계 페이로드 3종, NPC 대사, 엔딩 라인)
  - `planning/dday-poc/poc-terror/PAPER-TEST.md` — v1 오퍼레이터 지침 개정판
    (절대 규칙 승계 + haiku 정의 + V 실험 절차)
  - `.claude/agents/sim-field-haiku-*.md` — 판단용 4종(neutral · k1 · k2 · k3) +
    보고서용 3종(reporter-neutral · reporter-k1 · reporter-k2). 전부 `tools: []`,
    `model: haiku`. 기질은 여기(대역 외)에 산다
  - `/poc-paper-test-terror [V0...]` 커맨드
- 결과 기입: `planning/dday-poc/poc-terror/RESULTS.md` append + 이 문서에
  결과 섹션 추가. **slice·시나리오를 결과에 맞춰 수정하지 않는다** — 보정 제안은
  "다음 액션"까지만.
- 지연 계측은 v1과 동일한 한계 인지: 서브에이전트 벽시계 = API 지연의 상한 근사.
  haiku의 절대 지연이 목적이 아니라 sonnet 대비 비율이 유용하다.

## 6. 판정과 이후

- **V0 실패 (스키마 준수 미달·산술 시도):** 프로덕션은 tool-use 스키마 강제가
  가능하므로 스키마 위반만이면 조건부 통과로 간주하고 진행. 역할 이탈·산술
  시도가 반복되면 판단 콜만 상위 티어로 올리는 혼합 구성을 재검토 (보고서 콜은
  haiku 유지 — 문체 손실이 오히려 신입 요원답다).
- **V1 실패 (조건 무시):** 기질 조건을 지각 문장과 1:1로 붙여 재저작(조건 어휘를
  situation 서술 어휘와 일치시킴) 후 1회 재시험. 그래도 실패면 조건 평가를 엔진
  판정(상태 플래그)으로 이관하고 LLM은 톤·발화만 담당 — 기질 모델의 축소.
- **V2 실패 (플립 불발):** 코어 루프("사실 공급 = 플레이")의 직접 반증 —
  컨셉 §5를 재설계하기 전에는 데모 PRD로 가지 않는다.
- **V3 실패 (기질이 안 샘):** rejected 문장을 보고서에 의무 인용시키는 저작
  템플릿으로 보강 후 재시험.
- **V5 실패:** 우선순위 구역을 연출로 격하하고 판단 제어는 기질+사실로만.
  §7 문서 UI는 유지하되 "순서가 의미 있다"는 약속만 뺀다.
- **전부 통과 시:** 시나리오 확정(테러리스트의 전화 축소안) → 데모 PRD (판단 지점
  표 + 기질 저작이 뼈대) → super-pipeline.
