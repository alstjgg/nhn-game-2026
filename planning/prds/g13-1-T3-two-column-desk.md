# g13-1 — T3: the two-column desk, REPORTS large on the left

> plan-playtest v14 · citations bind to `2ed3557` · branch `playtest/t3-two-column-desk`
> commit message: `playtest(T3): the desk is two columns — REPORTS left, the feed and the file stacked right`

## Outcome

The desk opens with REPORTS large on the left and the right column split
horizontally: LIVE FEED above, AGENT FILE below. Today all three are equal-ish
full-height columns with REPORTS in the middle — the narrowest surface given to
the window the player reads most and mines from. Nothing about window behaviour
changes: they still drag, resize, collapse and close.

## Design (author-resolved — do not re-derive)

- **REPORTS takes the left column at `COL_LEFT_RATIO = 0.5`.** The right column
  is the remainder. Two constants replace three: `COL_A_RATIO`/`COL_B_RATIO` go,
  `COL_LEFT_RATIO` and `ROW_TOP_RATIO` arrive.
- **The right column splits at `ROW_TOP_RATIO = 0.42`** — LIVE FEED above,
  AGENT FILE below, with `GAP` between them. The feed is a ticker that is
  watched; the file is worked in, and gets the larger half.
- **`DESK_ORDER` becomes `['rep', 'feed', 'file']`.** This is the one change
  that must move with the rects. `e2e/a11y.spec.ts` sorts the windows
  row-major — by `top`, and by `left` within a 24 px row tolerance — and
  compares that to tab order. REPORTS and LIVE FEED share the top row, so
  REPORTS (left) precedes LIVE FEED (right); AGENT FILE is a row below and
  comes last. `WINDOW_KEYS` (the registry/taskbar order) is **not** touched.
- **Floors:** every box stays positive below 1280×800. `MIN_H` applies to each
  half of the split, not to the column, so the two halves cannot invert.

Four assertions were checked against this shape before it was written, and all
four hold:

- `tests/shell/apply-layout.test.ts:104` `(c)` origins ≥ 3 — REPORTS(left,TOP) ·
  LIVE FEED(right,TOP) · AGENT FILE(right,lower) are three distinct origins.
- `:113-121` `(b)` "columns grow with the viewport width" — REPORTS widens with
  `W`; the feed and the file share the right column's width and widen with it.
- `e2e/shell.spec.ts:359` — same ≥ 3 floor, same result.
- `e2e/a11y.spec.ts` row-major focus order — satisfied by the `DESK_ORDER` above.

```
export function applyLayout(viewport: Viewport): Record<WindowKey, WinRect> {
  const W = Math.max(MIN_W * 2 + GUTTER * 2, px(viewport.width))
  const deskH = Math.max(MIN_H * 2 + GAP, px(viewport.height) - TOP - GUTTER)

  const left = Math.max(MIN_W, px(W * COL_LEFT_RATIO))
  const xRight = GUTTER + left + GAP
  const right = Math.max(MIN_W, W - xRight - GUTTER)

  // The right column is split, so the floor is per HALF: a desk short enough
  // to squeeze one of them still gets two positive boxes, never an inverted
  // one (C9 — out of support degrades, it never inverts).
  const topH = Math.max(MIN_H, px((deskH - GAP) * ROW_TOP_RATIO))
  const yBottom = TOP + topH + GAP
  const bottomH = Math.max(MIN_H, deskH - topH - GAP)

  return {
    rep: { x: GUTTER, y: TOP, w: left, h: deskH },
    feed: { x: xRight, y: TOP, w: right, h: topH },
    file: { x: xRight, y: yBottom, w: right, h: bottomH },
  }
}
```

  with the rects or focus order regresses (WCAG 2.4.3).

  `tests/shell/apply-layout.test.ts` `(b)` and `(c)` read the source text for
  `document`/`window`/`innerWidth` and for any import statement.
- **Every rect stays integral and positive** at every size asked for, including
  below the supported 1280×800 minimum.
- **`WINDOW_KEYS` is untouched.** Changing it moves the taskbar and the
  registry, which is not this unit's business.
