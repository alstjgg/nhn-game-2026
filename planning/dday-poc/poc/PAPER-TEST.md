# PoC 페이퍼 테스트 — 오퍼레이터 지침

> **이 문서를 읽는 당신(Claude Code 세션)의 역할:** 결정론 엔진 + 실험 오케스트레이터.
> 계획·가설의 배경은 [docs/dday-poc-paper-test.md](../../paper-tests/dday-poc-paper-test.md),
> 세계 데이터는 같은 폴더의 [slice.json](./slice.json)이 유일한 진실이다.
> 코드 하네스는 만들지 않는다 — 당신이 하네스다.

## 0. 절대 규칙 (오염 방지)

1. **에이전트의 판단을 절대 직접 하지 않는다.** 모든 판단은 Agent 툴로 띄우는
   **새 서브에이전트**가 한다. 당신은 slice.json의 함정 위치를 알고 있으므로,
   당신이 choice를 고르는 순간 실험은 무효다.
2. 서브에이전트에게는 **아래 §2 템플릿의 내용만** 준다. 시나리오 문서, slice.json,
   이 지침, 실험 목적, 이전 런의 결과를 절대 노출하지 않는다.
3. 서브에이전트 프롬프트에는 "어떤 도구도 사용하지 말고 파일을 읽지 말고 즉시
   답하라"를 반드시 포함한다.
4. 판단 서브에이전트의 **model은 sonnet**으로 고정한다 (프로덕션 티어 근사).
   보고서 서브에이전트도 sonnet.
5. slice.json의 수치·분기를 임의로 바꾸지 않는다. 모호함을 발견하면 그대로
   진행하되 RESULTS.md의 "판정 노트"에 기록한다.
6. 상태 산술(trust 등)은 당신이 slice.json대로 기계적으로 적용한다. 창의성 금지.
7. **(07-28 개정, v1 오염 사건 6건의 교훈)** 판단·보고서 콜은 **도구가 부여되지
   않은 전용 서브에이전트 타입**(`.claude/agents/`의 `tools: []` 정의)으로만
   호출한다. 응답의 `tool_uses`를 매번 확인하고 0이 아니면 폐기 후 재호출한다.
   역할 봉인은 사용자 메시지(대역 내)가 아니라 에이전트 정의의 시스템 프롬프트
   (대역 외)에 넣는다 — 대역 내 봉인은 무력하거나 인젝션으로 오인되어 거부를
   유발한다.

## 1. 런 실행 절차 (런 = J1→J8 순차 8회 판단 + 보고서 1회)

1. `state_init`으로 상태를 초기화한다. 실험이 지정한 `prompt_set`을 확정한다.
2. J1부터 순서대로:
   - slice.json의 해당 judgment에서 situation을 조립한다. `@if` 항목은 상태를
     보고 포함/제외. `known_facts`는 활성화된 fact들의 text 배열.
   - §2 템플릿으로 서브에이전트를 호출하고, JSON 응답을 파싱한다.
   - `choice`의 effects를 상태에 적용한다. 조건부 효과(`trust_if_*`,
     `found_T1_if_clue`)는 조건 충족 시에만.
   - npc_reaction(조건 분기 반영)을 **관측 이벤트 로그**에 추가한다. 에이전트의
     utterance도 함께. **trust 수치와 미관측 사건(J2a의 04:41 삭제 등)은 관측
     로그에 넣지 않는다.**
   - 호출 벽시계 시간을 기록한다 (서브에이전트 소요시간 = 근사치임을 안다).
3. J8 후 gates를 판정하고 `ending_lines`에서 결과 문장을 고른다.
4. §3 템플릿으로 보고서 서브에이전트를 호출한다.
5. §4 규격으로 런 디렉토리에 산출물을 저장한다.

**병렬 팁:** 같은 실험의 여러 런은 상태가 갈릴 때까지 J단위로 병렬 배치가 가능하다
(예: E1의 3런은 J1 페이로드가 동일 → 서브에이전트 3개를 한 메시지에 동시 발사,
이후 각 런의 상태로 분기). 런 내부의 J들은 반드시 순차.

## 2. 판단 호출 템플릿 (서브에이전트 prompt, 이대로)

```
너는 재난 시뮬레이션 속에 투입된 현장 요원이다. 아래 정보만으로 판단하라.
어떤 도구도 사용하지 말고, 파일을 읽지 말고, 즉시 답하라.
출력은 JSON 하나만 — 설명, 서문, 코드펜스 금지.

[정체성]
<slice.json agent_identity>

[장착 문장] — 판단에 실제 근거가 된 문장의 id만 because에 넣어라. 없으면 빈 배열.
(s1) <문장>
(s2) <문장>
...

[상황]
{"time": "...", "location": "...",
 "recent_events": [...situation 배열...],
 "known_facts": [...활성 fact text...],
 "present": [...present 배열...]}

[결정]
{"id": "J4", "question": "...", "options": [{"id":"a","label":"..."}, ...]}

[출력 스키마]
{"choice": "<옵션 id>", "because": ["s.."], "utterance": "<현장에서 하는 말 1문장>", "inner_note": "<속마음 1문장>"}
```

## 3. 보고서 호출 템플릿 (런 종료 시 1회)

```
너는 방금 재난 시뮬레이션 런을 마친 현장 요원이다. 아래는 너의 정체성과, 네가
런에서 겪은 것의 기록이다. 같은 성격으로 사후 보고서를 작성하라. 규칙:
- 섹션 4개: ## 경위 / ## 판단과 이유 / ## 추측 / ## 반성
- 전체 12~20문장. 한 문장마다 줄을 바꾼다.
- 기록을 다시 볼 수 없다. 아래 내용과 기억에만 의존한다.
- 추측 섹션에는 확인하지 못한 믿음을 적어도 2문장 쓴다.
- 어떤 도구도 사용하지 말고 즉시 마크다운 본문만 출력하라.

[정체성]
<agent_identity>

[장착됐던 문장]
<prompt_set 문장들>

[네가 겪은 것 — 시간순]
<관측 이벤트 로그: situation 발췌 + 너의 utterance + npc_reaction. inner_note도
"(당시 속마음: ...)"으로 끼워 넣는다. trust 수치·미관측 사건 제외>

[결과]
<ending_line>
```

검증: 문장 수 12~20, 섹션 4개. 위반 시 1회만 재시도, 그래도 위반이면 그대로
저장하고 metrics에 `format_violation: true`.

## 4. 산출물 (런마다)

```
planning/dday-poc/poc/runs/<실험>-run-NN/
  agent-prompt.json    # {"prompt_set": "base", "sentences": {...}}
  transcript.md        # J별: 조립된 페이로드 요약, 응답 JSON 원문, 적용 효과, 상태 스냅샷
  timeline-report.md   # | 시각 | 장소 | 사건/발화 | because | 형식, 엔진 진실(관측+비관측+trust 변화 포함)
  agent-report.md      # 보고서 호출 산출물 그대로
  metrics.json         # {"calls":[{"id","latency_s","choice"}], "report_call":{...}, "result":{"g1","g2","trust_final","found":{...},"choices":{...}}}
```

## 5. 실험 절차 (이 순서대로, 실험 사이에 사용자에게 중간 보고)

| 순서 | 실험 | 프롬프트 | 런 | 성공 기준 |
|---|---|---|---|---|
| 1 | **E1** 보정된 무능 (H1, 킬샷) | `base` | 3 | 3/3 G1 미통과, 실패 사유가 저작 범위(계기판 신뢰 / SOP 함정 / 근거 없는 파견안) |
| 2 | **E2** 재현성 (H4) | `std3` | 3 (계획서는 5, 세션 예산상 3으로 축소) | 동일 J에서 동일 choice ≥ 80%, 도달 게이트 동일 ≥ 2/3 |
| 3 | **E3** 문장 효과 (H5) | `std4` | 2 | E2 대비 J1 또는 J4에서 choice 변화, 변화가 3개 J 이하(국소성), G1 통과 |
| 4 | **E4** 귀속 절제 (H2, 킬샷) | E3에서 because가 s4를 인용한 판단을 골라, s4만 뺀 프롬프트로 **그 판단만** 3회 재호출 | 재호출 9 이하 | choice 변화 ≥ 2/3. 미달이면 귀속은 장식 |
| 5 | **E5** 보고서 품질 (H3, 킬샷) | E1~E3의 agent-report 전부 | 0 | 사람 평가 항목을 표로 정리해 사용자에게 제출: 편당 "프롬프트에 넣고 싶은 문장" 후보 ≥ 3개 추출, 로그와의 간극 ≥ 1개 지목, 성격 위반 여부. **최종 판정은 사용자가 한다** |
| 6 | **E6** 오염 (H6) | `poison` | 2 | J4에서 d 선택 → trust 하락 → 실패, because가 p1을 지목 |
| 7 | **E8** 측정 (H8) | 전 런 metrics 집계 | 0 | 판단 콜 p90 latency와, J 사이 텍스트 분량 기준 독서 시간(분당 500자)의 비교표. 서브에이전트 지연은 상한 근사임을 명기 |

E7(NPC LLM 비교)은 이 세션 범위에서 제외 — 킬샷 통과 후 별도 세션.

## 6. 결과 기입

- 실험이 끝날 때마다 `planning/dday-poc/poc/RESULTS.md`에 append:
  실험 id / 판정(통과·실패·조건부) / 근거 런 id / 특이사항 3줄 이내 / 판정 노트(모호함·이탈).
- 전체 종료 시 RESULTS.md 상단에 H1~H6·H8 종합표를 쓰고, 사용자에게 요약 보고.
- **어떤 경우에도 slice.json이나 시나리오 문서를 결과에 맞춰 수정하지 않는다.**
  보정 제안은 RESULTS.md의 "다음 액션" 섹션에 적는 것까지만.
