# u2 — discovery

## 1. `[u0#c8] empty-modules-only census` is stage-scoped and u2 necessarily breaks it

`tests/scaffold/layout.test.ts` › `[u0#c8] empty-modules-only census` › *every file
under `src/client/` is a `.gitkeep`, `main.ts`, or pre-existing* asserts that
`src/client/**` contains nothing but `.gitkeep`, `src/client/main.ts`,
`placeholder.ts` and `style.css`.

u2's contract mandates six real modules under `src/client/driver/`
(`import-direction.test.ts` case (a) fails unless they exist), so the two
assertions are directly contradictory. The census was authored while u0 was the
only unit on the tree and is a *scaffold-stage* guard — u1 (real shell mounted
in `main.ts`) will invalidate it as well.

Not fixed inline: the file is outside this unit's `file_globs`, and weakening
another unit's test is not this unit's call. **Integrator action:** retire the
census, or re-scope it to "no file outside the units that have landed".

Status: u2's own gate (`npx vitest run tests/driver`, 90/90) is green; the full
repo run is `1 failed | 138 passed` with that single case the only failure.

## 2. §5.2 `meta` is explicitly provisional, and the driver cannot narrow it

The ratified fence carries `// exact meta shape settles when 윤석 builds the
run-loop manager`. Ported verbatim per [u2#c8]. The fixture driver therefore
treats `meta` as an opaque pass-through event with no clock stamp — it rides the
stamp of the preceding stamped event. If the run-loop manager later gives `meta`
its own stamp, the fixture driver's `stampOf()` needs one more branch.

## 3. Stamp inheritance is an invention of this unit, not of the spec

§5.4 says a fixture run is "an ordered `ViewEvent[]` with clock stamps", but only
three of the eight members carry a stamp (`beat_start`, `beat_end`, `feed.line`).
`waiting` / `fallback` / `report` / `score` / `meta` / `run_end` have none. To keep
stream order inviolable while still gating on the clock, an unstamped event
inherits the due minute of the last stamped event before it (the run's `start`
before the first one). This is the only reading that satisfies both "stream
order" and "clock stamps" — but it is a driver-side convention the spec does not
state. Worth ratifying before the live driver binds engine + composer.

## 4. Reference deviation (P0-A precedence): the clock loop is pumped, not
self-driving

`docs/design/phase2-ui/app.js:457–480` drives the sim clock from the browser's
frame callback and keeps `acc` / `last` in module globals seeded off the
high-resolution timer. Pacing (`MS_PER_SIM_MIN = 105`, ×1 / ×4 / pause, hard stop
at `T_END` with an end-of-run flush) is ported exactly; the *drive* is not.
`src/client/driver/clock.ts` exposes `advance(realMs)` and holds its accumulator
per clock instance, because:

- spec-client §2.1 / invariant 12 keep the driver view-agnostic — a DOM frame
  callback in `driver/` is a seam violation (and `import-direction.test.ts`
  case (j) fails on it);
- [u2#c5] requires a *pinnable* frame, which a wall-clock-seeded loop cannot give.

The animation freeze is the same trade: the reference animates inline, u2 has
surfaces register a tick with `test-hooks.ts` and the driver pump them, so
freezing is a real gate rather than an honour system.

## 5. `new_run` has no fixture semantics yet

`MembraneOp` includes `{ op: 'new_run' }`, and §5.4 only names `deploy` and
`mine` as ops the fixture acknowledges. The fixture driver answers `new_run` from
the canned set but changes no state — a fixture is one scripted run, so there is
nothing to roll over to. Real behaviour (run counter++, carried blocks, archive
append) belongs to the run-loop manager and arrives back as a `meta` event.

## 6. No `design.md` / `spec.md` was produced for u2

The unit directory held only `tests.md`. The RED tests were therefore the sole
runtime contract, and their "API surface these tests pin" section was treated as
the design. One shape was added beyond that list: `src/client/driver/seam-guard.ts`
holds `assertSeamClean` so that `index.ts` (barrel) and `fixture-driver.ts`
(consumer) do not form an import cycle; the barrel re-exports it, which is where
the tests look for it.
