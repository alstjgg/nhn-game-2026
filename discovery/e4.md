# discovery — e4

## Spec gaps

- **A8 has no in-repo target for two of its five supplier sets.** §8-1 unions
  `GateView ∪ BeatView ∪ RoundView ∪ ComposerDeps ∪ PROXY_OWNED_SLOTS`, but
  neither `ComposerDeps`'s slot list nor `PROXY_OWNED_SLOTS` exists anywhere
  under `src/` (design §1 records the same finding). `tests/engine/feed/slot-supplier.test.ts`
  therefore reads the slot list from `docs/contract-calls.md` §6 on disk — a
  restated list would test itself — and requires e4 to export
  `PROXY_OWNED_SLOTS` and `COMPOSER_DEP_SLOTS` from `src/engine/feed/index.ts`.
  Both names are transcribed from §8-1's own wording rather than invented.
  Whoever owns the composer (e5) should re-point at these instead of keeping a
  second copy.

- **`missing_prefix` is not one of §6's soft-defect rows.** The disposition
  table lists two `npc_lines` drops (foreign speaker, echo of the utterance);
  spec decision 6 adds a third for a line arriving without the `"<id>: "`
  prefix, on the ground that the engine never throws on model output. Tested as
  a drop, not as a throw. If the contract is later revised, this is the row to
  revisit.

- **Where a production soft flag is recorded is still open** (contract-calls §6,
  ⚠️ note). e4's default holds: drops come back in `FeedResult.drops` and no run
  record is written.

## Seam friction

- **Read-scope miss — `docs/contract-calls.md` §6.** The unit's read scope
  named only contract-engine-composer §2.0/§5/§8. A8 is *defined* as "every slot
  in call contracts §6's supplier table", and the three soft-drop rules
  underpinning A5–A7 are in §6's disposition table, so §6 had to be opened. Only
  that section was read.

- **EXPERIENCED prose is provisional** (spec decision 7 / design D-5), so no
  test asserts rendered wording. The ordering tests assert containment and
  relative position only; a retune of `EXPERIENCED_PREFIX` must not turn the
  suite red.

## Reference ambiguities

- **`f`/`b` are `Sentence`, not `FeedLine`** (spec decision 4), so §8-8's "every
  `FeedLine` sourced from Call 1·2·3" is satisfied on the `Sentence` path for
  Call 3. The golden pins both paths from one allocator so the round-end order
  (`f` before `b`) is observable.

- **The golden pins id ⟷ text pairs, not ids alone.** D1's stated failure mode
  is a *re-split*, which keeps the id count identical while moving every id onto
  different text; an id-only golden would pass through it.

## Implementation deltas (decision 14 — spec assumption vs. what e0 landed)

| Spec assumed | e0 landed | e4 does |
|---|---|---|
| `mint(run, channel, seq)` | `mintSentenceId(run, channel, index)` | consumes as-is |
| `parse(id)` | `parseSentenceId` · `tryParseSentenceId` · `isMintedSentenceId` · `isAuthoredSentenceId` | consumes as-is |
| `segmentReportBody → Sentence[]` | returns `string[]` | mints `b` over that array |
| e0 declares the feed builders | `src/engine/index.ts` has only `Engine.feed(): FeedLine[]` | `BeatFeedInput`/`RoundInput`/`FeedResult` declared fresh in `src/engine/feed/types.ts` |

- **`TemperamentPack` is aliased twice, deliberately.** A12 forbids
  `src/engine/feed/**` from importing `src/engine/index.ts`, so `types.ts`
  aliases `datapack.ts`'s `Temperament` exactly as `src/engine/index.ts` does.
  Both point at the one authored shape, so they cannot drift apart; the
  duplication is one line and the alternative is an import that breaks the
  folder's dependency direction.

- **Where the gate sits in EXPERIENCED is e4's call, not §5's.** §5 fixes the
  three input rows and their order but not where the gate's
  `inner_note`/`utterance` pair lands relative to the beat that produced it.
  e4 emits it after the first beat's script events and before that beat's
  narration — the round's natural shape (stimulus → decision → consequence).
  An empty `inner_note` or `utterance` emits no line at all.

- **Rendered text is trimmed, not whitespace-collapsed.** Collapsing runs inside
  an npc line would edit model output on its way to the screen; the collapse is
  applied only to the *comparison* used by the echo rule. The two are separate
  on purpose — `drops.ts` `collapse()` never touches what is rendered.
