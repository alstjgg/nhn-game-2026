## 7. Endpoint A is the slot CARD, not the `.slot-pin` — design decision B corrected

`design.md` §2 B made `.slot-pin` the preferred slot anchor. The reference does
not: `app.js:583` reads `#slotBoard .bcard[data-block=…]` — the slotted CARD —
and puts the endpoint 6px inside its left edge; `.slot-pin` is only the red dot
the card's skin prints at its top-right corner (`desktop.css:405`, vendored at
`styles/win-block-store.css:71`), and the overlay draws its own pin circles at
both endpoints. The e2e agrees (it measures the first `[data-block-id]` in
document order, which is the `.slot` cell). The adapter therefore collects
`[data-block-id]` in document order and folds by id — cell first, pin folded
away — which keeps design B's real point (one thread per DISTINCT id, never per
node) while dropping its wrong anchor. Deviation logged under P0-A precedence.

## 8. A filled slot below the AGENT FILE fold has no thread — by c3's own rule

At the default arrangement the file's dossier stands above the board, so slot 1

## 10. `boot.ts` imports the layer as a namespace on purpose

`tests/components/red-thread.test.ts` asserts `indexOf('createThreadLayer') >
indexOf('desk.arrange')` over `boot.ts` — a named import would put the

overlay only after the desk exists) the code satisfies. `boot.ts` therefore does
`import * as threadLayer from './thread-layer.ts'`. Cosmetic, but it is the
suite that forces it.
