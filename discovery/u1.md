Things this unit must NOT fix inline. Appended by IMPLEMENT (attempt 1).

## 1. Invariant-vs-reference deviation applied (P0-A precedence)

`docs/design/phase2-ui/index.html` loads all three faces from
`fonts.googleapis.com` / `fonts.gstatic.com`. spec-client §3 inv 10 requires
self-hosted fonts under `public/assets/`, so the third-party request is **not**
reproduced. Ported the compliant equivalent: `tokens.css` carries the three
family *stacks* only (`--mono` / `--kmono` / `--myeong`, each ending in a
generic family, values verbatim). No `@font-face`, no font file, no webfont
link — u10 owns `styles/fonts.css` + `public/assets/fonts/` (u1#c7).

## 2. Cross-unit test conflict — u0's census fails by construction

`tests/scaffold/layout.test.ts` → `[u0#c8] empty-modules-only census` asserts

## 3. Test-harness quirk worth not "cleaning up"

`tests/styles/css-utils.ts` `declarations()` requires a declaration to be
followed by `;` or `}`, but `ruleBodies()` hands it a body string with the
closing brace already stripped — so a rule's *last* declaration is invisible
to any suite that scans bodies. `shell.css` therefore writes
`#desktop{display:contents;}` with an explicit terminating semicolon; removing
it turns `[u1#c3] (b)` red without changing a pixel.

## 4. Scope gap — the design slice stops 5 lines short of the file

The unit's reading scope lists `desktop.css` up to `549–612 (tally + toast)`,
but the file is **617** lines: `#toast.on` (615) and `body.booting .win` (617)
sit outside every listed slice. Both are load-bearing (the toast never shows
without `.on`; windows flash before the boot sweep without `body.booting`) and
were ported.

## 5. Adaptations logged (spec-client §8 — "pixel-exactness is not the bar")

- **Grey consolidation.** The reference carries several visually identical
  chrome greys (`#e4e7ea` / `#e2e8ed` / `#dfe6ec` / `#f0f3f6` → `--txt-hi`;
  `#c3ccd4` / `#a9b5c1` / `#a8b4bf` → `--txt-2`; `rgba(0,0,0,.022|.025|.028)`
  → `--sh-025`; …). They collapse onto one step of the scale — the point of a
  token scale. No color is re-invented: every literal in `tokens.css` still
  occurs in `desktop.css` (enforced by `[u1#c2] (c)`).
- **`!important` removed, specificity used instead.** `.tr-i` / `.tr-b` padding
  becomes `.tly-table td.tr-i` / `td.tr-b`, and `.win.collapsed{height:auto}`
  drops its `!important` (`.win.collapsed` already outranks `.win`). Required:
  `24px!important` is not a token reference, so the spacing lint rejects it.
- **`#app{height:100%}`** added in `base.css` — the repo's `index.html` mounts
  into `<div id="app">`, the reference styles `<body>` directly.
- `--kraft-2`, `--fanfold-bar`, `--highlight`, `--ink-2/-3` are declared but
  unreferenced; the reference does not use them either, and `[u1#c2] (a)`
  ("nothing dropped") requires them to survive.
