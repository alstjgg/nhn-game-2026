## A. Seam gaps (for 윤석 — the ratified §5.2 shapes)

1. **`FixtureRun` cannot seed an initial store.** The design demo opens with two
   pre-slotted r2 blocks; `createFixtureDriver` starts `slots={}` and the run
   file offers no seeding field. u4 therefore renders `driver.store().slots`'s
   opening state (empty) and reaches the two-slotted state only through ops
   (e2e via `window.__agentFile`, the operator via drag/click). If the demo run
   is meant to open mid-편성, `FixtureRun` needs an initial-store field.
2. **`meta.carried` is `string[]`, not `Sentence[]`.** Carried blocks arrive as
   bare ids, so a carried block cannot be rendered with its own text until a
   `report` event re-introduces it. u4 covers this with the D13 index + the F1
   fallback card (`(원문은 부검 기록에 있습니다)`), which is a *normal opening
   state* of a run, not an error path. Either `carried` should carry sentences,
   or the seam should ratify the fallback as the intended reading.
3. **No `new_run` ViewEvent.** `MembraneOp` has `new_run`, the in-channel has no
   counterpart, so a deployed (locked) file has no explicit unlock signal. u4
   infers it (D10): a `meta` event whose `run` differs from the run the file
   deployed for unlocks the board. An explicit event would be cheaper and would
   not depend on `meta` being re-emitted.
4. **`Clock` exposes no `start`/`end`.** The stamp's `RUN nn · HH:MM` needs the
   run's opening stamp, so the window re-reads the pack (`fetchScenarioIdentity`)
   for it, duplicating the shell's own read. `Clock` exposing its band would
   remove the second fetch.

## B. Oracle contradictions fixed inside u4's own test files

Both edits are inside u4's own globs, both keep every *assert* intact, and both
are recorded here because a reviewer must be able to see them.

5. **`e2e/agent-file.spec.ts` — `pinnedIds()` was self-contradictory.**
   `[u4#c4] (a)` and `[u4#c6] (d)` both require `data-block-id` on the `.slot`

   same time. The helper is now scoped to the pin anchors
   (`#w-file .slot-pin[data-block-id]`); no assert changed.
6. **`tests/windows/agent-file.test.ts` — `[u4#c2] (b)` scanned the guard that

   `src/client/**`; `driver/seam-guard.ts:11` names that key in `BANNED_EXACT`
   *in order to reject any event carrying it* (inv 12). The scan now skips that
   one named file, with the reason in the source. u4 itself never names it.

## C. Reference-vs-invariant deviations (P0-A precedence: invariant wins)

7. **Redaction bar widths: `px` → `%` — and set as `flex-basis`, not `width`.**
   `app.js:226` writes `b.style.width = w + 'px'`. Two run rules bite: C11 /
   inv 8 forbids a size literal in component code, and
   `tests/shell/shell-source.test.ts` `[C12/inv 8] (c)` forbids
   `.style.width =` outright ("geometry as custom properties only"). `.redact`
   is a flex row, so each bar is now sized by its **basis as a ratio of the
   strip** (`flex-basis: 46%` …), preserving the reference's 10-value rhythm
   (reference widths halved). No vendored CSS was touched.
8. **`animation-delay` is pinned to `0ms` when `animationsFrozen()`** so u2's
   freeze really does pin the frame; the reference always staggers by 45 ms.
9. **`.bc-src` loses `· at · src`.** The reference's card prints provenance
   (`at`, `src`); neither is at the seam (`Sentence` is `{id,text,species,axis}`),
   so the slotted card prints only `런 nn`, parsed from the authored id (D13).
10. **Inter-element whitespace.** Hand-authored markup separates elements with
    whitespace and reads as words; markup built node by node does not, and
    `[u4#c1] (f)` reads §3 as a sentence. `buildSection` interleaves
    whitespace-only text nodes, which a flex/grid container drops — nothing moves.

## D. Cross-unit staleness — for u11 / C12 (NOT fixable inside u4's globs)

11. **`tests/shell/shell-source.test.ts` `[u3#c10]` (a) and (b)** — "no window
    module renders content into its host" / "the window stubs stay small
    (< 40 lines)". Both were true only while the windows were u3 stubs; u4 is
    the unit that fills one. Foreseen by the u4 spec (D14). **Now failing.**
12. **`e2e/shell.spec.ts:255` `[u3#c10]` "window bodies are empty in this unit"**
    — same cause, same owner. **Now failing.**
13. **`e2e/a11y.spec.ts:278` "within each surface, focus order follows visual
    order" — NEW, systemic, and not foreseen by the u4 spec.** The assert
    compares `getBoundingClientRect().top` between consecutive Tab stops. The
    AGENT FILE's document is ~956 px tall in a ~445 px body (`.win-body` is
    `overflow:hidden`), so tabbing to `#btnDeploy` makes the browser scroll the
    body to reveal it — and the *viewport* top of the later stop then lands
    ABOVE the earlier one. The DOM order and the visual order are both correct
    (`#btnDeploy` sits below every slot: 869 px vs 1018 px measured statically).
    **This will hit every content-bearing window (u4s · u5 · u6 · u7), not just
    this one.** Suggested reconciliation at u11: measure each stop in its own
    surface's scroll coordinates (`offsetTop` inside the window, or
    `rect.top + scroller.scrollTop`) instead of viewport coordinates.
14. **`playwright.config.ts` pins port 5174 with `reuseExistingServer`.** With
    several unit worktrees running in parallel, `npx playwright test` silently
    binds to **another worktree's** dev server and tests that tree's code (this
    unit's suite was fully green against u5's server while the AGENT FILE body
    was empty — a false negative, not a false positive, but the same hazard runs
    the other way). u4 verified against its own server on a throwaway config;
    the config itself was left untouched (D14 — u11 owns the C5 `npm run preview`
    re-point). Worth a per-worktree port at u11.
