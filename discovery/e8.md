## 3a. `meta.archive[].run` cannot be fully truthful under the frozen schema

**Raised in final-PR review (#116, finding E).** `metaEvent()` filled
`archive[].run` with the array index (`i + 1`). That is not the run number:
`startRun()` advances `run_count` (a run that never ends still counts — the
comment on that line says so), while `endRun()` appends, so **start 3 and end
only 1 and 3** and the second archived id belongs to run 3 while the event
called it run 2. The client's past-report label then names the wrong run.

Fixed for every run the current session opened: `endRun` records
`run_id → run_count` at the moment it archives, which is the run in flight
because nothing moves the counter between a run's start and its end.

**What is left, and why it is a schema limit rather than a bug.** The pairing
cannot be persisted. `data/runs/_schema/meta-state.schema.json` declares

```jsonc
"report_archive": { "type": "array", "items": { "type": "string", "minLength": 1 } }
```

under `"additionalProperties": false`, so the ratified shape has nowhere to put
a number; and `run_id` is `{"type": "string", "minLength": 1}` with **no
documented grammar anywhere in `docs/`** (`contract-run-artifacts.md` does not
give one), so no number can be read back out of an id either. After a reload,
`metaEvent()` therefore falls back to position, which is

- **exact** whenever `report_archive.length === run_count` — every started run
  ended, the common case; and
- a **lower bound** otherwise, with `length < run_count` as the detectable
  signal that it is.

Both legs are pinned by `tests/runloop/meta-event.test.ts` `[#116 E]`, so the
residual cannot be mistaken for an untested path. Lifting it needs a
`data/runs/_schema` revision (either a `{run, run_id}` archive item or a
ratified `run_id` grammar), which is not this module's call to make — `data/**`
is frozen for this unit and the schema is the law on the shape.
