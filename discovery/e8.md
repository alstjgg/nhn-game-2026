## 1. Scope overflow (MINOR) — `tests/scaffold/skeleton.test.ts` had to be widened

**Steer candidate.** e8's `file_globs` are `src/runloop/**` · `tests/runloop/**` ·
`discovery/e8.md`, but e0's skeleton census (`tests/scaffold/skeleton.test.ts` §3)
asserts `createRunLoop({} as never)` throws `unimplemented: createRunLoop`. That
guard is correct *until* the behaviour exists; the first unit to implement any of
the five factories necessarily invalidates its own row.

Applied the pre-agreed additive fix (design D-1) and nothing else:

- `ModuleSpec` gains an optional `implemented?: true`;
- the `runloop` row sets it;
- the §3 `describe` iterates `MODULES.filter((m) => !m.implemented)`.

§1 (folder exists), §2 (exports census), the isomorphism guards and the id-minting
guard still run over every row, `runloop` included — the census was narrowed at
exactly one describe, not loosened. The four still-stubbed factories keep the
guard. e9–e12 will each need the same one-line row edit; the harness may want to
make that an explicit shared-file allowance rather than a per-unit overflow.
