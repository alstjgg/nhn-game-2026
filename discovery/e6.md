## A5's regex scan is stricter than "no numeric literal" — a real trap

The offender scan `/\b(?:const|let|var)\s+([A-Za-z_$][\w$]*)\s*(?::[^=]*)?=\s*(\d+)\b/g`
uses `[^=]*` for the optional type-annotation gap, which matches **across
newlines and across statements** until it finds the next literal `=`. A `let
attempt: Attempt` declared without an inline initializer, followed later by
`callCount += 1`, was swept into a false match (`attempt = 1`, sourced from the
`+=` in a *different* statement several lines down). Fixed by naming the loop
variable `outcome` instead of `attempt` — the retry-loop counter itself is
named `callCount` (not `attempts`) precisely so no `src/transport/**`
identifier containing `attempt`/`retr(y|ies)`/`budget` is ever bound with `=`
to anything, literal or not. `RETRY_BUDGET` needed an explicit `: number`
annotation for a related but separate reason: without it, `RETRY_BUDGET = 1`
matches the *first* offender regex (a bare comparison/assignment scan) because
`budget` sits directly against `= 1` with only whitespace between; the `:
number` annotation breaks that adjacency. Recorded here since this trap is not
obvious from the design doc and will recur for any later unit that adds a
retry-shaped constant.

## Header-honouring rule for a 4xx/500 vs. `gradeStatus`'s own pure contract

`gradeStatus()` is a pure, general lookup: for any mapped `status >= 500`,
`fallback = row.fallback || header.fallback === 'true'` — its own unit tests
require this literally (`gradeStatus(500, {fallback:'true'}, null).fallback
=== true`). But the full-transport AC (A2) requires 500 to force
`fallback:false` even with an injected `x-llm-fallback: true`, same as every
4xx. Resolved by keeping `gradeStatus` exactly as specified/tested, and adding
a caller-side filter in `index.ts` (`headerForGrading`) that drops the header
before calling `gradeStatus` whenever the status maps to a **non-retryable**
row (`STATUS_ROWS[status].retry === false`) — i.e. every mapped row except
502/504. This reads the "is the header eligible here" decision off the same
data table (OCP: a future retryable status is a one-row edit), rather than
naming 500 specifically.
