## 2. Fixture shape vs this unit's contract — the archive rail had nothing behind it

`meta.archive` lists RUN 01 and RUN 02, but `woodari-run03.ts` streams **one**
`report` event (round 3 only, by u2f's own §3 ruling "One `report` event, not
three"). The archive rail's entire purpose — *"switching runs keeps mined and
previously-slotted marks correct by id"* ([u6#c4]) — is then untestable and, in
the product, dead: every archived segment opens an empty pane.

`woodari-reports.ts` already exports `reportOf(1)` / `reportOf(2)`, so
`demo-run.ts` composes the two missing `report` events from **the fixture's own
exports** — no content originates in this unit — and appends the live run to
`meta.archive` under a label derived from the run's own clock band (the design
target does the same: data.js, *"appended when the run terminates"*). The
archived reports carry no clock stamp, so they ride the run's last beat and the
opening minute still releases no report at all (§7 #4).

**Integrator action:** this composition belongs in u2f's stream, not in a
consumer. When it moves there, `demo-run.ts` collapses to
`return fixtures.woodariRun03`, and this unit's code needs no change: the rail
is already `meta.archive ∪ {runs that filed a report}`, which degrades to
`meta.archive` the moment the fixture covers all three.

## 3. Driver friction — the animation pump stops with the clock, and the report lands exactly then

`fixture-driver.advance()` returns early on `!clock.running`, so `tickAnimations`
never fires once the clock reaches the run's terminal minute. But the round
report is released **by** that same terminal minute (`release(clock.ended ? null
: …)`), so a typewriter driven off `registerAnimation` — which is what §3 inv 5
and the "no timer of its own" guard require — would freeze on its first frame in
the real play-through. The e2e never saw it because every spec drains the stream
first, at 08:50, with the clock still live.

Worked around inside this unit: `report-view.ts` takes a `pumped()` predicate
(`() => !driver.clock.ended`) and paints the report whole when the pump is
finished — *paused* is not *stopped*, so pressing ▶ still resumes a replay.

**Owner action (u2 / u11):** let `advance()` tick animations even after the
clock has stopped, or release the closing `report` one minute before the
terminal stamp. Either removes the workaround.

## 4. Invariant-vs-reference deviations applied (P0-A precedence)

1. **The rail is a listbox, not a row of plain buttons.** `app.js`
   `renderArchive()` builds bare `<button class="arch">`s with no roles and no
   roving tabindex. PRD §4 a11y requires "a listbox-like control with an
   announced selection", so the port adds `role="listbox"` / `role="option"` /
   `aria-selected` / roving `tabindex` and ←/→/Home/End. The `.arch` / `.arch.on`
   skin is unchanged.
2. **`.arch-note` is `aria-hidden`.** The reference appends it inside the rail;
   a non-`option` child of a `listbox` is an a11y violation, so it is hidden from
   the tree while keeping its flex position (the CSS anchors it to the rail).
3. **A space node between `RUN nn` and the time span.** The reference appends
   `<span>` and `<em>` adjacent, which makes `textContent` read
   `"RUN 0108:50 — 21:04"` — one unbroken digit run in the accessible name. A
   text node restores the word boundary; nothing visual changes.
4. **Mining sends an op, and stops there.** `mine()` in the reference also calls
   `openWin('store')`, `renderStore()` and `toast()`. Reaching a sibling window
   is forbidden (C8 / inv 12 / this unit's guard (f)), so `mine()` returns
   id-keyed effect descriptors and the window plays only its own tear.
5. **`.min` sentences are `<span role="button">`, not `<button>`.** Report body
   sentences are inline runs inside justified Korean prose; a real `<button>`
   cannot line-break across a justified column. See §5 (a) below — this
   knowingly collides with a u3 guard.

## 6. Seam friction — `Sentence` carries no clock, so the fact column has no time
